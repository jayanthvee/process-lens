# PL-045 report (T2): the window_hidden event now says why the window stayed hidden

**Status:** done. Extension only. `window_hidden` keeps pausing the run; its detail now carries one
line of evidence from the visibility check.

## The change

**`executor/visibility.ts`**
- `ensureVisible` returns a `VisibilityReport` instead of a boolean:
  `{ visible, tried, error?, before?, after?, waitedMs }`.
- `WindowFacts` is `{ state, focused, tabActive }`.
- `VisibilityDeps` gains optional `windowFacts?: () => Promise<WindowFacts | undefined>`.
- The facts are read once before `bringForward` and once at the end of the wait. A read that
  throws or answers `undefined` is simply absent from the report; it never breaks the check.
- A `bringForward` that throws keeps its message in `report.error` instead of being discarded.
- `windowHiddenMessage(report?)` builds the `window_hidden` detail: `WINDOW_HIDDEN_MESSAGE`, then
  one line such as `(window minimized→minimized, focused no, tab active yes, raise error: none,
  waited 2000ms)`. With no report it is exactly `WINDOW_HIDDEN_MESSAGE`. It never contains a URL
  or page text.
- A visible page is unchanged: `{ visible: true, tried: false, waitedMs: 0 }`, no raise, no facts
  read.

**`background/command-step.ts`** (the ticket calls this `executor/command-step.ts`; the file lives
under `background/` and is the only `ensureVisible?` caller). The option is now
`() => Promise<VisibilityReport>`, and a hidden page throws the `window_hidden` `ExecutorError`
with the report's line in its message (the session sends that message as the event detail).

**`background/service-worker.ts`** — only `workTabVisibility` and the `window_hidden` conversion:
- `windowFacts` reads `chrome.tabs.get(tabId)` then `chrome.windows.get(tab.windowId)` and returns
  `{ state: win.state ?? "unknown", focused, tabActive }`; any error returns `undefined`.
- `runCommandStep` keeps the last report. The conversion of a step failure on a hidden page now
  throws `windowHiddenMessage(report)`, and both window_hidden paths `console.warn` the full report
  from the worker. No URL is logged.

Nothing under `popup/` was touched; no runner or Python changes.

## Tests first (red before the fix)

`apps/extension/tests/window-hidden.test.ts` was rewritten first and run against the old code:

- **Red:** 15 tests, **11 failed**. The failures were the expected ones — `ensureVisible` returned a
  boolean, `windowHiddenMessage` did not exist, and the prepare/dispatch refusals had no report.
- **Green:** 15 of 15 after the implementation.

New cover:
- a visible page reports `{ visible: true, tried: false, waitedMs: 0 }` and never raises;
- hidden then visible after the raise: `visible: true, tried: true`, `waitedMs` filled in;
- hidden and the raise throws: `visible: false`, `error` holds `"no window"`;
- `windowFacts` is read exactly twice (before the raise and at the end);
- a throwing `windowFacts` and an `undefined` one both leave the report intact;
- the `window_hidden` detail line names `window minimized→minimized`, `focused no`,
  `tab active yes`, `raise error: no window`, `waited 2000ms`, and contains no URL;
- the plain message when there is no report;
- the PL-040 prepare/dispatch refusal tests, updated only where the return type changed.
