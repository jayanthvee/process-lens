# PL-018b report (T1): replay inside open shadow roots and same-origin iframes

**Status:** done. The text half was GLM's PL-018c; T1 did the frame half and the two real-browser fixes.

Before this, two of the six widget-corpus forms failed in a real browser: `test_widget_shadow_form` and
`test_widget_iframe_form`. **Both pass now.**

## PL-018c (GLM): approved
- **`PAGE_TEXT_SOURCE`** is the light DOM plus every open shadow root, nested ones included. The three text checks
  (`text_visible`, `text_absent`, `text_count_increases`) all read it.
- **The tests went red first, then green.** The `text_absent` shadow test is the safety case: before the fix, an
  error message inside a web component read as "no error".
- **Review:** clean, and it stayed inside the three files the ticket named.

## The changes (T1)
1. **Frame contexts in command mode.**
   - The service worker keeps one `FrameContexts` per attach, and the command step gets it.
   - It starts listening before `Runtime.enable`. A debugger that a restarted service worker found already
     attached gets `Runtime.disable` first, so the enable reports every frame's context again.
   - `FrameContexts` now forgets destroyed and cleared contexts.
2. **Waiting for a loading frame.** `frameContextId` waits up to 3 s for the frame path and its context before
   it refuses the step. When the path doesn't resolve, the error names the wanted path and the frames the page
   has.
3. **Clicks inside same-origin frames.**
   - The page-side measure, settle and hit-test add each enclosing iframe's content-box origin, so the press
     lands in top-viewport coordinates.
   - The last hit test also checks, in every parent page, that the point still reaches the iframe. An overlay
     over the frame refuses the click.
   - A cross-origin frame's offset can't be read, so a click there is still refused, now with a message that
     says so.
4. **The save checks read same-origin iframes.**
   - The text reading walks into every same-origin iframe document.
   - It reads every frame, not just the step's own. That is safe because the check is also probed before the
     commit: a confirmation already showing in any frame parks the row instead of verifying it.
5. **Hidden text is not "visible".** A shadow child or an iframe that isn't rendered is skipped
   (`checkVisibility`). Chrome reports an unrendered element's whole text as its `innerText`, so the shadow form's
   hidden "Saved" status made every save look already done.
6. **The recorder records the top page's URL.** A step inside a same-origin frame used to carry the frame's own
   URL. The compiled recipe then opened `iframe-child.html` by itself, where the frame path pointed at nothing.

  - the same-origin click offset;
  - a parent-page overlay over the frame;
  - the cross-origin refusal;
  - iframe text in `text_visible` and `text_absent`;
  - the recorder's top-page URL.
- **Real browser:** `test_widget_shadow_form` and `test_widget_iframe_form` both pass.
- **The full e2e suite:** 21 of 22 passed, **both widget tests included**. `test_record_compile_run_on_lead_crm`
  failed once (0 of 3 verified) and then passed 3 times in a row on its own. A flake, not this change.

## Known limits
- **Cross-origin iframes are still refused,** both for clicks and for reading text.
- **Only open shadow roots.** A closed root is invisible to page script by design.
