## What this ticket delivered

The PL-024 check could already settle a spreadsheet column by the value the task was taught with,
but only when the caller passed that value in `sample_row` — and the web app never has it. This
ticket moves the taught value onto the recipe, so the value match works with nothing extra passed.

One commit, 5 files, +106 / −2 against the ticket base `975a602`.

- **`packages/recipe/schema/recipe.schema.json`** — `$defs.input_field` gains an optional `example`:
  `{"type": "string", "maxLength": 200, "description": "The value this column held when the task was
  taught; used only to match spreadsheet columns."}`. Nothing else in the schema changed.
- **`packages/compiler/compiler.py`** — one new helper, `_derived_field(value)`, used where
  `input_schema` fields are built from `options.sample_row`. It sets `example` to the column's sample
  value as a string, cut to 200 characters, and leaves `example` out entirely when the value is empty
  (`""`, whitespace-only, or `None`). The emitted field is unchanged (`{"type": "string"}`) in the
  empty case, so nothing downstream shifted.
- **`services/api/batches.py`, `GET /batches/{id}/check`** — when the caller passes no `sample_row`,
  one is built from `meta.input_schema.fields[*].example`: each field whose `example` is a non-empty
  string contributes `column → example`. The existing `_mapping_for` / `_rank` value match is
  untouched. A `sample_row` the caller *does* pass always wins (`recorded is None` guard), and a
  field with no example contributes nothing, so behaviour with no examples at all is exactly the old
  name-only match.

## What T1 should look at hardest

1. **The `sample_row`-wins guard.** The fallback only fires when the caller passes nothing
   (`recorded is None`), and an empty-string `sample_row` value on a column is *not* overridden by
   the recipe example. That is deliberate — the caller's value is the more specific statement — but
   it is the one place the two sources meet, so it is worth a second pair of eyes.
2. **The example is a snapshot, not the destination's truth.** It is the value typed while teaching,
   so a task taught with a placeholder or a test address would carry that. Matching still only
   *ranks* a column (exact name beats exact value), so a bad example cannot force a wrong column any
   more than a bad name could — but a genuinely generic example narrows the value signal to nothing.
3. **Whitespace-only is treated as empty.** `_derived_field` omits the example when
   `str(value).strip()` is falsy, and the API skips examples that are blank after `.strip()`. That is
   the ticket's word "empty"; flagging it in case T1 reads "empty" as strictly `""`/`None`.
