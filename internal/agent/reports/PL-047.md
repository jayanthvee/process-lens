# PL-047 report (T2): a parked row says what ProcessLens looked for

**Status:** done. **Branch:** `pl-047`. Runner only: `services/runner/` plus the runner tests.

## The change

**`services/runner/check_words.py`** (new)
- `describe_check(condition, row, variables) -> str` renders the condition's templates with the
  runner's own `render` and returns one plain sentence per schema kind:
  - `text_visible` -> `the page never showed "Lead created" within 8 seconds`
  - `text_absent` -> `the page never stopped showing "Saving..." within 8 seconds`
  - `text_count_increases` -> `"Ana Ruiz" did not appear one more time within 8 seconds`
  - `url_matches` -> `the page never went to a URL matching "/leads/" within 8 seconds`
  - `element_present` -> `the "Save" element never appeared within 8 seconds`
  - `element_absent` -> `the "Saving..." element never disappeared within 8 seconds`
  - `value_equals` -> `the field never came to equal "Ana Ruiz" within 8 seconds`
  - anything else -> `the save's check did not pass`
- The wait comes from the condition's own `timeout_ms`, through the existing
  `condition_timeout`, so `8000` is written as `8 seconds` (`0.5` stays `0.5`).
- Every sentence is capped at `MAX_SENTENCE = 160` characters. A long value is cut with `…`;
  the finding and the wait are never cut. An element is named by the selector's `description`,
  else its first usable target (role name, label, test id, fuzzy text, CSS selector).
- `parking_reason(check_sentence, destination)` builds the full parked reason and falls back to
  `the destination` when the run cannot name one.

**`services/runner/run_loop.py`**
- The failed-check path (`submitted_unverified -> reconciling`, `verdict.passed` false) now passes
  `describe_check(condition, row, variables)` into `_reconcile` as `check_sentence`.
- `_reconcile` takes that optional keyword. If the reconcile then parks, its reason becomes
  `<sentence>; check <destination_key>: if the row is there, Dismiss it, otherwise Try again`.
  Every other caller (recovery, an event, no dispatch proof) passes nothing, so those parking
  paths keep the reconciler's words exactly.
- `PARKING_REASON` in `reconcile.py` is untouched and still exported. No ledger transition changed.

## Three example reasons

1. `the page never showed "Lead created" within 8 seconds; check demo-crm: if the row is there, Dismiss it, otherwise Try again`
2. `"Ana Ruiz" did not appear one more time within 8 seconds; check demo-crm: if the row is there, Dismiss it, otherwise Try again`
3. `could not verify the save automatically; check the destination` — a reconcile with no failed check (recovery / event path), unchanged.

The destination name is the run's `destination_key` (`demo-crm` in the runner fixtures). When it is
empty, `parking_reason` says `the destination` instead. No product name is invented.
