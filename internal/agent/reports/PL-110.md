# PL-110 — report

Branch `pl-110` (from `pl-109` at `491deaa`). Typing into a box that searches as you type.

Nothing here matches one product's classes, names or URLs: the picker is recognised by ARIA role and
ARIA relationships, and the tests use generic markup.

## 1. Knowing the box is a picker

- **At replay time** (`apps/extension/src/executor/step-runner.ts`, `isPickerField`): a field is a
  picker when it carries `role="combobox"`, any `aria-autocomplete` hint, or `aria-controls`/
  `aria-owns` naming a listbox that is in the page (a `role="listbox"` element, or one holding
  `role="option"` children). A plain `<input>` has none of these and keeps the strict fill check.
- **While recording** (`apps/extension/src/background/recorder-session.ts`): when a step whose first
  role rung is `option` arrives, the newest fill before it is marked `autocomplete: true` — the
  recording shows a fill followed by a click on an option, so it is recorded as a pick.
  The compiler already carries that envelope onto the step (`packages/compiler/compiler.py` emits
  `autocomplete: true`; the recipe schema already allows it), so nothing needed there.
  Proves: `apps/extension/tests/pl110-picker.test.ts` ("the recording marks a pick, not a plain
  fill", both cases); `packages/compiler/tests/test_pl110_pick.py` (marked → step carries it,
  unmarked → plain).

## 2. Replaying a pick the way a person does

In `completeAutocomplete` (the replay path for a pick):

1. The fill is typed with `tolerateRewrite: true` (`dispatch.ts`): a picker rewrites its own text
   while it searches, so the read-back no longer calls that "did not stick". A box the page left
   **empty** is still a failed fill.
2. The listbox is read until it **settles** — the same option texts on two polls at least
   `PICKER_SETTLE_MS` (300 ms) apart — bounded by the step's timeout (`settledOptionTexts`).
3. Choice (`chooseOption`): an option whose name **equals** the value (an existing record), else the
   `Create "<value>"` option, else park with
   `No match for “<value>” in <field>, and no way to create it.`
4. The pick is a click on the stamped option through the guarded click path (`pickOption`), and the
   box is **not** compared to the typed value afterwards. Instead `requireBoxShows` checks the box
   now carries the chosen option's name (either string may contain the other, so a widget showing
   "Name <address>" passes; an empty box does not), else parks with
   `Picked “<option>” but the box shows “<shown>”; check the row's <field>.`

The pre-existing containment fallback and the guarded Enter fallback are kept behind this: an exact
match or a Create option wins first; otherwise the old "one suggestion contains the value" rule still
applies, so every recorded autocomplete that worked before still works.

Proves (written failing first, all in `apps/extension/tests/pl110-picker.test.ts`):
- a picker that rewrites the box while typing → picks the exact option (no "did not stick");
- an existing exact match is preferred over the Create option;
- a listbox that arrives after the typing has finished is waited for;
- a picker with only Create → chooses the Create option;
- a picker with neither → parks with the one plain sentence;
- a plain field the page rewrites → still refuses with "did not stick".

## 3. A plain fill keeps today's check

`dispatchFill` only tolerates a rewrite when the caller says the field is a picker, and the picker
detection is the field's own ARIA. The plain-field refusal is unchanged, and the runner's plain
words for it (`services/runner/step_words.py`, "The page changed the <field> as it was typed") are
unchanged. Two new tests prove a picker's own sentences are shown as written rather than wrapped:
`tests/runner/test_step_words.py`.

## Deliberate behaviour changes (and the tests updated for them)

- **No suggestion at all** used to read `no suggestion contains "…" in the listbox of step …`; it is
  now the ticket's `No match for “…” in <field>, and no way to create it.`
  `executor-fill-autocomplete.test.ts` asserts the new sentence (same intent: parks, names the value).
- **A fill with no autocomplete witness but a `role="combobox"` field** is now a pick, because the
  ticket says the field's own role makes it one. That test was rewritten to a genuinely plain field
  (an unrelated listbox on the page), which is what it was protecting.
