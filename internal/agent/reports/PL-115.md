## 1. Task cards name the app, not the address

**Before.** A card's second line was `task.app` exactly as the API sent it: `localhost:8069`,
`127.0.0.1:8069`, `goodlabs.com`, `www.goodlabs.com`.

**After.** `siteWords(app)` (appended to `apps/web/src/lib/words.ts`):

- an Odoo host or port 8069 → `Odoo`;
- a Twenty host or port 3000 → `Twenty`;
- anything else → the host with `www.` and the port removed (`goodlabs.com`).

The website's Tasks table uses the same helper, and a port never reaches either screen. The test
renders a loopback Odoo address twice and a `www.` address, and asserts the visible text contains no
`:port`.

**Test.** `item 1: task cards name the app, not the address` / "shows Odoo for a loopback Odoo
address and never a port".

**Note.** `TaskRow` carries only `app` (the first allowed origin). The recorded page title's site
part is not stored anywhere yet, so the fallback is what is shown; see "Needs PL-113/114".

## 2. Default task names are not names

**After.** `isDefaultTaskName` + `taskTitleWords`:

- `Recorded task` with no site → `Untitled task`;

The name is shown once: an untitled card does not repeat the site underneath its title, and the
website's Tasks table does not either.

**Tests.** `item 2: default task names are not names` / "shows Untitled task with the site, and
offers no Rename until the server can rename"; "shows Recorded task as Untitled task when there is
no site".

## 4. The runs list says what each run did, in one line

**Before.** A table headed Task / Started / Status / Progress; `This task` when the name was
missing; `11 of 20 done`; `Nothing has run yet. When a task runs, it appears here with what it did.`

**After.** One card per run (`<ul class="run-list">`), each with:

- the task's name (`taskTitleWords`; a nameless run reads `Untitled task`, never `This task`);
- a status badge from the five words below;
- one sentence from `runLineWords`:
  - running: `Added 3 of 5 · 1 already added · 1 needs you` / `Changed 2 of 3 · 1 already done`;
  - finished: `Finished: all 4 done`, `Finished: 11 done · 4 need you`, or
    `Finished: 2 of 5 done` while rows are still open;
  - stopped: `Stopped by you after 2 rows`, `Stopped by you before any rows`;
  - waiting: `Waiting for you: <the pause reason in one sentence>`;
- the start time from `runTimeWords`: `today 11:49 PM`, `yesterday`, `Oct 17`
  (`Oct 17, 2025` across a year), inside a `<time>`;
- `Open`, and the saved-time line when there is one.

**Tests.** `item 4: the runs list says what each run did in one line`: "writes a running, a finished
and a stopped run as one sentence each"; "says a paused run is waiting for you, and gives the
reason"; "sends a pause that needs the run page to Open, not a blind Resume"; "shows today's time
with the hour, yesterday as yesterday, and dates only when older".

**Existing assertions updated.** `tests/runs.test.tsx` asserted the old table: `11 of 20 done`,
`10 of 10 done`, `Nothing has run yet`, and `Finished — 4 need you`. The ticket fixes these words,
so they now assert `Added 11 of 20`, `Finished: all 10 done`, `No runs yet. Pick a task in Tasks and
press Run.`, and `Finished: 11 done · 4 need you`.

**Decision.** The ticket's item 4 example says `1 already done`, while item 5 fixes `Already added`
for a task that adds things. Item 5 is the explicit rule, so an add task says `1 already added`; a
change task says `1 already done`; a sign-in run never says either.
