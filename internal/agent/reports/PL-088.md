# PL-088 report

Status: done (T2). No e2e and no browser run, as the ticket asks: this is parsing and its tests.

## Changes

All in `services/api/batches.py`, except item 8 in `apps/web/src/pages/TaskRun.tsx`.

- **Encoding (item 1).** `_decode_text` tries UTF-8 (BOM-aware), decodes UTF-16 when a UTF-16 BOM
  is present, then falls back to Windows-1252 and Latin-1. A truncated UTF-16 file decodes with
  replacement characters instead of raising. A file is never refused for its encoding; the old
  "this .csv file is not UTF-8 text" refusal is gone.
- **Delimiter (item 2).** `.tsv` is tab-separated. A `.csv` sniffs its first 4 KB with
  `csv.Sniffer().sniff(sample, delimiters=",;\t|")` and falls back to a comma. The reader opens
  with `newline=""`, so CRLF and CR-only files parse and a quoted cell may hold a newline.
- **Blank rows (item 3).** A CSV/TSV row whose cells are all empty or whitespace is dropped before
  the header is chosen and before the 2,000-row count, the same rule `_read_xlsx` used.
- **Title rows (item 4).** `_is_title` calls a row a title when it has at most one non-blank cell
  and that cell is the row's first one. The header is the first row that is not a title, so a
  title narrow or as wide as the table is skipped, and an xlsx title (which openpyxl pads with
  empty cells) is skipped too. A header whose *first* cell is blank but which names a column later
  is a header, not a title, so `,Name` keeps its real header. When every row is title-shaped (a
  one-column file), the first row is the header, as before.
- **Unique headers (item 5).** `_headers` strips, names blank headers by position, and makes names
  unique with " 2", " 3" as `packages/documents/clean.py` does. A generated `Column N` steps past
  every real header name, so it never takes one. Every column's value survives, and the response's
  `columns` are exactly the keys the rows are stored under.
- **Excel values (item 6).** `_excel_text` gives a midnight datetime or a date `YYYY-MM-DD`,
  another datetime `YYYY-MM-DD HH:MM`, a time `HH:MM`, a whole float its integer, and a bool
  `TRUE`/`FALSE`; everything else is `str()`. This is only applied to `clean`; `raw` keeps the cell
  as read.
- **Trim (item 7).** Every value in `clean` is stripped. `raw` is untouched.
- **Formats (item 8).** `.tsv` is accepted (`TSV_SUFFIX`, the suffix check, and the file picker's
  `accept` and hint). A `.tsv` is stored as the `csv` batch kind, because the database's
  `batch_kind` enum has no `tsv`. `.xls` is refused with the ticket's exact "Save As" instruction.
- **Review hardening.** A NUL byte (valid UTF-8, rejected by PostgreSQL's `jsonb`) is stripped from
  a cell instead of failing the insert, a cell past `csv`'s 131,072-character field limit is a 422
  with a message and what to do, and a UTF-16 character cut in half by a truncated file is dropped
  rather than written as a junk row.

`apps/web/src/pages/TaskRun.tsx`: the picker accepts `.tsv` (`accept=".csv,.tsv,.xlsx"`) and the
hint reads "A .csv, .tsv or .xlsx file, up to 2,000 rows and 5 MB."

## Tests

`tests/api/test_batches_api.py` (+18). Every file is built inside its test; nothing is read from
`.cache`.

- Item 1: a cp1252 CSV keeps `é` and `£`; a UTF-16 BOM tab file uploads; a truncated UTF-16 file is
  not a 500.
- Item 2: a semicolon CSV gives three columns; a `.tsv` uploads, and its batch kind is `csv`.
- Item 3: `,,,` rows are dropped and 2,000 real rows still upload.
- Item 4: a title is skipped; a title as wide as the table is skipped; a title in a workbook is
  skipped; a blank *leading* header cell is not a title; a one-column file keeps its first row.
- Item 5: `Name, Name` gives `Name` and `Name 2` with both values; a generated name does not take a
  real `Column 1`.
- Item 6: an xlsx with a midnight datetime, a timed datetime, a whole number and booleans writes
  readable `clean` values while `raw` keeps Excel's string forms.
- Item 7: values are trimmed in `clean` and untouched in `raw`.
- Item 8: `.xls` is refused with the exact message and no batch is written.
- Hardening: a NUL byte in a cell uploads clean; a cell too long to read is a 422.

The tests were written first and committed failing: `dafb2bf` (`11 failed, 18 passed`) and
`3f921cf` (`4 failed`), with `33fa569` covering the first review's two defects.

Two independent adversarial reviews were run against the branch, and both found real defects that
were fixed, each behind a test that failed first:

1. `cd1451c`: a header row whose first cell is blank (` ,Name`) was read as a title, so the first
   data row became the header (or the file was refused with "no rows"). This was a regression
   against `main`, which uploaded that file.
2. `e907479`: that fix's "row spans the table width" rule re-broke item 4 — a CSV title with
   trailing delimiters (`Q4 customers,,`) and *every* xlsx title, because openpyxl pads rows to the
   sheet dimension. The rule is now "a title is a row whose one non-blank cell is its first cell",
   which satisfies both. The same commit closed two 500s found by review (a NUL in a cell and a
   cell past `csv`'s field limit); both were already reachable on `main`.
3. `25ef96e`: a third review found no blocker; it asked for a stronger truncated-UTF-16 assertion,
   which exposed a junk row of replacement characters. Those are now dropped, and the test pins the
   row count and the surviving row rather than only "not a 500".

Known trade-off: a header whose *only* named cell is its first one and whose later columns are
unnamed (`Name,\nAna,ana@x.com`) is indistinguishable from a merged title, and is read as a title per
the ticket's own rule 4 ("rows above it with at most one non-blank cell are skipped"), so the first
data row is lost silently. A blank header in the first column (` ,Name`) is preserved. Flagging for
T1: if the Owner wants that case reported, the response's `notes` is the place, but that text shows
on the run page, which the ticket puts out of scope.

Also unchanged and pre-existing: a row wider than the header has its extra cells dropped, and a
workbook with no worksheets is still a 500 (`_read_xlsx` wraps only `load_workbook`). Neither is
reachable from an ordinary Excel file, and neither is in this ticket's scope.
