## Deviations from the ticket, and why

1. **`StepCommand` also carries `record_key` and `idempotency_key`.** The fake destination keys its rows
   by the idempotency key, and PL-014's real executor will want the same context. The plan's field list
   did not include them.
2. **`approvals.reason` added in `0003`.** The ticket requires a rejection to park the record "with the
   reviewer's reason", and `approvals` had no column for it; the API already takes `reason`.
3. **`recover_run` also reassigns records already in `reconciling`.** The kill test proved the hole: a
   record left `reconciling` by the dead worker kept the dead worker's claim, so the new worker could not
   reconcile it and the run sat paused with an open record. `sql-patterns.md` and `LEDGER_SPEC.md` are
   updated to match.
4. **`package/ledger/create.py` and `reads.py` are new modules beyond the plan's list.** Creation must go
   through the ledger (the insert guard) and the API's reads must not contain ledger SQL (S3's separation
   rule covers reads too). Both are documented in `sql-patterns.md`.
5. **`python -m services.runner` refuses to claim runs.** The real browser executor arrives with PL-014;
   until then the CLI prints that no executor is connected and exits 0, rather than writing ledger rows it
   cannot act on.
6. **`run_summary` exposure on `GET /runs/{id}` reads the view** rather than recomputing counts.
7. **Existing tests changed:** the guard matrix list, the doc-driven 32-transition count, the
   migration-runner's expected file list, and the `claim_record` call in `tests/runner/test_lease_race.py`
   (its signature gained the `epoch` the fence needs) — all required by the new migration and the review
   fixes, none weakened (assertions were made stricter, not looser).

## Open questions for the owner or T1

1. **Reconcile definition (the ticket's open decision).** The runner builds against the `Reconciler`
   interface; nothing here needs `meta.reconcile` / `reject_when`. Confirm option 1 so the real reconciler
   can be written against the schema.
2. **The `records_not_exit` branch of R5 is defensive.** With recovery reconciling the whole commit
   window and the lease fence now on the claim (finding T2), every record reaches an exit state through
   the public seams, so the run-level branch is a backstop; its guard (`all_records_in_exit_state`) is
   unit-tested directly. Say so if you want a seam that makes the branch reachable.
3. **`parked → skipped` does not carry the R1 `commit_attempted` rule.** A person dismissing a parked
   record still ends it `skipped` even if that record had entered the commit window (its outcome was
   reconciled or checked first, per the ledgers own rules, but the guard does not force that). R1 added
   the rule only to `filling → skipped`. Confirm whether the owner wants `parked → skipped` to require
   `commit_attempted = false` as well — that is a ledger change and would need a new migration.
4. **Recipe `variables`.** Only `kind: constant` variables are resolved at run time; `rule_table`,
   `page`, `document` and `ai_text` sources fail closed, because `extract`/`classify`/`read_value` are
   pre-batch operations (D-017). The shipped `create-lead.recipe.json` uses a `rule_table` variable, so it
   is not runnable by this runner yet — expected, and worth confirming.
5. **`failed` from a commit.** The ticket leaves "a commit that doesn't verify always goes to
   `reconciling`", and `submitted_unverified -> failed` is implemented for a positive rejection, which the
   fake can produce but the attended executor cannot yet. Confirm that stays the plan.
6. **Heartbeat default raised to 365s.** R6 needs three times the longest step; the recipe schema caps a
   step at 120 000 ms, so the default now covers the worst legal recipe. A deployment that pins a shorter
   `--heartbeat-timeout` is refused at run start with a `RunnerConfigError` rather than silently weakened.
7. **Merge.** No pull request was opened (GitHub is not set up in this session) and nothing was pushed to
   `main`; the branch is pushed to `origin/pl-013` for T1 and the owner.
