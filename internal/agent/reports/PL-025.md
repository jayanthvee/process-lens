## What each screen shows

**The popup, top to bottom** (requirement 3, in order):

1. `Teach a task` with the recorder's state beside it — `Not recording` / `Recording`, as a dot plus
   a word;
2. one line of explanation, then the **connection status**: `Connected to ProcessLens` or
   `Not connected`;
3. **Start teaching** (the one gold button), with **Stop** and **Clear the steps** beside it;
4. the **live list of recorded steps**: one plain sentence per step — `Clicked New lead`,
   `Typed the email`, `Clicked Save` — and `The steps you take will appear here.` while there is
   nothing;
5. the **Save as task** form: `What should this task be called?`, `Which column identifies each
   row?`, `Which click finishes the row?`, `If this row is already there, skip it`, `Sites this task
   may use`, `Stop and ask me if one of these is empty`, and the one gold **Save as task** button.

Below them, under `Other controls`, the controls that must keep working: `Steps recorded`,
`Streaming`, the optional server field, `Save a copy of the steps`, the **Try one row** group, and
`ProcessLens address` with Connect / Disconnect. None was deleted — removing one would be a
behaviour change.

## No behaviour changes

The ticket's central constraint, so it was checked mechanically rather than by eye:

- **The diff is text, styles and one new module.** `git diff -U0` on `popup.ts` and `make-recipe.ts`
  shows no change to a message sent, a storage key written, a request-body field, or an ordering.
  `duplicate_check`, `park_fields`, `allowed_origins`, `commit_step_ids`, `when_to_use`,
  `record_key_column` and the two `chrome.storage.session` keys are all built exactly as before.
- **`dataset.state` was not touched.** The `git diff` for `dataset` is empty; the three assignments
  (`stateEl`, `runStateEl`, `sessionStateEl`) are the same lines as before, from the same sources.
- **Two things I had to catch and put back.** My own plan's "no remote URL in the markup" rule was
  over-broad: it bans any `http`, which would have forced `#hub`'s default out of the markup and into
  JS — a behaviour change. The rule is now about loaded resources, and `#hub` keeps its
  `value="http://127.0.0.1:8000"` in the HTML where it has always been. Separately, the
  missing-name refusal had moved from `#make-warnings` (via `showProblems`) to `#make-result` (via
  `notice`), changing which line a person reads; it is back on `#make-warnings`.
- **Nothing outside the lane.** No recorder, executor, service-worker, message-protocol, manifest,
  test-fixture or e2e change; no `package.json` edit; no web app or API change.

## The independent review, and what it found

A read-only reviewer was sent at the branch with one instruction: try to refute it. It confirmed the
restyle and the e2e contract, and found a real leak that this ticket's own test could not see.

**The compile route's sentences reached the screen verbatim.** The route answers in the same
engineer's voice the worker uses. A recognised commit is reported as
`assertion for click-2 taken from the recorded observation`; a refused navigation as
`navigate step 7 goes to …, whose origin … is not in allowed_origins`
(`packages/compiler/compiler.py`). `#make-warnings` printed both as-is, so a person read a step id
and a schema key — exactly what DESIGN.md §2 and requirement 7 forbid. **`click-` is rule 12 of the
word list**, and `allowed_origins` is the phrase DESIGN.md §2 maps to "sites this task may use".

Fixed. Every sentence the route sends is measured against `ENGINE_WORDS` before a person can read
it, and the ones this page cannot show are **counted out loud rather than dropped**: the headline
still carries the true problem count, and one plain line says how many notes it could not put into
words. The worker's session detail gets the same treatment, which closed a second instance the same
review found (a guard's `the page origin … is not in allowed_origins` reaching `#session-state`).
Two phrases the worker really sends — `allowed_origins` and `allow_destructive_control`, both named
by DESIGN.md §2 and both absent from requirement 7's twelve — joined the list.

**The test could not have caught it.** Its only fetch stub answered a clean success, so no route
`problem`, no route `warning`, no session `detail` and no executor `message` was ever rendered into
the DOM it checked. That is the honest core of the reviewer's second finding, and it is fixed: the
test now drives a 200 that carries a warning-bearing body and a 422 that carries a problem naming a
step id, and asserts on what a person reads in both. The browser script does the same against the
built extension.

**Also from the review:** the frozen-id guard was a string search, which cannot tell a present id
from a duplicated one; it now parses the markup, requires each id exactly once, checks that the
control the harness `fill`s is an input and the one it `select_option`s is a select, and checks the
two notes are separate elements.

The reviewer's "checked and found sound": every changed line of `popup.ts` and `make-recipe.ts`
against `3eea87c` preserves the message, the key, the body field and the ordering; the e2e selectors
keep id, kind and meaning; `is ready`/`Could not` are preserved; `tokens.css` is verbatim; and the
restyle breaks none of DESIGN.md's mandatory rules.

## What T1 should look at hardest

1. **The two gold buttons** above — the one design call this ticket makes that DESIGN.md's "at most
   one primary" would read against.
2. **The filtered route sentences.** The popup now says `1 more note about this recording is written
   for the engine, not for you.` instead of the compiler's own text. That is honest and it obeys
   §2, but the *actionable* fix is the compiler wording `packages/compiler/compiler.py` sends to a
   person — `assertion for click-2 …`, `commit step click-2 has no assert_after` — which is out of
   this ticket's scope and worth a ticket of its own. One consequence worth knowing: when a
   rejection's only problem is engineer-worded, the person sees the count and the note but not an
   explanation they can act on.
3. **The one behaviour-adjacent change**: `#make-warnings` now shows only the sentences it can put
   in plain words. Everything else about the form — what it sends, what it stores, when its button
   is enabled — is untouched.
