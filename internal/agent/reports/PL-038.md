## Part 1 — Approve/say no inside "3. Try one row"

Commit `eded31e` — `feat(web): approve a stopped preview row inside the Try one row card`.

- **`src/components/ApprovalPanel.tsx`** is PL-015's decision block moved out of `RunDetail.tsx`
  unchanged: same `panel` / `panel-h` / `approval` / `approval-values` / `approval-line` classes,
  the same ask, the same "Go ahead" and "No, stop this row", the same operator fetch and
  `decide()` body. Props are exactly `{ detail: RunDetailPayload; onDecided: () => void }`; it
  renders `null` when `detail.open_approval` is null, and both pages mount it only when there is a
  request to answer.
- **`src/components/approvalPanel.css`** carries the rules that were `.run-detail .approval…` in
  `runs.css`; they are now scoped to `.approval` so the panel looks the same on both pages. The
  run page's own `.refusal` and `.run-action` rules stay in `runs.css`.
- **`RunDetail.tsx`** renders `<ApprovalPanel detail={detail} onDecided={run.reload} />`; its 20
  existing tests are unchanged and green (now 26, with Part 2's six).
- **`TaskRun.tsx`** replaces the `Live` branch with the panel whenever `run.data.open_approval` is
  set, and the card's actions row with it. The card already polls while the run is open, so the
  panel appears without another request. After a decision `run.reload()` runs, `open_approval`
  clears, and the card returns to Live → outcome → "Run the other N rows".
- **The wait is named:** while the preview run is open and no decision is waiting, the card says
  "Adding this row in the ProcessLens window…" beside the Live dot.
- **`taskRun.css`** flattens the nested panel's surface (`.task-run .panel > .panel` loses its
  border, background and shadow) so the decision reads as the card's next block, not a card inside
  a card. No new tokens or styling system.

Tests (`tests/taskRun.test.tsx`, 3 new, all red first): the card shows the exact values and both
decisions; Go ahead POSTs `{request_id, decision: "approved", decided_by}` to `/api/v1/approvals`
and reloads the run; "No, stop this row" sends `rejected`; the card names the wait when nothing is
waiting; the card's text passes `engineWordsIn(...) === []`, and `save-lead`, `lead-save` and
`targets` never reach it. 14 tests in the file, all green.

## Part 2 — Try again and Dismiss on the run page, one row or the batch

Commit `2dd362c` — `feat(web): try a failed row again from the run page, one row or the whole batch`.

- **`needsHelpActions.ts`** gained `sendRecordAction(recordId, action, input)`, the one call both
  screens make, so the path and the body cannot drift. `NeedsHelp.tsx` now uses it.
- **`src/components/DestinationCheck.tsx`** is the safety tick extracted from `NeedsHelp.tsx`
  (same `destination-check*` classes, label and "why" sentence, from `needsHelpActions.ts`). It is a
  component rather than a function in `needsHelpActions.ts` because it is markup, and that module
  stays free of JSX. Its CSS moved from `needsHelp.css` into `destinationCheck.css`.
- **`RunDetail.tsx`**: a `parked` or `failed` row gets the same two actions in a new last cell
  (`record-requeue` / `record-dismiss`, the same classes Needs help uses), gated by the same
  `actionGate`. A `commit_attempted` row gets the tick on its own line under the row and both
  buttons stay disabled until it is ticked. **Verified row → no actions.**
- **Batch:** with the run finished and 2+ rows eligible, one "Try all N again" button sits above
  the table and re-queues each eligible row in turn. Rows that may already be saved are excluded
  and named — "Felix needs a check first." — until their own tick is set. A refusal anywhere in
  the batch stops it, shows `refusalWords(...)` beside the button, and reloads what the API now
  says.
- **After any action both `records` and `run` reload.** When a finished run is put back to work the
  API reports it open, the existing `isOpenStatus` effect restarts the poll, and the status says
  **"Running again"** (`RUNNING_AGAIN` in `lib/words.ts`) instead of pretending it is the first run.
- **`runs.css`** adds placement only: the batch row, the two buttons in the narrow action cell, and
  removing the tick's double rule inside a table cell. Phone width keeps the buttons left-aligned
  and the action column wraps rather than widening the page.

Tests (`tests/runs.test.tsx`, 6 new, all red first): a failed row's Try again POSTs to
`/api/v1/records/{id}/requeue` and reloads run + records; a commit-attempted row is disabled until
the tick and then sends `destination_checked_by`; a done row offers nothing; "Try all 2 again"
re-queues exactly the two eligible rows and leaves "Felix" out with the naming sentence; the whole
page passes `engineWordsIn(...) === []`; and a finished run put back to work shows "Running again"
and starts polling again on `POLL_INTERVAL_MS`. 26 tests in the file, all green.
