# PL-059: A save from a "new" page is checked by the address it lands on

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Branch: `pl-059`

## Status: **done**

Commit `7f323bb` (compiler + tests; the report is the commit after it). A save click sent from a
`/new` page with no recorded navigation now gets a `url_matches` check for the address it must
land on, instead of the fill-name check that can never pass on a quotation form.

## What changed

`packages/compiler/assertions.py`

- `NEW_PAGE_SUFFIX = "/new"` and `NEW_PAGE_RECORD_SEGMENT = r"(?:[0-9]+|[0-9a-f-]{8,})"` — one
  pattern that accepts both a plain record number (`/odoo/sales/42`) and a UUID
  (`/objects/companies/6f1c2a9e-...`).
- `condition_from_new_page(url, timeout_ms)` — returns `None` unless the URL has an origin and its
  path (trailing slash and query removed) ends in `/new`; otherwise returns
  `{"url_matches": <path prefix> + <record segment>, "timeout_ms": ...}`.
  - The prefix comes from the existing `path_pattern` helper, so the pattern has the same shape
    as the navigation checks: a path, escaped, not a full URL (`url_matches` is matched against
    the whole page URL, so a path pattern is enough).
  - A save page at the site root (`/new`) maps to `/` as the prefix, since the record page is one
    segment below it.
- The module docstring now names this third source, so the documented inference order is true.

`packages/compiler/compiler.py`

In `compile_recording`'s commit loop, after `_resolve_commit_assertion` (supplied assertion →
recorded observation → recorded navigation), and **only when** there is still no assertion, the
candidate is a `click`, and no `after_url` was recorded:

```python
assert_after = condition_from_new_page(candidate.url, options.assertion_timeout_ms)
```

The fill-name fallback runs only if that yields nothing too. The warning
`this save is checked by the page moving from /new to the saved record` is emitted as the step's
source, in the same warning chain as the existing ones.

Why only a click: a `select` or a `press` marked as a commit consumes nothing and saves nothing,
so an address check there would be a guess. (A submitted form is already collapsed into its
click by `collapse_submits`, so the real save path is covered.)

The resulting order is exactly the ticket's: supplied assertion → observation (PL-049 already
drops generated numbers) → recorded navigation → `/new` address → fill-name fallback. A commit
step still never ends with an empty `assert_after`; if nothing applies, the existing refusal
fires.

## Existing tests that had to change (and why)

The ticket allows a PL-044/PL-049 change with an explanation. Five pre-existing records used the
tests' default URL `https://app.example.com/records/new` (or `SALES_NEW`), which PL-059 now
legitimately treats as verifiable. Their intent was to test *absence of evidence*, so they were
moved to a page without the `/new` signal — the assertions themselves are unchanged.

- `test_compiler.py::test_a_commit_with_nothing_to_assert_is_refused`
- `test_observations.py::test_a_commit_with_no_observation_still_fails_closed`
- `test_pl018.py::test_a_commit_with_only_a_weak_observation_is_refused`
- `test_pl049.py::test_a_generated_reference_falls_back_to_the_new_records_name` (moved from
  `SALES_NEW` to the new `SALES_FORM = .../odoo/sales`)

PL-044's tests pass **unchanged**. All other compiler tests pass unchanged.

This is worth flagging for review: the fail-closed rule is still tested, but only off a `/new`
page. On a `/new` page, a commit with no observation now compiles by design.

## Residual risks

- **Single-page apps.** An app that saves on `/new` without changing the URL will now wait out
  the 8-second timeout and park, where the fill check might have passed. That is the ticket's
  deliberate trade: a check that cannot pass is worse than one that parks honestly, and Odoo and
  Twenty both change the address.
- **Loose id segment.** `[0-9]+` matches just the leading digits of a longer segment, so
  `/odoo/sales/42-extra` would pass. That errs toward accepting a record page, and the pattern
  still cannot match `/new`.
- **`/new` is a naming convention.** Apps that use `/create`, `/add`, or a modal dialog get no
  address check and keep the old fallbacks. Extending the signal would need a ticket of its own.
- **A caller-supplied assertion still outranks everything**, including this check — unchanged
  from before.
