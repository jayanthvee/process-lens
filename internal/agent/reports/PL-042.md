# PL-042: A recording that saves twice — the popup says so and keeps the first entry

**Status:** done · **Branch:** `pl-042` · **Commit:** `db6990f`
**Owner:** T2 (GLM Flash) · Awaiting T1 review (browser check)

## What changed

`apps/extension/src/popup/make-recipe.ts`

- New exported helper `firstEntryEvents(events, commitStepId)`. A recording **saves twice**
  when the click chosen as the save step names the same control as another click in the
  recording. Ladders are compared by a signature built from the role/name rung, falling back
  to the first css rung (`targetSignature`). When a repeat exists, every event after the
  **first** save click is dropped; a single-save recording (or one with no chosen step, or a
  step with no comparable rung) comes back unchanged — the same array reference.
- Every reader now sees only the first entry:
  - `recordedValues`, `recordedWarnings`, `searchDetected` trim via an internal
    `entryEvents` (save step = `defaultCommitStepId(events)`), so `defaultRecordKeyColumn`
    and `parkFieldDefaults` are covered transitively through `recordedValues`.
  - `makeRecipeRequest` trims with `choice.commitStepId ?? defaultCommitStepId(events)` and
    sends the trimmed events as `recording`; the default `allowed_origins` derives from them
    too.
- `recordedWarnings` appends, exactly: "This recording saves twice. ProcessLens kept the
  first entry and ignored the repeat after it." The popup shows it through the existing
  `#make-warnings` support block; no new button, no markup change.

`apps/extension/tests/popup-make-recipe.test.ts` — new describe block
"a recording that saves twice (PL-042)", 7 tests.

Not changed (per ticket): the compiler, the recorder, `defaultCommitStepId`/`commitChoices`
(the commit select still lists every click), `recordedOrigins` as a public function.
