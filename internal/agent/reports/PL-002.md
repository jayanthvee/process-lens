## Deviations from the ticket, and why
- **`up` waits for health.** `make up` runs `docker compose up -d --wait` so the documented
  `make up && make migrate` cannot race the health check.
- **`/health` always answers HTTP 200** with exactly `{"status": "ok", "db": true|false}` as specified;
  `status` describes the process and `db` the dependency. A 503 for a process without a database would
  change the response shape, so I left it out - see open questions.
- **`tests/db/test_health_api.py`** lives in the database test folder: `tests/db/` is the only test path in
  Scope, and the endpoint's answer is a database fact.
- **`${MINIO_CONSOLE_PORT:-9001}`** carries a default because `.env.example` is outside Scope, so MinIO's
  console port cannot be added there. Every *required* variable is one `.env.example` already defines.
- **The psql smoke script was converted, not deleted.** `db/tests/ledger_guard_test.sql` still exists
  (existing file, "new files only" in Scope) and is covered by `tests/db/test_ledger_guard.py`.
- **Ledger row timing for self-managed transactions.** `0001_init.sql` contains its own `BEGIN`/`COMMIT`;
  that boundary is kept and the `schema_migrations` row is written immediately afterwards in a second
  transaction. Files without transaction control get one transaction covering their statements and the
  row, so a failure rolls back both. Documented in `db/migrate.py`.
- **One `.gitignore` line appended** (`*.egg-info/`, written by `pip install -e .`); no existing line
  changed (verified by prefix comparison against `main`).
- **`packages/recipe/schema/` was not created**: it is a protected path. Only `packages/recipe/.gitkeep`.
- **Local scratch, gitignored, not part of the deliverable:** `.venv/`, `.env` (copy of `.env.example`),
  and `.data/` (bundled PostgreSQL 16.2, the gitleaks binary, and the harness scripts plus
  `.data/checks.log` with the full output pasted above).
- **Pre-commit hook override.** The upstream `gitleaks-system` hook does not set `pass_filenames: false`,
  so pre-commit appended all 34 file paths as positional arguments and gitleaks refused to run (nine
  identical `accepts at most 1 arg(s), received 4` errors - the file list was partitioned 8x4 + 1x2).
  Our config overrides it with `pass_filenames: false` plus `--config .gitleaks.toml`; the hook now passes.
  This looks like an upstream manifest bug worth reporting there.

- `uvicorn[standard]` - serve the API locally; the `standard` extra brings `python-dotenv`, so
  `uvicorn --env-file .env` works without a second dependency.

  requiring libpq on a developer machine.
- Dev: `pytest` (test runner), `httpx` (needed by FastAPI's TestClient), `ruff` (lint and format),
  `pre-commit` (gitleaks hook).
- No dependency was added for `.env` parsing (a small reader lives in `db/migrate.py`), and gitleaks is used
  as a released binary rather than a Go module.
