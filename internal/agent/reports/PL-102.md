# PL-102 report: codes from email, and never recorded

Status: built, tests pass; live Gmail check still owed.

## What changed

- `apps/extension/src/shared/email-code.ts` (new): `parseGmailFeed` (no DOMParser), `findCode`
  (time window, code words, dates/prices/phones excluded, `G-123456`, site-named sender wins, the only
  code wins, two unexplained codes are `ambiguous`), `scrubCodes`.
- `apps/extension/src/background/code-lookup.ts` (new): `lookForCode` looks every 5 s until found or
  out of time; `readGmailFeeds` reads `mail.google.com/mail/u/0..4/feed/atom` with the person's own
  Gmail sign-in. No Gmail answers: `no_gmail` at once.
- Command session and service worker: `enter_code` may carry `from_email` (no code), `remember` and
  `look_ms`. The worker reads email only after the person's yes (`processlens.codesFromEmail` in
  `chrome.storage.local`), otherwise answers `not_allowed`. The look starts from when this session
  reported the code page. Every typed code (person's or email's) then waits up to 10 s for the code
  page to go and reports `cleared`.
- Recorder: `isPasswordField` now also covers 4–8 single-character boxes and numeric fields whose label
  asks for a code. Every event leaves the page with names and text rungs passed through `scrubCodes`.
- Runner: on `code_required` while a record is filling, `_code_from_email` asks the extension first
  (`BrowserExecutor.code_from_email`, 60 s look + 15 s). Typed and cleared: the record is released
  with its attempt refunded and the run carries on. Anything else: the pause as before. A login page
  is never answered from email.
- Hub: a code (or an email ask) goes only to the Chrome the run is pinned to (`runs.browser_id`). Before
  this it went to whichever extension attached last, which with one team code could be someone else's
  Chrome. The reply now carries `cleared`.
- API: `POST /runs/{id}/code-from-email` (`remember`, default true). Both code routes resume the run by
  themselves when the code page went away (`resumed` in the answer), behind the same gate as Resume.
- Run page: "Read it from my Gmail" beside the code box, with what it does and that it will do it by
  itself from then on; plain reasons for `none`, `ambiguous`, `no_gmail`, and a code that left the
  site still asking.

## Built differently from the ticket

- The runner asks for the emailed code before pausing, instead of the extension acting on its own
  after the pause. Nothing has to resume a paused run, and the ledger, lease and abandon guard stay
  where they were. The look is 60 s from the runner and 45 s from the run page's button, not 2 min.
- The consent is the run page's one button ("Read it from my Gmail"), which also remembers the yes.
  "I'll type it" is the code box beside it.
