## Where it fails: the replay's first editable-row click

Every row parks at **step `click-5` — "Click Search a product"**, the click on the editable
order-line row's product autocomplete, before any line is added. What the recipe had for it
(`PROCESSLENS_E2E_DUMP_RECIPE=1`), that step only:

```json
{
  "action": "click",
  "id": "click-5",
  "name": "Click Search a product",
  "targets": [
    { "by": "role", "name": "Search a product", "role": "combobox" },
    { "by": "css", "selector": "input.o-autocomplete--input.o_input" },
    { "by": "text_fuzzy", "value": "Search a product" }
  ]
}
```

What the run said (all three rows identical; `parked`, `attempts=1`, `attempted_commit=False`,
run `status=completed`, `pause_reason=None`, **no `sale.order` written**):

```
harbourview dental = parked:the click target could not be resolved: no rung of the target
ladder resolved to exactly one element [page http://127.0.0.1:8069/odoo/sales/new;
4 input(s), 340 element(s)] [rung 1 (role): 0 matched, 0 usable - no visible, enabled match;
rung 4 (css): 2 matched, 2 usable - more than one match; rung 5 (text_fuzzy): 0 matched,
0 usable - no visible, enabled match]
```

Root cause: **the editable row's fields have no accessible names — only placeholders.** The
recorder therefore has nothing better than rungs that cannot resolve on replay:

- the role rung `"Search a product"` is the field's *placeholder*, and the accessible-name
  lookup matches 0 elements;
- the css rung `input.o-autocomplete--input.o_input` matches **2** elements (the customer's
  autocomplete and the row's own), and the replay ladder accepts only a rung that resolves to
  exactly one.

Two more compiled defects sit behind this one; a replay that got past `click-5` would meet them
in order:

1. **`fill-3` — "Fill input" (the quantity).** Same root cause: the row's quantity input has no
   accessible name, so its only rung is `{"by": "css", "selector": "input.o_input"}` — many
   matches on the quotation form, same refusal.
2. **`branch-1` — "Skip a record if the search finds it".** The product autocomplete is
   *recorded* as "Search a product", and the compiler's duplicate check reads any fill followed
   by a click naming "search" as a destination search, so every row carries a
   skip-as-duplicate branch keyed on `{{row.search_a_product | lower}}`. No search was
   demonstrated; the branch is a name collision, not a workflow.
3. **`click-7` — the commit's evidence.** The save's recorded observation is the
   demonstration's own quotation number, compiled verbatim into
   `"assert_after": {"text_visible": "S00001", ...}`. No replay row's save can show `S00001`;
   the assertion is not templated and is not a URL shape, so every commit would be
   unverifiable.

## Run log (4 runs of the test, the ticket's cap)

1. **Setup error, not a test failure**: the worktree had no `apps/extension/node_modules`, so
   the `built_extension` fixture's npm build failed. Fixed by `npm ci --prefix apps/extension`
   (the same install a fresh checkout needs) and building `dist` once.
2. **Test failure at the row builder**: the recording's columns (`Fill input` for the quantity)
   did not match the first column mapping. The row builder now reads the compiled schema's
   own fields and examples instead of guessing from labels.
3. **Test failure before the replay started**, with no diagnostics left (pytest shows nothing
   of an xfailed run and this run predates the trace): most likely a recording-phase flake or
   a compile refusal. Phase-boundary tracing was added to the test; the next run is the
   authoritative one.
4. **Authoritative run** (3:17, xfailed as expected): recording and compile clean, all three
   rows parked at `click-5` with the reason quoted above. Evidence:
   `.cache/pl046/quote-golden-trace.log`.

## For the fix (out of scope here, per the ticket)

The smallest change that would let this golden pass is in the recorder/compiler, not the test:
name editable-row fields (an accessible name or a field-name css rung instead of the generic
`input.*` selectors), stop reading "Search a product" the placeholder as a destination search,
and template or shape-generalize the commit's recorded confirmation when it is a per-record
reference like `S00001` (the lead golden's save passes because its heading already existed
before the save; the quotation ref does not).
