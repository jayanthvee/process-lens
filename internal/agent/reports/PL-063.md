## The price golden's finding: the save records no commit evidence

Three runs of `tests/e2e/test_odoo_product_price_golden.py` (each after
`infra/test-apps/reset.py odoo` and a fresh `dist`):

1. **Run 1** — the demonstration records cleanly (18 events: search fill `PL-CHR-2001`, Enter,
   the row click that opens `/odoo/products/3`, the form's page-set fills, the typed Sales
   Price `349.00`, the Save click), the popup offers exactly two columns —
   `('Search...', 'search')` and `('Sales Price', 'sales_price')` — and the compile **refuses**.
2. **Run 2** — pinned the cause: the save produces **no recorded evidence**
   (`wait_for_observation_after` returns nothing; the events after the save are fill-14 and
   click-2, neither carrying an observation). An update-in-place on Odoo's product form
   navigates nowhere — the URL stays `/odoo/products/<id>` — and no confirmation the recorder's
   observation window recognizes appears.
3. **Run 3** — the popup's exact words, now in the trace
   (`.cache/pl063/price-golden-trace.log`):
   - result: `'Could not save this as a task (1 problem).'`
   - warnings: `'commit step click-2 has no assert_after: the recording observed no confirmation
     and no navigation, and none was supplied for it'`

The failing step is **click-2, "Click Save manually"** — the commit. Everything the ticket wants
from this golden (three replayed rows, `list_price` assertions, the second run's dedupe shape,
and the `idempotency_key` carrying `{{row.sku}}:{{row.new_price}}`) sits behind that refusal and
is **unreached**, so none of it is claimed here. The test is marked `xfail(strict=True)` with
this reason; if the compiler ever accepts such a recording, the strict marker will XPASS and
surface it.

**Smallest product change that would make it pass** (T1's call, not made here): the recorder's
confirmation selector (`CONFIRMATION_SELECTOR` in `src/content/recorder.ts`) matches
`.notification`, but Odoo 18's save toast carries the class **`o_notification`** — teaching the
selector `o_notification` (or the compiler to accept an update-shaped commit whose page already
is the record's own) would give the commit its evidence. Unverified: no product change was
permitted here.

## Second finding, from the same run: the duplicate branch is proposed for an update

The trace records `popup proposed the duplicate branch: True` — the heuristic read the demo's
real search (fill the search view, Enter) and proposed the skip-if-the-search-finds-it branch.
For an update that is **not right**: the product the search finds is the one the row is about to
change, so the branch would end every row `skipped`. The golden unticks the popup's checkbox —
the decision a person updating prices would make — and that is why the compile got as far as
the commit-evidence refusal.
