### 1. The taught value is shown everywhere a field is named — DONE

- The run's row values: the field's name reads `Contact — you typed “ben baller”` above the row's own
  value.
Proves: `apps/web/tests/pl109Fields.test.tsx` (words and the Check-it page);
`apps/web/tests/panelTeach.test.tsx` (the step line);
`tests/api/test_batches_check_helpers.py::test_every_mapping_entry_carries_the_taught_example`.

### 2. Names a person recognises, never two the same — DONE

`namedValues` (`apps/extension/src/popup/make-recipe.ts`) keeps the PL-107 naming order (label,
column header, aria-label, a non-example placeholder) and, when two fields would share a name, tells
them apart by the taught value: `Contact (ben baller)` and `Contact (ben baller's opportunity)`. A
tie on the value too falls back to a plain ordinal word ("the second field"), never `Contact 2`. The
machine column keeps its old derivation, so no schema key or saved mapping changes.
Proves: `apps/extension/tests/pl109-field-names.test.ts`.

### 3. Columns matched by their values, not only their headers — DONE

`services/api/batches.py`:
- `_value_kind` reads what a taught value looks like: `email`, `money`, `phone`, `name`.
- `_rank` and the name fallback in `_match` suggest a column whose first-row value (or uniform values)
  look like the taught value even when the header differs. Money is kept apart from a plain count, so
  a quantity is never matched to a price; a person's name is guessed only when exactly one column
  looks like a name.
- `_mapping_for` tracks the column each field claimed, so two fields with different taught values
  never get the same column suggested.
Proves: `tests/api/test_batches_check_helpers.py` (email by values, money vs count, name only when
unique, no shared column).

### 4. Matched or ask — no “Check this” — DONE

`fieldReading` (`apps/web/src/lib/fields.ts`, used in `TaskRun.tsx`):
- A confident match (or the person's own pick) is **Matched**, with the first row's value beside it
  (`Email → riley.ivanova@…`).
- An unsure match is a question in the person's words: **Which column has the email addresses?** (and
  the matching question for money, a phone, or any other field). “Check this” is gone.
- “Not in my file” is still the select's own option; the Match cell then says **Left empty for every
  row.**
Proves: `apps/web/tests/pl109Fields.test.tsx`.

### 5. The key value is decided, not asked — DONE (panel and popup)

`apps/web/src/panel/PanelTeach.tsx` no longer opens with "Which column identifies each row?". When a
taught value can identify a row it shows one line: **We'll use Email so nothing gets added twice.
Change**. The select ("Which value is different for every row?") appears only under **Change**, or on
its own when no value can identify a row (no email, no id/number, no name). The old auto-pick of the
first field as the key is gone, so a recording with nothing identifying asks instead of guessing.
The save error now says "Choose which value is different for every row."

The popup has the same line (`renderKeyDecision`, `apps/extension/src/popup/make-recipe.ts`): when
`defaultRecordKeyColumn` can decide, the select is hidden and the line reads **We'll use Email so
nothing gets added twice.** beside **Change**; when it cannot, the question is shown. A new recording
starts on its decision, not on the last recording's open question.

Proves: `apps/web/tests/pl107KeyColumn.test.tsx` — the decided line names Email; the question opens
under Change; a recording with no identifying value asks straight away.
`apps/extension/tests/pl109-popup-decided.test.ts` — the popup's decided line, Change opening the
select, and the question only when no value can identify a row.

### 6. The save click is decided, not asked — DONE (panel and popup)

The panel shows **The Save click saves your work. Change** (or "Nothing gets saved. Change"), with
the recorded clicks and "Nothing gets saved" under **Change**. The default is still the last
recorded click; the selected id is what `commit_step_ids` sends.

saved.** rather than showing an empty question.

Proves: `apps/web/tests/pl107KeyColumn.test.tsx` — the decided line names the click; the question

proves "Nothing gets saved" compiles with `commit_step_ids: []` and a chosen click is the one sent.
`apps/extension/tests/pl109-popup-decided.test.ts` — the popup's decided line, Change opening the
question, the "Nothing gets saved" choice, and the no-click line.
