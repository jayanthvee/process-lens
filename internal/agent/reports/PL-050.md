# PL-050: The demo refuses to start a second copy

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Branch: `pl-050`

## Status: **done**

Commit `64ba102` (report in the commit after it). `scripts/demo.py` now refuses a second copy
before migrations, builds, or the API, and releases its pid lock on the way out. The tests were
red first, the three gates are green, and the real entry point was exercised with port 8000
genuinely held.

## What changed

`scripts/demo.py` (only file changed besides the tests):

- **`port_in_use(port) -> bool`** — binds `127.0.0.1:<port>` with a plain socket and closes it at
  once; a failed bind means something is already there. No dependency.
- **`other_demo_pid(path) -> int | None`** — reads the lock file and returns its pid only when
  that process is alive. A missing file, an unreadable file, a non-numeric file, and a dead pid
  all return `None`, so a crash's leftover is overwritten instead of respected.
- **`_pid_alive(pid)`** — `os.kill(pid, 0)` on POSIX (with `PermissionError` treated as alive,
  since that means the process exists but is not ours to signal); on Windows, a `ctypes`
  `OpenProcess(SYNCHRONIZE)` plus a zero-time `WaitForSingleObject`, because `os.kill` there would
  terminate the process. `psutil` is not a dependency, so `ctypes` it is; no new dependency.
- **`write_pid_file(path)` / `remove_pid_file(path)`** — the lock is `DATA_DIR / "demo.pid"`,
  holding `os.getpid()`. Cleanup reads the file first and only unlinks it while it still holds
  this process's pid, so a second copy that already took the lock keeps it.
- **`already_running_message(pid)`** — the same plain line as the port refusal, naming the pid.
- **`main()`** now, before anything else:
  1. `port_in_use(API_PORT)` → print `PORT_TAKEN_MESSAGE`, return 1;
  2. `other_demo_pid(PID_FILE)` → print the pid variant, return 1;
  3. `DATA_DIR.mkdir`, `write_pid_file(PID_FILE)`;
  4. `try:` the whole existing body (migrations → supervisor loop) `finally:`
     `remove_pid_file(PID_FILE)`.

The port message is exactly the ticket's:

```
ProcessLens is already running on http://127.0.0.1:8000 (or something else is using port 8000). Close the other copy first: find its terminal and press Ctrl+C.
```

The pid message keeps the same shape and names the copy:

```
ProcessLens is already running on http://127.0.0.1:8000 (another demo, pid 4242, is watching the same database). Close the other copy first: find its terminal and press Ctrl+C.
```

No new dependency, no extension/runner/e2e change, no `.env` or database change.

## Residual risks

- **Pid reuse.** A dead demo's pid can be reused by an unrelated process, and the lock would then
  name a live process. The port check still catches the common case, and the alternative (a
  start-time token in the lock) is more machinery than this ticket asks for.
- **Check-then-bind race.** Between the probe closing and uvicorn binding, another process could
  take the port. The window is milliseconds and uvicorn would then fail loudly; the check is a
  guard, not a reservation.
- **Loopback only.** The probe binds `127.0.0.1`, exactly as the API does. Something listening
  only on another interface would not be detected -- and would not conflict with the API either.
- **Windows access rights.** `OpenProcess(SYNCHRONIZE)` fails for a process this user may not
  open (for example a service); such a pid is treated as dead. The lock can only ever name a demo
  started by the same person, so this does not arise in practice.
- The pid-case sentence is a wording choice: the ticket says "the same message with the pid", and
  this keeps the same structure and the same closing instruction while naming the pid instead of
  guessing "or something else is using the port".
