# PL-060: A recipe remembers how long the person took to do one row by hand

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Branch: `pl-060`

## Status: **done**

Commit `dc3b194` (compiler, schema, tests; the report is the commit after it). The recipe now
carries `meta.manual_seconds_per_row`, measured from the demonstration itself rather than guessed
by a constant.

## What changed

`packages/recipe/schema/recipe.schema.json`

`meta` gains one optional property, inside the existing `additionalProperties: false` object:

```json
"manual_seconds_per_row": {
  "type": "number",
  "minimum": 1,
  "maximum": 86400,
  "description": "How long one row took the person by hand, measured from the demonstration."
}
```

`apps/extension/src/shared/recipe-types.ts` was **not** touched: `schema-conformance.test.ts`
compiles only `#/$defs/step` from the schema, so a `meta` property is outside what it checks, and
the TypeScript types do not model `meta` at all. No npm gate was therefore required.

`packages/compiler/compiler.py`

- `MANUAL_SECONDS_MIN = 1`, `MANUAL_SECONDS_MAX = 86400`.
- `_manual_seconds_per_row(candidates, events) -> int | None`:
  - Maps each event's `seq` to its parsed `at` (the existing `_parse_iso`).
  - Walks the **kept candidates** — the list that actually becomes steps, after every fold — from
    the first one with a parseable `at` to the commit's own `at`; with no commit, to the last
    kept event.
  - Returns `None` when fewer than two kept events have a parseable `at`, when the commit itself
    has no usable `at` (the measurement ends there, so there is nothing to measure to), when the
    span is negative or over 86400 seconds, or when the two timestamps cannot be compared (a
    recording mixing naive and offset times).
  - Otherwise `max(1, round(seconds))`.
- `compile_recording` calls it after the duplicate-search demotion, so a search click that was
  demoted is no longer treated as the row's commit. When a value exists it writes
  `meta["manual_seconds_per_row"]` and appends `one row took about N seconds by hand`. When it
  does not, nothing is written and no warning is added — the screen falls back, as the ticket
  says.

Because the measurement walks the candidate list, steps the folds dropped (a retried fill, a
folded option fill, a container click, a page-set fill) do not count toward the span.

## Residual risks

- **The span includes reading and thinking, not just typing.** It is "how long the person took",
  which is what the brief asks for, but it is one observation of one row — a slow or interrupted
  demonstration yields a large number. PL-061 presents it; nothing here smooths it.
- **A clock that jumps backwards between the two timestamps** yields a negative span, which is
  dropped silently rather than flagged. That is the ticket's rule (no warning on omission), but
  it means a corrupt recording shows no manual time at all rather than an obviously wrong one.
- **The measurement ends at the commit's `at`, not at the moment the page settled.** That is what
  the ticket specifies; a save whose confirmation takes ten seconds is not counted.
- **No commit step** (a recipe that only reads) measures to the last kept event, which may be a
  shorter span than the person actually spent before the last recorded action.
