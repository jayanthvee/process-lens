## Summary

Two changes, each tested first and seen to fail before the implementation.

**The demo window says what it is doing.** `scripts/demo.py` grew a small frozen dataclass,
`State` (`session_attached`, `waiting_run`, `worker_running_for`, `last_exit`), and a pure function
`status_lines(previous, current) -> list[str]`. Each supervisor tick builds a `State` and prints
whatever `status_lines` returns, so the window announces exactly these, once per change and never
twice in a row:

- "Chrome is connected." / "Chrome is not connected: open the ProcessLens extension and press Connect."
- "A run is waiting for Chrome." (a run is open and no session is attached)
- "Started a runner for run `<first 8 chars of the run id>`."
- "The runner finished." (exit 0) / "The runner stopped with code `<n>`." (otherwise)

The old ad-hoc prints ("the worker exited (code n)", "started a worker for the browser session") are
gone; the loop derives `waiting_run` from the same rows `worker_decision` starts on, resets
`last_exit` when it starts a new worker, and prints the worker log path no more (the logs still land
in `.data/worker-logs/`). The connected-session-with-a-waiting-run case produces the "Chrome is
connected." line only — no waiting line, since that is a start, not a wait.

**One write path for `tenants.min_extension_version`.** New migration
`db/migrations/0008_admin_grant_tidy.sql` runs `REVOKE UPDATE (min_extension_version) ON tenants FROM
processlens_admin` with a one-line comment: the admin panel sets the floor through the API (ADM-001).
The API connects as the database owner, so its write is unaffected; `tests/db/test_admin_migration.py`
now asserts, under `SET ROLE processlens_admin`, that the direct write raises `InsufficientPrivilege`,
and the test that exercised the direct write no longer does. `tests/db/test_migration_runner.py`
expects `0008` in the applied list and the recorded hashes, and `internal/docs/ADMIN-MODULES.md` no
longer lists the grant, notes the revocation as the precedent for a write moving behind the API, and
adjusts the "grants only its own columns" rule accordingly.
