# PL-061: Show the real manual-versus-automated time

Owner: T2 (DeepSeek) · Reviewer: T1 · Branch: `pl-061` (built on `pl-060`)

## Status: **done**

Commits `17d420b` (ledger + API) and `69ed8cd` (web); this report is the commit after them.
The three-minute guess is gone from the screens: the figures come from the manual time each task
measured while it was taught (PL-060), with the old three minutes only as a labelled fallback.

## What changed

### 1. Ledger reads — `packages/ledger/reads.py`, `packages/ledger/__init__.py`

Two new reads, both with the tenant filter every neighbour has, and all SQL in `reads.py` (the
separation rule is untouched; `tests/runner/test_sql_separation.py` stays green).

- `run_time(conn, run_id) -> RunTimeRow | None`
  - `done`: the rows the run finished with (`verified` + `skipped`), the same count the results
    screen calls "done".
  - `automated_seconds`: `extract(epoch FROM finished_at - started_at)`, `None` while either
    timestamp is absent, so an open run has no wall clock.
  - `manual_seconds_per_row`: the pinned version's `recipe -> 'meta' ->> 'manual_seconds_per_row'`,
    guarded by `jsonb_typeof(...) = 'number'` so an older or hand-written document reads as absent
    instead of failing the page on a cast.
- `week_manual_seconds(conn, days, tenant_id) -> WeekTimeRow`
  - Sums, over the audit table's `verified` transitions inside the window, each row's own
    `manual_seconds_per_row`, using `FALLBACK_MANUAL_SECONDS_PER_ROW = 180` when the task has
    none.
  - `estimated_rows` counts the rows that had to use the fallback.
- The two row shapes (`RunTimeRow`, `WeekTimeRow`) are declared in `reads.py` — "read-only shapes
  the API needs", as the module's own docstring puts it — rather than in `models.py`, keeping the
  change inside the ticket's file list. Both are exported from `packages.ledger`.

### 2. API — `services/api/home.py`, `services/api/runs.py`

- **Home** now returns:

  ```json
  {
    "manual_seconds": 360,
    "automated_seconds": 60,
    "saved_seconds": 300,
    "estimated_rows": 0,
    "minutes_saved": 5
  }
  ```

  `saved_seconds = max(0, manual - automated)`. `minutes_saved` is kept (and derived from the same
  `saved_seconds`) so the existing web tests kept passing until the screens moved, as the ticket
  required. Where the old formula and the new one both apply — a week of fallback rows — they give
  the same number, so no existing expectation changed value; only the shape assertion did.
- **Run detail** adds `manual_seconds_per_row`, `automated_seconds_per_row` (wall clock ÷ done
  rows, one decimal) and `saved_seconds` (the run's whole manual time less its wall clock, floored
  at zero). All three are `None` while the run is open or when no row finished.

### 3. Web — `lib/words.ts`, `pages/RunDetail.tsx`, `pages/Home.tsx`

- `words.ts` gains, in the existing format-helper style:
  - `secondsWords(130) -> "2 min 10 s"`, `secondsWords(14) -> "14 s"`, `secondsWords(180) -> "3 min"`;
  - `timeComparisonWords({...})` → `"By hand: about 2 min 10 s a row · ProcessLens: 14 s a row ·
    About 31 minutes saved"`, or `"By hand: about 3 min a row (estimated)"` when unmeasured;
  - `estimatedRowsNote(12) -> "estimated for 12 rows"`, and `null` at zero;
  - `ESTIMATED_MANUAL_SECONDS_PER_ROW = 180`, the one place the fallback is named.
- `RunDetail.tsx` prints the comparison as one line directly under the outcome (inside the
  progress panel, using the page's existing `.times` meta styling, so no CSS file was touched). It
  shows nothing while the run is open or has done no row. The "Time saved" figure now comes from
  `saved_seconds` when the API sends it, with the old arithmetic only as a payload fallback, and
  its small line says which basis was used.
- `Home.tsx` draws its gold figure from `saved_seconds` and shows the small note only when
  `estimated_rows > 0`.
- Both pages read the new fields through a local intersection type (`HomeSummaryTime`,
  `RunDetailTime`) declared in the page file, because `apps/web/src/types.ts` is outside this
  ticket's file list. The note in each page says so, so the next change can fold them into the
  shared types.

## Residual risks

- **"Automated" is the runs' wall clock, not the sum of per-row times.** It is the same definition
  the Home figure always used, so a run that waits 10 minutes for a person still counts those
  minutes against the saving. The ticket kept that definition.
- **The week's automated side spans all finished runs**, while the manual side counts only
  `verified` transitions. A run whose rows were all parked adds wall clock and no manual time,
  which lowers the week's saving — arguably correct, but worth knowing.
- **Per-row automated time is an average** (wall clock ÷ done rows). One slow row and nine fast
  ones read as one uniform number.
- **Fallback is fixed at 180 s.** A tenant whose real manual time is very different, on a task that
  never measured itself, gets a figure that leans on the old guess — which is why the estimate is
  counted and labelled on both screens.
- **`types.ts` still lacks the new fields.** The two local intersection types work and are
  commented, but the shared types should absorb them in a small follow-up.
