## Summary

Implemented all 6 fixes from `internal/agent/tickets/PL-031.md` against the real owner's Odoo quick-create recording (`packages/compiler/tests/fixtures/odoo_quick_create_owner.json`). The fixture was left unedited; the compiler now handles it as recorded.

## Fixes implemented

1. **Drop Odoo's "?" help marker from labels**
   - Compiler (`packages/compiler/normalize.py`): strips a trailing `?` from recorded step names and target-rung text when the prefix is a real word.
   - Recorder (`apps/extension/src/shared/fingerprint.ts`): `accessibleName`, `labelText`, and `aria-labelledby` now exclude `<sup>`/`<sub>` children whose trimmed text is `?`.

2. **A retried field keeps only its last attempt**
   - Added `_fold_retried_fills` in `packages/compiler/compiler.py`. When the same first rung is filled again before the commit step, the earlier fill and intervening clicks that only touched that field are dropped.

3. **Drop container clicks**
   - Added `_drop_container_clicks` in `packages/compiler/compiler.py`. Drops css-only clicks with no durable rung, and `role: generic` clicks whose text contains two or more input labels.

4. **Don't record what the page typed**
   - Recorder (`apps/extension/src/content/recorder.ts`): fill events now carry a `keystrokes` count.
   - Compiler (`packages/compiler/compiler.py`): a fill with `keystrokes == 0` whose value equals another field's value is page-set and dropped. For older recordings without `keystrokes`, the same value on a different field is treated as page-set only when the fill arrived within 50 ms of another fill (covers the unedited fixture's Opportunity fill).

5. **A "Create" option must also accept an existing record**
   - Added `_expand_create_option` in `packages/compiler/compiler.py`. A `Create "{{row.<col>}}"` option click gets an exact-match rung first (`{{row.<col>}}`), then the Create template, so existing records match before a new one is created.

6. **A quick-create save must be checkable**
   - Added `_infer_assertion_from_fills` in `packages/compiler/compiler.py`. When an explicitly-marked commit click has no observation and no navigation, but a previous fill was templated from the record key or a required column, the compiler infers `assert_after: {"text_visible": "{{row.<col>}}"}` and warns that "this save is checked by the new record's name appearing".
