### 2. Re-check the rows the moment a column changes

`apps/web/src/pages/TaskRun.tsx`:

- The shared half of `continueOn()` is now `saveMappingAndCheck(from)`: PUT `/batches/{id}/mapping`,
  then GET the check. `continueOn()` calls it and keeps its old behaviour — save, ask, `setStep(3)`.
- The select's `onChange` records the pick (`editMapping`) and calls `recheckColumns()`, which sends
  the same save-and-ask immediately and stays on step 2. It writes the answer to `confirmed`, so the
  row problems and the "N rows ready · M rows need a look" line refresh under the dropdown.
- **Keeping the pick, and the latest answer only.** The picks live in a ref (`editsNow`) as well as
  in state, so a request started in the same tick as the click reads the pick the person just made,
  not the previous render's. Every save-and-ask — a column's and Continue's — goes through one
  chain (`inAskOrder`), and each step of the chain reads the picks **when it starts**. Two changes
  can therefore never race: the second ask runs after the first, sends the later mapping, and its
  answer lands last, so a slow earlier answer cannot replace a newer one. A failed ask rewinds the
  chain rather than wedging it.
- `asking` is a counter, so "Checking…" stays up until the last queued ask settles.

### 3. Do not guess a column whose values do not fit the field

`services/api/batches.py`:

- New `_fits_kind(kind, raw_rows, column)`: the column's non-blank values are counted against
  `kinds.is_email` / `kinds.number_value`; the column fits when **at most** half fail (so a tie, a
  1-of-2 column, keeps its place and its stray value is still flagged row by row, as the ticket's
  guard requires). Blank cells are ignored here — they belong to the task's own `missing` rule.
- `_match` takes the field's `kind` and the rows, and ranks only the offered columns.
- `_mapping_for` reads the kind from the field's example (`kinds.kind(spec["example"])`) and passes
  it down; `check_batch` passes `raw_rows = [row.raw for row in rows]`, so every row is read, not
  just `row_one`.
- A saved mapping is untouched: `_with_saved` still runs after the guess and still wins.

**One judgement call, flagged for T1.** An exactly-named column is exempt from the fit test: a
spreadsheet column whose normalised name equals the field's (`Email` for `email`) keeps its place
even when most of its values do not fit. Two reasons: the ticket's own example is a column matched
by a *shared word* ("Expected" for `expected_revenue`), not by its exact name; and
`tests/api/test_batches_value_checks.py::test_a_value_that_is_not_an_email_in_an_email_column_is_flagged`
— an existing test the ticket does not list for change — needs exactly that column chosen so its two
bad values are flagged "isn't an email". A literal reading of item 3 would unmap that column and the
existing test would fail, so the exemption is where the two requirements meet. If T1 prefers the
strict reading, the change is one clause in `_match` and that one existing test moves from "flags
two bad values" to "leaves the field Not found".

### 7. "Not found" stops for a person, who can skip it in one click

T1's review rejected the first version of this item, and the review is right. Ending the row
`skipped` is final, but `element_absent` cannot prove the record is gone: it is also true before a
slow results table has drawn, and on a login page, an expired-session dialog or an error page. The
executor's wall probe runs only when a check answers false (`service-worker.ts`
`probeWallForCheck`), so an absence that answers true never probes at all. A skip there would lose
the row for good. The row now parks, and a person skips it with one click after looking.

- `packages/compiler/compiler.py`, `_not_found_branch(value_template, host)`: outcome `parked`,
  name `Park a record when the search finds nothing`, reason `Not found in <host>.`; with no host
  the reason is `Not found in the app.`, which still starts with `Not found in` — the prefix
  `rowOutcome` reads. The host comes from `urlsplit(candidates[search_run].url).hostname`, i.e. the
  page the search ran on.
- The compile warning no longer talks about an outcome: `the search finds the record to change; if
  it finds nothing, the row is left for you to skip`. It carries none of `ENGINE_WORDS`.
- `apps/web/src/pages/needsHelpActions.ts`, `recordActionLabel(action, reason?)`: the existing
  parked-to-skipped dismiss reads `Skip it` for a row whose reason starts with `Not found in`, and
  `Dismiss` for every other row. `isNotFoundReason` in `lib/words.ts` is the one predicate behind
  the label, the sent reason and `rowOutcome`, so they cannot drift.
- `actionReason(action, reason?)` in the same module is what the two row tables pass as the request
  body's `reason`: the not-found reason for a dismiss, and nothing for every other action. A normal
  dismiss still gets the API's own default sentence, and a requeue still sends `{}`.
- `apps/web/src/pages/RunDetail.tsx` and `NeedsHelp.tsx`: the button uses that label and sends the
  row's own reason with the dismiss, so a skipped not-found row still reads `Skipped` rather than
  `Already there` afterwards. It is the existing `POST /api/v1/records/{id}/dismiss`, no new
  endpoint, and no destination tick: the record never reached a commit.
- `apps/extension/src/popup/make-recipe.ts`: `PARK_WHEN_NOTHING_FOUND` is back to
  `Park a row when the search finds nothing`, which is again what the branch does. The popup test
  and `tests/e2e/test_odoo_product_price_golden.py` are therefore unchanged from `main`.
- `rowOutcome` is unchanged for a parked row (`Needs your help`); a skipped row with the
  `Not found in` reason reads `Skipped`.
- `apps/web/src/lib/words.ts`, `plainReason`: a not-found reason is shown exactly as written.
  The code-to-words fallback turns `_`/`-` into spaces, which rewrote the host in
  `Not found in my-crm.example.com.` as `my crm`; the reason is the row's whole explanation, and its
  own test already said "as it stands". The shortcut is limited to the not-found reason, so every
  other reason keeps its old path.
- **Ledger untouched.** The branch runs after the search and before any commit, so the record is in
  `filling` (or `prechecked` if it preceded every step, which it does not) with `commit_attempted`
  false. `filling → parked` is legal, and the person's skip is the ordinary `parked → skipped`
  dismiss (migration 0003). `run_loop`'s `end_record` still turns a commit-attempted skip into a
  park (B2).

  The one shape that could put the record somewhere else — a recording whose `commit_step_ids`
  names a step **before** the search — was traced in the first revision and is unchanged: the
  compiled order is `fill(commit) → press → branch → …`, but every exit from `_commit_step` is
  terminal (`verified`, `failed`, `reconcile`, or a parked/stopped path), so a record that reaches
  that commit never goes on to the branch. Nothing to report as a state violation.

## Notes for T1

- **How this revision was checked.** The gates below ran at the final head. Two independent reviewer
  children were started to refute the change; one failed for provider credit and the other spent its
  budget re-reading a tree that was still being edited, so neither produced a usable review. I did
  the refutation pass myself instead: a probe confirmed the compile warning carries none of the 12
  `ENGINE_WORDS` patterns, a probe with the search step's URL removed confirmed the empty-host branch
  really compiles to `Not found in the app.`, and the ledger guard's legal set was read to confirm
  `filling → parked` and `parked → skipped` (both `commit_attempted = false`) are the transitions used.
  Treat that as one reviewer's pass, not two independent ones.

- **Item 7 changed under review, and the ticket's words are superseded.** The ticket asked for
  `skipped`; the review showed that `element_absent` cannot tell "no such record" from "results not
  drawn yet", "login page", "expired session" or "error page", and that a skip is final. The code
  now parks with the same reason, and the run page and Needs help offer one-click **Skip it** through
  the existing dismiss. `packages/compiler/tests/test_pl106_not_found_skips.py` keeps its ticket
  filename (the review changed the outcome, not the item), and its docstring says so.
- **The skip is still one click and needs no confirmation.** Only a commit-attempted row carries the
  destination tick; a not-found row never reached a commit, so `actionGate` leaves it actionable
  with no extra box. The button sends the row's original reason so the skip is not relabelled
  "already there". Needs help uses the same `recordActionLabel`, so the identical row reads
  "Skip it" there too; leaving it as "Dismiss" on one screen and "Skip it" on the other would be
  the same row under two names. That is the one place this fix reaches beyond the run page.
- **A wrong park is recoverable; a wrong skip was not.** The cost of this choice is that a row
  parked on a login or error page reads "Not found in <host>." until a person looks. That is the
  intended trade the review asked for.
- **Item 3's exact-name exemption** and **item 8's sidebar line on `/apps`** are the two places where
  the ticket's words met an existing test's requirement; both are argued above and either can be
  flipped in a line.
- **Home's "already there" count still counts every skipped row**, including one a person skipped
  after a not-found search. The ticket puts that split out of scope; it now under-counts only rows a
  person consciously skipped, not ones the engine skipped for them.
