## Part A (first push): items 1–9 and 14, plus 15 and 16

### 1. A button's name leaves out what the page hides
`nodeTextExcludingHelp` (`apps/extension/src/shared/fingerprint.ts`) skips a subtree that is
`aria-hidden="true"`, `hidden`, or `display:none`/`visibility:hidden` (inline first, computed style
when available); opacity alone still counts as visible. `accessibleNameOf` in
`apps/extension/src/executor/ladder.ts` computes the name the same way, and a role rung also accepts
the element's old full-text name (only when the name comes from its own text) so a recipe pinned
before this fix still resolves.
Proves: `apps/extension/tests/pl107-recorder.test.ts` ("a button's name leaves out what the page
hides", both cases); `apps/extension/tests/executor-ladder.test.ts` (still green).

### 2. Every box of a split code is a code field
`isPasswordField` now builds on `isCodeFieldOnOwn` (password, one-time-code hint, a code name, a
`maxlength="1"` row, a `Digit N of M` label read cheaply, or a numeric field labelled a code) plus
`inCodeRow` (4–8 same-shaped sibling inputs where one is a code field). An ordinary six-field form
stays ordinary. The digit label is read from aria-labelledby/aria-label/a wrapping label first, so a
page of ordinary text fields never pays for an accessible name; `inCodeRow` skips any container with
more than 20 children so a 1000-field snapshot stays fast.
Proves: `apps/extension/tests/pl107-recorder.test.ts` ("every box of a split code is a code field",
four cases); `recorder-code-fields.test.ts` and `recorder-snapshot.test.ts` (cost) still green.

### 3. One click on a submit button is one line
`stepLines` (`apps/extension/src/popup/flow.ts`) folds a `submit` that comes right after a `click`
on the same first target into that click's line.
Proves: `apps/extension/tests/pl107-recorder.test.ts` ("one click on a submit button is one line").

### 4. Teaching never records the email tab
`isEmailHost` (`apps/extension/src/shared/email-code.ts`) knows Gmail, Outlook (live/office), and
Yahoo Mail; plain google.com is not mail. `RecorderSession.append` drops an event whose URL is an
email host and returns `null`; the service worker (`appendEvent`, the `record:event` case, and the
navigation listener) handles the drop.
Proves: `apps/extension/tests/pl107-recorder.test.ts` ("teaching never records the person's email
tab", both cases).

### 5. Start over is always there; Start teaching starts empty
`PanelTeach` (`apps/web/src/panel/PanelTeach.tsx`) shows **Start over** whenever there are steps and
it is not recording (it sends `record:clear`); **Start teaching** sends `record:clear` before
`record:start`.
Proves: `apps/web/tests/pl107Panel.test.tsx` ("starting over", both cases).

### 6. Ask which click saves; "Nothing gets saved" is an answer
A select labelled **Which click saves your work?** under the step list, one option per recorded click
(its line's sentence, value = step id), then **Nothing gets saved** (value `""`, sending
`commit_step_ids: []`). The last click stays the default. The step list still shows the click lines
that carry a problem, so a sentence never appears twice.
Proves: `apps/web/tests/pl107Panel.test.tsx` ("which click saves", three cases).

### 7. A refused save says why, on the same screen
`compileRefusalSentence` (`apps/extension/src/popup/words.ts`) maps a "no assertion could be
inferred" refusal to the sentence that names the click and points at the save question; a schema /
step-name refusal keeps PL-103's plain sentence; anything else becomes "This recording can't be saved
yet: …". Both the panel and the popup use it.
Proves: `apps/web/tests/pl107Panel.test.tsx` ("a refused save says why"); `popup-make-recipe.test.ts`
still green.

### 8. Try again on a finished run puts it back to work
`requeue_record` (`packages/ledger/records.py`) sends a `completed` run back to `queued` and clears
its worker/lease fields via `reopen_completed_run` (`packages/ledger/runs.py`), in the same
transaction. A `running`/`paused` run is left alone. A `cancelled` run is refused with 409 and "This
run was stopped. Start a new run to try this row again." The SQL lives in `packages/ledger`.
Proves: `tests/api/test_pl107_try_again_reopens.py` (finished → queued, running stays, stopped → 409).

### 9. The panel tells the truth about the row it tried
`TaskRun` (`apps/web/src/pages/TaskRun.tsx`) reads the preview row from
`/api/v1/runs/{id}/records` and takes the "Try one row" badge from `rowOutcome(row.state)`, not the
run's status. A parked/failed row shows its plain reason and its **Try again** / **Skip it** buttons
there, through the same `sendRecordAction` as RunDetail (with the destination check when the row may
already be saved).
Proves: `apps/web/tests/pl107TaskRun.test.tsx` (badge + reason + buttons, Try again posts the record
action, a verified row reads Done).

### 14. Say what the key column question means, and default to the email
Panel and popup label: **Which value is different for every row?** with "We use it so nothing gets
added twice." `defaultRecordKeyColumn` (`apps/extension/src/popup/make-recipe.ts`) prefers an
email-shaped value, then an id/number, then a person's name, and offers no default when nothing fits.
Proves: `apps/extension/tests/pl107-key-column.test.ts`;
`apps/web/tests/pl107KeyColumn.test.tsx` (label, hint, email default).

### 15. Try again keeps the row's original reason
`requeue_record` keeps the row's previous reason as `Trying again — last time: <original>` instead of

Proves: `tests/api/test_pl107_try_again_reopens.py`

### 16. A "create" option in a dropdown follows the row's value
The compiler already templates a `Create "<value>"` option and orders the exact value first

name becomes `Create "{{row.contact}}"`, and the exact option is rung 1 while the Create option is
rung 2, so an existing record is clicked and a missing one is created.
Proves: `packages/compiler/tests/test_pl107_item16.py`;
`apps/extension/tests/pl107-create-option.test.ts` (resolver picks the exact option, then Create).

## Part B (second push): items 10–13

### 10. A cookie notice in the way is answered, not reported as "something in front"
`answerConsentNoticeInPage` (`apps/extension/src/executor/consent.ts`) runs in the page when a click's
hit test finds the target covered: it walks up from the covering element to a consent notice (a
dialog/region/banner/aside, or a container whose own class/id/aria-label says cookie/consent/
privacy, that mentions cookies/consent/privacy and holds buttons) and clicks a reject-style button
(Reject all / Reject / Decline / Refuse / Necessary only / Only essential). The click branch in
`step-runner.ts` then retries the click once. If the notice offers only Accept/Allow/Customize,
nothing is clicked for the person: it parks with `A cookie notice is covering the page. Answer it
in the work window, then press Try again.`
Proves: `apps/extension/tests/pl107-consent.test.ts` (Reject answered and the click retried;
Accept-only parks with no press; a non-notice overlay is ignored).

### 11. A click the site already did by itself counts as done
`resolveWhenReady` (`apps/extension/src/executor/step-runner.ts`) takes an optional probe; the click
branch passes one that asks the step's own `assert_after` once on each wait. If it holds while the
target is busy/disabled, the step is done with detail "the page moved on by itself" and no press is
sent. `aria-busy="true"` is now treated as not-ready beside `disabled`/`aria-disabled` in the
resolver, so a busy control is waited on rather than clicked. A step with no assertion keeps today's
behaviour.
Proves: `apps/extension/tests/pl107-self-done.test.ts` (busy and disabled targets with a held
assertion are done with no press; no assertion keeps the park).

### 13. A column is not named after a field's hint text
`humanName` (`apps/extension/src/popup/make-recipe.ts`) skips a name that is an example placeholder
("e.g. …", "eg …", "Example: …", "such as …"); when that was the only name, it uses the field's own
id/name from its css rung, then calls a text field "Name".
Proves: `apps/extension/tests/pl107-column-name.test.ts` (id fallback, "Name" fallback, a real label
kept).

The ticket also asks the Check-it step to suggest a file column by value shape when no header matches
by words. That matching lives in the API's batch check and was not changed this push; with the column
now called "Name" instead of "E g product pricing", the existing word match against "Full Name" is the
path that works tonight.
