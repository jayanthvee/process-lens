## 2. A stray step can be deleted after Stop

**The line.** `src/popup/flow.ts` now owns the live list: `stepLines(events)` maps one line per
recorded interaction (an `observation` and an `unrecordable` get no line; a `navigate` does), and
`renderStepList(list, events, { recording, onRemove })` draws it. Each line is the plain sentence
plus a quiet `×` button with `aria-label="Remove this step"`; the button is `hidden` while
recording and shown after Stop. `popup.ts` redraws through it on every `record:state` and from the
worker's answer to a removal.

**The message.** `src/shared/messages.ts` adds `{ type: "record:remove"; seq }`. `popup.ts` sends
the line's `seq`. `src/background/service-worker.ts` handles it in one new case: when
`canRemoveStep(status.state)` (idle) it calls `session.remove(seq)` and updates `count`; while
recording it does nothing and the unchanged status goes back — a silent refusal.

**The session.** `RecorderSession.remove(seq)` in `recorder-session.ts` drops the event with that
`seq` and the `kind: "observation"` event recorded immediately after it. That adjacency is the link
the recorder keeps for same-document evidence; the arrival/pending-target path is the other kind,
and an observation attached to the action itself (`event.observation`) goes with the event. An
`arrival` still pointing at the removed step is cleared, so nothing waits for evidence about a
step that is gone. Nothing else changes, and step ids are never re-minted: `sequence` keeps
counting from where it was. `canRemoveStep(state)` is the one rule the worker and the hidden button
read.

**Re-render.** The worker's response carries the new `status` and `events`; the popup re-renders
the count and list from them and calls `makeRecipeForm.refresh(events)`, so the Save form's columns
lose the removed step too.

**Tests.** New `tests/popup-remove-step.test.ts`, 11:
- every line carries a labelled, quiet × on a real button;
- hidden while recording, shown after Stop;
- a click sends `{ type: "record:remove", seq }` with the line's own `seq`;
- the list and the count re-render without the removed step;
- `RecorderSession.remove`: the step and its observation; a step with no observation leaves the
  next event alone; the last step; an observation attached to the action; an unknown seq; the
  arrival target the removed step was owed;
- `canRemoveStep` refuses `recording`, permits `idle`.

`recorder-session.test.ts` (21) still passes. `popup-words.test.ts` now drives the real
`renderStepList` and checks each line's sentence and its remove button, so the test cannot drift
from the popup's own list.
