## The blocker (resolved by T1)

> **Resolved.** T1 approved option 1 (widen the Scope to those three files) and it is applied: see
> *Review fixes* below. `pytest -q` is now fully green.

Requirement 1 says the front door applies to **every** HTTP route and must refuse any client that is
not loopback and any `Host` that is not `127.0.0.1:<port>`/`localhost:<port>`. Three existing test
files — **`tests/db/test_health_api.py`, `tests/db/test_recipes_api.py`, `tests/db/test_runs_api.py`**
— build their client as a bare `TestClient(app)`, and the ticket's Scope does not include `tests/db/`.
I probed the real behaviour with the hub's own predicates rather than guessing
(`.data/probe_frontdoor.py`, no repo change):

```
default TestClient  -> 403 {'host_header': 'testserver',   'client_host': 'testclient', 'loopback': False, 'host_local': False}
base_url 127.0.0.1  -> 403 {'host_header': '127.0.0.1:8000','client_host': 'testclient', 'loopback': False, 'host_local': True}
```

The default client is refused **twice over**: httpx's `Host` is `testserver`, and its client address
is `testclient`, which is not loopback. Even `base_url="http://127.0.0.1:8000"` still fails the
loopback check — the client address must be set too, i.e.
`TestClient(app, base_url="http://127.0.0.1:8000", client=("127.0.0.1", 51234))`, which is the shape
`tests/api/` and `tests/runner/test_hub.py` already use.

There is no in-scope way around it: a `Host` check that tolerated `testserver` would be exactly the
CSRF hole requirement 1 exists to close. So the choice is T1's:

1. **Widen the Scope to those three files**, so their client construction becomes the local one above
   — one line each, no assertion changes (the same kind of change T1 authorised for the hub tests).
   This is my recommendation: it keeps requirement 1 intact and the `pytest -q` gate meaningful. I
   have **not** touched them.
2. Or decide otherwise (a different rule, or accept a red `pytest -q` on this branch with the reason
   recorded). I did not choose for you.

## Requirements, one line each

1. **The API's front door.** `services/api/middleware.py` (new) — an ASGI middleware: `Host` via the
   hub's own `host_header_is_local`/`LOCAL_HOSTS`, peer via `is_loopback`, `Origin` on a
   state-changing request only when absent or equal to this API's own origin, and `Content-Type`
   `application/json` whenever a body is present (a header-declared body, or a peeked one). Non-Http
   scopes pass straight through, so the hub keeps its stricter checks. Tests
   (`tests/api/test_frontdoor.py`): `test_a_non_loopback_client_is_refused`,
   `test_a_rebound_host_header_is_refused`,
   `test_a_foreign_origin_on_a_state_changing_request_is_refused`,
   `test_a_text_plain_body_is_refused`, and the control
   `test_an_absent_origin_is_accepted`.
2. **The read endpoints.** `services/api/runs.py` + `packages/ledger/reads.py` —
   `GET /api/v1/runs` (`list_runs`: newest first, capped at 50, recipe name/version, per-state counts
   as `dict[str,int]`), `GET /api/v1/runs/{id}/approvals` (`list_open_approvals`: undecided only).
   `RecordDetail.commit_attempted` already existed, so requirement 2's last clause needed no change.
   Tests (`tests/api/test_runs_reads.py`): `test_the_runs_list_is_newest_first_with_recipe_and_counts`,
   `test_the_runs_list_is_capped_at_fifty`, `test_the_approvals_endpoint_returns_only_undecided_requests`.
3. **Dismissing a parked record.** `packages/ledger/records.py::dismiss_record` implements the
   "Dismiss a parked record as skipped" pattern, and `POST /api/v1/records/{id}/dismiss` exposes it.
   `commit_attempted = false` goes straight to `skipped`; a commit-attempted record carries
   `destination_checked_by` and the fresh check in the same update, with the trigger as the authority.
   **The trigger's refusal is an `IllegalTransition`, not a `StateConflict`** — the first cut of the
   endpoint caught only the latter and returned 500 on the no-check case; it now catches both and the
   test below pins the 409. Tests (`tests/api/test_dismiss_api.py`):
   `test_dismiss_a_non_commit_record_goes_to_skipped`,
   `test_dismiss_a_commit_attempted_record_without_a_check_is_409`,
   `test_dismiss_a_commit_attempted_record_with_a_check_is_dismissed`,
   `test_dismiss_a_verified_record_is_409`, `test_dismiss_a_missing_record_is_404`.
4. **The operator identity.** `services/api/main.py` — `GET /api/v1/operator` returns the
   `PROCESSLENS_OPERATOR_ID` UUID, or 503 with a sentence when it is unset, blank, or not a UUID;
   nothing invents an id. Tests (`tests/api/test_operator.py`): `..._is_503_when_the_variable_is_unset`,
   `..._is_503_when_blank_or_not_a_uuid`, `..._returns_the_configured_id`.
5. **The page.** `apps/web/` (new) — TypeScript + Vite, no framework, Vitest with happy-dom, the same
   versions as `apps/extension` (TypeScript 5.6.3, Vitest 4.1.11, `@types/node` 22.x; happy-dom
   replaces jsdom, which requirement 5 mandates). `npm --prefix apps/web run check` runs typecheck →
   test → build. `services/api/main.py` mounts the built `apps/web/dist` at `/` with `StaticFiles`,
   registered **after every route** (a mount at `/` catches whatever no earlier route matched, so it
   must be last — `/health` and `/api/v1/operator` are defined above it and still answer), and `/`
   returns a one-line build hint when there is no `dist`. The page polls every 2s while a run is open
   and stops once it is finished, and renders every value with `textContent`. Tests
   (`apps/web/tests/`): `commitGate.test.ts` (the non-pre-ticked confirmation gates **both** buttons
   and un-ticking re-disables them), `runButtons.test.ts` (buttons follow the status),
   `errorDetail.test.ts` (a 409's `detail` beside the button, no retry; 503 disables the actions),
   `polling.test.ts` (2s ticks, stops when finished), `injection.test.ts` (`<img onerror=...>` stays
   text — no `img` element).

## Running it locally

```powershell
# 1. build the page (once; the API serves the build, not the sources)
npm --prefix apps/web install --cache .cache/npm
npm --prefix apps/web run build

# 2. point the API at the database and give it an operator id to act as
$env:DATABASE_URL="postgresql://processlens:change-me-locally@localhost:5432/processlens"
$env:PROCESSLENS_OPERATOR_ID="3f1c4f5e-0000-4000-8000-00000000abcd"   # any UUID

# 3. serve
.\.venv\Scripts\python.exe -m uvicorn services.api.main:app --env-file .env --host 127.0.0.1 --port 8000
```

Then open **http://127.0.0.1:8000/** — the page and the API share that origin, so the page's own
`Origin` satisfies the front door and no CORS header is involved. Without step 1, `/` answers the
one-line build hint instead of a page. Without `PROCESSLENS_OPERATOR_ID`, the page says the operator
identity is missing and disables the actions that need it.

### B1 — the front door broke pairing with the real extension

The extension's service worker opens its session with `POST /api/v1/executor/sessions` and Chrome
sends `Origin: chrome-extension://<id>`; the door refused it, so Connect got a 403 and no batch could
run. Fixed in `services/api/middleware.py`: `_origin_refusal` now also accepts exactly
`chrome-extension://{PROCESSLENS_EXTENSION_ID}` — via the hub's own `origin_is_extension`, so an unset
id accepts nothing — and only when `request.url.path.rstrip("/") == "/api/v1/executor/sessions"`.
The host, loopback and content-type checks are untouched, and every other route still accepts only
the API's own origin.

Tests in `tests/api/test_frontdoor.py` (all four fail without the exception):
- `test_the_pinned_extension_origin_may_open_a_session` → 201
- `test_another_extension_id_may_not_open_a_session` → 403
- `test_the_extension_origin_opens_no_other_route` (on `POST /api/v1/runs/{id}/cancel`) → 403
- `test_an_unset_extension_id_accepts_no_extension_origin` → 403

### B2 — dismiss accepted a `prechecked` record

`commit_attempted = true` / `= false` predicate and its parameters verbatim), and both refusal
