Items 1, 2 and 6 are done; item 5 is done for sliders, range inputs, number fields, +/− steppers and

## What changed

**Schema.** `packages/recipe/schema/recipe.schema.json` gains `step_check`: `action: "check"`,
`targets`, `value` (a value source), and an optional `checked` (the state the demonstration left the
field in). `check` joins the step union. The commit-assertion rule applies to it like any other
commit-capable step.

**Recorder** (`apps/extension/src/content/recorder.ts`).
- A checkbox's `change` now emits one `check` step carrying the state it ended in, instead of a
  click that flipped the box on replay. A switch built from a button and `role="switch"` is read the
  same way, one turn later so the page's own handler has run.
- A radio's `change` emits one `select` **on its group** (its radiogroup, fieldset, form or parent),
  with the chosen option's own label — so another row can choose another option.

**Types** (`shared/recipe-types.ts`, `executor/types.ts`): `CheckStep`, `RecordedKind` gains
`"check"`, `ExecutedAction` gains `"check"`.

**Executor** (`executor/fields.ts`, new; `dispatch.ts`, `step-runner.ts`, `executor.ts`).
- One page-side function, `fieldActionInPage`, in four modes: `check`, `choose`, `number`, `read`.
  It is self-contained because it is serialized with `toString()`.
- `check`: idempotent. A box already in the asked-for state is left alone, so the flip is gone.
- `choose`: exact match, then case/space-insensitive; **a bare number is the option's place in the
  row**, which is how "3" picks the third star. A value the group does not offer parks with every
  option it does offer. A control that is not a group answers `not a group`, so a custom combobox
  still takes the existing open-and-click path.
- `number`: writes a range/number input through its own value setter, sets a `role="slider"` the
  same way, and for a stepper presses its +/− buttons until the number matches (bounded, and it
  reports a limit rather than looping).
- `step-runner.ts`: a `check` step resolves its ladder, coerces yes/no, and parks if the field will
  not take the value. A `select` whose native and combobox paths both missed now falls through to
  `choose`, which is what makes a radio group and a status bar work. A `fill` of a numeric value on
  a range/number control is set, not typed; a field that is not a number control answers so and the
  ordinary typing path runs unchanged.
- `executor.ts`: `check` joins the executed actions and the "must carry a ladder" rule.

**Compiler** (`packages/compiler`). `check` is an actionable step action; a recorded check renders
as `action: "check"` with its `value` and `checked`, never `clear_first` or `option_match`. A taught
check is bound to the sample row's yes/no column when exactly one column means the same thing
(`yes/y/true/1/x/on/✓` against `no/n/false/0/off/blank`, case-insensitive), with a warning when
several columns could be it.

**Runner** (`services/runner`). `_command` renders a check's value and sends a real boolean; a cell
that is not a yes or no raises `‘<value>’ isn't a yes or no for <field>.`, which the existing
`TemplateError` path parks. `creation.py` accepts `check` in its action whitelist — without that,
every recipe with a check step would be refused at run creation.

**Words** (`apps/extension/src/popup/words.ts`): "Ticked Limit registrations" / "Unticked …", and
"Chose Goods for Product type" when the field's own name is not the value.

## Not done

1. **Item 3, click-only date pickers.** Not started. Nothing about calendar grids, month navigation,
   date formats or the ambiguous `03/04/2026` park exists. A `fill` of a readonly date field still
   goes through the typing path, and the step then parks with the existing "the page changed the …
   as it was typed" sentence rather than choosing a day.
2. **Item 4, tags and chips.** Not started. A cell "VIP, Partner" is not split; the chip machinery
   is unchanged.
3. **Item 5, recording a star row.** The executor can click the Nth star, but the recorder still
   records a click when a star is clicked, so a taught rating is not yet a `select` with the
   number. One half of the item is missing, and its recorder test with it.
4. **Item 7, uploads.** Teaching records no upload step (proved above), and I did not invent one:
   the step's value has to name a column the run attaches a document from, and teaching has no way
   to know that column. Guessing one would produce a recipe that fails to compile or uploads the
   wrong file. The missing decision is a file-column picker in the panel, next to the key and save
   choices; the recorder hook is the `type === "file"` early return in `onInput`/`onChange`.
5. **Panel wording for the kinds that are missing** — "Set the date to 5 Nov 2026", "Picked tags
   VIP, Partner", "Set the rating to 3 stars" are not written, because those steps do not exist yet.
6. **The "can't repeat" panel sentence** for drag-and-drop, colour pickers and signature pads is not
   written; those interactions are unchanged.
