### The fix

`_infer_assertion_from_fills` now considers only the **entry the save belongs to**: a new
helper `_page_change_start` walks the steps before the save and finds the last **page
change** — a `navigate` step, a step whose `after_url` landed on a URL path other than the
save's page, or a step whose folded `observation.url_matches` pattern does not fit the
save's page path (`re.fullmatch(pattern, save_path) is None`). A candidate whose
observation carries no URL (`url_matches`) is never a page change. Steps after that point
are the entry; with no page change the whole recording is one entry, exactly the behavior
before PL-044. Both `first_entry` and the `columns` check use only that entry. If the entry
gives nothing, the function still returns `None` — no fallback to an earlier entry.

## The exact new check value

For the two-saves fixture (`odoo_two_saves_owner.json`) trimmed at seq 24, with
`commit_step_ids=["click-8"]` and record key `email`:

```json
"assert_after": { "text_count_increases": "{{row.contact}}", "timeout_ms": 8000 }
```

Why `{{row.contact}}`: the abandoned entry's pick ("Probe Four Contact", seq 4) sits before
the page change — the Internal link click (seq 9) carried the observation recorded on the
contact's own page (`url_matches: /odoo/crm/res.partner/\d+`, which does not fit the
kanban's path `/odoo/crm`). The entry therefore starts at seq 11. The second entry's only
option pick is the "Start typing..." hint (seq 14), which `_HINT_OPTION` rejects, so the
check is the second entry's first templated fill: the Contact combobox (seq 15), bound via
the sample row to `{{row.contact}}`. Before the fix the check was the constant
`"Probe Four Contact"`.
