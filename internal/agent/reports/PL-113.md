### B1. A busy commit could mark a row Done with no committed key

**What was wrong.** The busy path called `filling -> verified` from the page's check alone. Two
invariants broke: `verified` for a commit step must come from `verify_commit`, which writes
`committed_keys` in the same transaction (AGENTS.md §4) -- so a re-run re-saved the row; and
PL-107 item 11 says "already done" only when the check was FALSE before the step and TRUE now -- so
a confirmation left on screen from the previous row (or a check that is always true, the PL-113 item
1 bug) marked the row Done.

**Fix** (`services/runner/run_loop.py`). A busy prepare now needs a definite false-before: the
check is read once with a 0 ms timeout (`_check_before_step`, which returns `None` for no answer and
never treats an unknown as a false), and the path is taken only when that read is `False`, the
same check then passes, and the executor answered. The row then ends through the normal commit
window -- `begin_commit` (write-ahead), `submitting -> reconciling`, and `_reconcile`, whose
destination check ends in `verify_commit` with the key. A destination without the record sends the
row back to `pending` rather than calling it Done.

The "before" read sits just after `prepare` (which sends no input) rather than before it, so the
commit path's post-assertion event drain keeps its place; moving it before `prepare` made
`test_event_draining.py::test_a_challenge_during_the_commit_assertion_parks_the_record` release the
record to `pending` instead of parking it in the commit window, which is an invariant this ticket
has no business changing.

**Proved by** `tests/runner/test_pl113_busy_click.py` (rewritten, 4 tests):
- `test_a_busy_save_whose_check_already_held_parks` -- true before, true after: **parked**, the busy
  sentence, no key. Before the fix this row was `verified`.
- `test_a_busy_save_the_page_completed_is_verified_with_a_committed_key` -- false before, true
  after, destination has it: `verified`, reason `added and checked`, and **one `committed_keys`
  row**. Before the fix there was no key.
- `test_a_busy_save_the_destination_does_not_have_is_not_verified` -- the page's check cannot stand
  in for the destination: never `verified`, no key.
- `test_the_raw_error_is_kept_for_support` -- the busy error stays on the step event (before the fix
  the row was verified without writing one).

The key count is read through `run_records` for this run, because the runner tests share one session
database and an unscoped count saw other tests' keys.

### Minor: a stray control byte in the hint-option pattern

T1 noted `compiler.py` might hold a backspace character. It did: `_HINT_OPTION` ended an alternative
with `\x08` where `\b` was meant, so "No records" never matched as a suggestion box's prompt. It is
now `\b` (a word boundary): `No records` and `Start typing…` match, a real record name still does
not. No existing test pinned the broken behaviour; `packages/compiler` stays green.
