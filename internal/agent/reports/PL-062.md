**Status:** done. One branch (`pl-062`, worktree `.worktrees\deepseek2`), all gates green, pushed.

## What the editor does

`apps/web/src/pages/TaskDetail.tsx` gained an **Edit steps** button (secondary; Run stays the page's
one primary action). In edit mode each step row has:

- **Name for step N** -- an inline input; 1-120 characters. The step's sentence updates as it is
  renamed ("Type the work email").
- **Remove step N** -- refused for the step that saves ("This is the step that saves; it can't be
  removed."), for the last step in a list, and for a step another step names. The refusal shows on
  that row and the step stays.
- **Comes from for step N** -- for a fill or a select only: a dropdown of the task's own columns
  (`meta.input_schema.fields`) or **Fixed text**. Never AI text.
- **How we know it saved for step N** -- for a commit step only: the page shows a text, the address
  becomes a path, or keep what was recorded. The recorded `timeout_ms` is kept.

**Save** and **Cancel** sit at the bottom of the same panel. Save posts the edited document to
`POST /api/v1/recipes?workflow_id=<id>&change_reason=<diffSummary>`; the API stores it as the
workflow's next immutable version and answers with it. A 422 shows the API's problems as plain
sentences at the top of the editor and stays in edit mode with the edit intact. After a save the
page shows the new step list, the new version number, and "Runs already started keep the old steps."

The note under the editor says it once: **"To change what a step clicks, teach that part again."**

`apps/web/src/lib/editRecipe.ts` is the whole model, pure functions with no React: `renameStep`,
`removeStep`, `setValueSource`, `setSaveCheck`, `diffSummary`, plus `flattenSteps`, `columnsOf`,
`stepName` and `problemsInPlainWords`. Each returns `{ok: true, document}` or
`{ok: false, refusal: "<one sentence>"}`.

## What the editor cannot do (by design)

- **Element targets.** No change to `targets`; the note says to teach that part again.
- **Order.** Steps cannot be moved, and none can be added.
- **New versions only.** No stored version is ever rewritten: saving adds N+1, and a run that
  already started keeps the version it pinned.
- **Anything outside the four operations.** No meta, approval policy, variables or `format_version`
  edits; the document is otherwise carried through byte-for-byte.
- **AI text as a value.** The value control offers a column or fixed text, and `setValueSource`
  refuses any other kind.

## Part 3: the task already points at the newest version

`GET /api/v1/tasks` returns `rv.version = (SELECT max(v.version) ...)` per workflow in
`packages/ledger/reads.py` (`_LIST_TASKS`), so a task's `recipe_version_id` is the latest version.
**No change to `reads.py`.** The new API test proves it end to end: create a task, post an edited
document as version 2, then `GET /api/v1/tasks` names version 2's id. It passed before any change
was made, which is the finding the ticket asked for.

## Notes for T1

- **No `goto` in v1.** The v1 schema has no field that names a step id -- a branch and a loop hold
  their inner steps inline. `removeStep` still refuses a step any step's `goto` names (the name this
  format would use if a reference is ever added), and it refuses to empty a branch's list, because
  the schema requires at least one step in `then`, `else` and `steps`.
- **Change reason wording.** `diffSummary` writes, for example, `Renamed step 2; step 2 now comes
  from the "full_name" column; the save is now checked by the address.` The step number is its
  place in the order the run follows, which is the order the page lists.
- **Shared test helper.** `apps/web/tests/helpers.tsx` now records the query string (`search`) on
  each request, so the page test can prove the change reason. `tests/api.test.ts`'s one exact
  request assertion gained `search: ""`.
- **Undo is a full undo.** Cancel drops the draft entirely; there is no per-edit undo.
- **One flaky run.** A full `npm run check` once tripped the suite's 5-second per-test timeout on
  the run-flow page while the machine was loaded (the first transform after a CSS edit); every
  test passed on the clean run before and after, and the slowest test is 2.9 s. Nothing in this
  ticket slows a page render outside edit mode.
- **Not verified by me:** no browser. The 400 px layout is CSS plus the same testing-library pass,
  not a person looking at it.
