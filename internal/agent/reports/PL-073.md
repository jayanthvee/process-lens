## The fix (`apps/extension/src/content/recorder.ts`)

`confirmationIn` recorded a confirmation's whole `textContent`, collapsed. A toast built from a
title and a message (OrangeHRM's `oxd-toast`: "Success" + "Successfully Saved") has its child texts
**run together with no space** — `"SuccessSuccessfully Saved"` — which is a string no page shows, so
the commit check derived from it could never pass.

`confirmationText(el)` now decides what to record:

- **one piece of text** → today's behaviour exactly: the whole collapsed text, cut at 200. A plain
  "Lead created" toast is untouched.
- **several pieces** (the element's own text, then each descendant's own text, in document order) →
  the **longest piece that carries a confirmation word** (`CONFIRMATION_WORDS`: saved, created,
  updated, added, deleted, sent, success, complete, done); otherwise the longest piece.

`presentConfirmationText` — the arrival observation, for a page that arrives showing a flash message
— uses the same helper, so a server-rendered toast is recorded the same way.

## Would the executor have matched the glued text?

No, and the code says why. `text_visible` compiles to `pageText.includes(needle)` after both sides
have whitespace collapsed (`assertions.ts`). The page text is `document.body.innerText`, and
`innerText` puts a **newline between two block-level boxes** — so on the real page the toast reads
`"Success\nSuccessfully Saved"`, which collapses to `"Success Successfully Saved"`. The recorded
needle had no space between the words, so `includes` was false. (The PL-069 reason line also ends in
an ellipsis, another character the page never shows.) With the message recorded, the needle is
`"Successfully Saved"`, which is a substring of the page's collapsed text whether the blocks are
separated or not — so the value the recorder now writes is always one the executor can find.

One honest caveat: jsdom does not implement `innerText`, so the executor test sees glued
`textContent` and can only prove the *new* value is found. The "glued value is not found" half is
proved by the whitespace-collapsed string comparison in the second new executor test, and by the
`innerText` reasoning above.

## The golden: two runs, both spent on a harness defect

`apps/extension/dist` was rebuilt, `reset.py orangehrm` ran (never `odoo` or `all`), and the golden
ran **twice** — the whole budget the ticket allows.

1. **Run 1** came back `xfail` in 58s: too fast to be a replay, so the xfail was hiding an early
   failure.
2. **Run 2** (`--runxfail`, to see it) failed in the demonstration:

   > Locator.click: Timeout 30000ms exceeded. waiting for get_by_role("option", name="CRM Cleanup")

**What it is.** The timesheet's project field **arrives prefilled** — OrangeHRM remembers the last
project and shows it as `"Northwind Traders - CRM Cleanup"`. The demonstration types `"CRM Cleanup"`
into that field without clearing it, so the value becomes `"Northwind Tcrmraders - CRM Cleanup"` and
the app answers **"No Records Found"**. The app's own API returns the project for the same search,
and the project is seeded correctly (probes in `.cache/` show both). Two fixes are needed in the
demonstration, both inside `tests/e2e/test_orangehrm_timesheet_golden.py`:

- clear the field before typing (`hint.fill("")`), as the Odoo golden already does for its
  autocompletes;
- match the option by its text (`has_text=...`) rather than by exact accessible name, since the app
  shows `"<customer> - <project>"`.

PL-073's limits allow this file to change in **the marker only**, so I did not make them. The marker
now carries this failure as its reason rather than PL-069's, which is what the ticket asks when the
run fails further on.

**What is therefore still unproven:** that the recorder fix lets the OrangeHRM commit verify end to
end. The unit tests prove the recorded value, and the executor test proves the value is findable;
the end-to-end path needs one more golden run after the two-line harness fix above.
`strict=True` means that run, if it passes, fails as XPASS — the signal to drop the marker.
