# PL-018c report (T2): the save checks read text inside open shadow roots

**Status:** done.

## The bug

The three text checks in `apps/extension/src/executor/assertions.ts` — `text_visible`,
`text_absent` and `text_count_increases` — read only `document.body.innerText`. Text rendered
inside an open shadow root is never part of that string, so:

- a confirmation inside a web component was never seen and the save went to "could not verify";
- the safety bug: an error message inside a shadow root read as absent, so `text_absent` could
  **pass on a page that was showing the error**.

## The change

1. **`PAGE_TEXT_SOURCE`**, exported from `assertions.ts`: one shared JS expression string that
   evaluates to the page's visible text with the same whitespace collapse as before
   (`.replace(/\s+/g, " ").trim()`). It is:
   - the light DOM: `document.body.innerText || document.body.textContent || ""`, unchanged;
   - plus every open shadow root, found with the same walk `markerExpression` uses in
     `executor/page.ts` (recursive `el.shadowRoot`, so nested roots count). For each root, the
     `innerText` (falling back to `textContent`) of each element child, skipping `STYLE`,
     `SCRIPT` and `TEMPLATE`.
   - The parts are joined with a single space. Closed roots are invisible to page script and
     are never read; iframes are out of scope, per the ticket.
2. **All three checks use `PAGE_TEXT_SOURCE`.** Nothing else in them changed: the fail-closed
   empty-string refusals, the `window.__processLensCounts` baseline logic, and the
   normalization are all as before (the collapse moved into the shared source, applied once to
   the whole string).

## Tests first

New `describe("text checks read open shadow roots (PL-018c)")` in
`apps/extension/tests/executor-assertions.test.ts`, written and run **before** the change —
the first three failed exactly as the ticket predicted:

- `text_visible` finds text inside an open shadow root, and inside a nested one — **failed
  first**;
- `text_absent` fails when the text is only inside a shadow root (the safety test) — **failed
  first**;
- `text_count_increases` counts an occurrence added inside a shadow root after the baseline —
  **failed first**;
- text in a `<style>` or `<template>` inside a shadow root is not counted.

The tests use jsdom's `attachShadow` and evaluate the built expression string the same way the
existing tests do.

## Verified

- `npm --prefix apps/extension run check`: typecheck clean, **443 tests passed (32 files)** —
  including all 4 new tests and every existing test, unchanged — build clean, package
  validation passed.
- `tests/e2e` was **not** run, per the ticket (T1 runs the widget e2e after review).

## Known limits

- `innerText` in real Chrome respects visibility (jsdom falls back to `textContent` for
  everything), so text inside a shadow child the page itself hides still counts — the same
  trade the light-DOM `innerText || textContent` fallback already made.
- Frames remain out of scope; a confirmation rendered inside a same-origin iframe is still not
  seen (PL-018b/T1's frame half).
