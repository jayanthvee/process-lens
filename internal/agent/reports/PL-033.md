# PL-033 — A popup and dashboard a non-technical person can walk through

Status: **complete** — branch `pl-033`, pushed. No e2e was run (T1 runs it); the demo was not
started. Tests were written first and seen failing before the implementation landed.

## Time and cost

- **Total time:** about 23 minutes on the session clock (goal elapsed 1,374 s at report time).
- **Cache %:** the status bar is host-side and not readable from inside the session — read it off
  the operator's bar; this report cannot supply it honestly.

## What was delivered, requirement by requirement

### 1. The popup is three steps (`apps/extension/src/popup/`)

`popup.html` now holds one card per step, in order, marked `data-step="teach|save|open"`:

1. **Teach** — `#start` (Start teaching), `#stop`, `#clear`, the recorder state `#state`, the
   connection status `#session-state`, the step count `#count` ("15 steps recorded", from the new
   `stepCountWords`), and the live list `#steps`.
2. **Save** — the task name `#make-name`, the key select `#make-key`, the duplicate tick, the
   origins and park-field fieldsets, `#make-go`, `#make-result` and the new `#make-plain`.
3. **Open in ProcessLens** — `hidden` until a save succeeds, then shown with one button,
   `#open-task`.

Only the current step's button is gold. `src/popup/flow.ts` (new) holds `currentStep`,
`applyStep` and the card classes: the current card keeps `is-current` and its `button--flow`
buttons keep `button--primary`; every other card's flow button is demoted to `button--quiet`.

Everything else went inside a closed `<details id="more">` named **More**: the commit select
(`#make-commit`, which already preselects the last click via `defaultCommitStepId`), Try one row /
Pause / Resume / Stop (`#run-*`), `#run-state`, `#export`, `#stream` and the streaming field
`#ws`, `#note`, the ProcessLens address `#hub` (default `http://127.0.0.1:8000` kept in the
markup) with `#connect` and `#disconnect`. Inside it, a second closed `<details
id="support-notes">` named **Notes for support** holds `#make-warnings`.

**The popup's own Try one row is out of the flow** — `#run-start` sits under More, not in any
step card. Nothing was deleted or renamed: every frozen id survives exactly once
(`tests/popup-words.test.ts` still parses the markup and enforces that).

### 2. The link works

`#open-task` calls `chrome.tabs.create({ url })` via `openTaskTab` in `flow.ts`, with the address
`taskUrl(baseUrl, workflowId)`. The form no longer renders an `<a href>` in `#make-result` —
`showSaved` reports "… is ready." and calls the new `onSaved` dep with the task URL; `popup.ts`
stores it and lights up step 3. `popup.html` now contains no `<a>` at all, and a test enforces
that.

### 3. Plain words only

- Under the save result, `#make-plain` shows **at most 2 sentences** built by
  `plainSaveNotes` in `words.ts`: "I couldn't check for duplicates because you didn't search
  first." when the recording holds no search, and "Stops and asks when Email is empty." (or
  "… Email or Phone …") from the pre-ticked park columns. Nothing about values the page set or
  about columns; nothing from the compiler.
- `NO_SEARCH_HINT` is now exactly the ticket's sentence.
- **The PL-031 compiler warnings joined `ENGINE_WORDS`** (`skipped the fill`, `bound a literal`,
  `templated`, `derived the input schema`, `dropped container click`, `folded the retried fill`,
  `assertion for`, `this save is checked`) — 14 rules became 22. The word-list test enforces each
  one and fails on every sentence the compiler really sends.
- Everything else the compiler or recorder says is hidden from the person and **kept raw under
  More → "Notes for support"** (`#make-warnings`). `hiddenNote` and the `readableBlock` filter are
  gone; the old "1 more note…" line no longer appears.

### 4. Connecting is automatic and visible

- `flow.ts` also holds `autoConnect`: on open, `popup.ts` reads the session once and, when it is
  `idle`/`disconnected`, sends `executor:connect` to `#hub`'s value (default
  `http://127.0.0.1:8000`) exactly once, then refreshes the session.
- `sessionWords` now says **"ProcessLens isn't running"** for an idle/disconnected session and
  keeps "Connected to ProcessLens" for a ready one; the markup's initial `#session-state` text
  matches.
- **Dashboard:** `runStatusWords(status, chromeAttached?)` in `apps/web/src/lib/words.ts` returns
  **"Waiting for Chrome: open the ProcessLens extension and it will connect"** when a run is
  `queued` and `GET /api/v1/executor/session` reports `attached: false`. `TaskRun.tsx` (Try one
  row) and `RunDetail.tsx` (the run page) both poll the session on the same clock as the run and
  pass it through. With Chrome attached, or while the session is not yet known, "Queued" stands.

### 5. Readable step names (`apps/web/src/lib/steps.ts`)

- The recorder's action prefix is dropped from a step's own name: "fill Contact" →
  **"Type the contact"**; "click Add" still reads **"Click Add"**.
- A `press` step reads **"Press Tab in Phone"**, using its target's label; with no label, just
  "Press Tab".
- A name longer than **40 characters** is not a name: the step shows its action and its first
  label instead ("Type the contact", "Click Add").
- All of it is in `stepWords` (`usableName`/`plainName`/the `press` case) — the place
  `grep -rn "Type the" apps/web/src` points at. The example-recipe expectations are unchanged.

## Frozen contract

`#make-*`, `#start`, `#stop`, `#clear`, `#hub`, `#connect`, `#session-state` and every other
frozen id keep their id, element kind and behaviour; `#hub` still carries
`value="http://127.0.0.1:8000"` in the markup; `#make-result` still carries `is ready` /
`Could not` and stays a separate element from `#make-warnings`; `dataset.state` assignments are
untouched; the two `chrome.storage.session` keys and the request bodies are unchanged. The
frozen-id test in `popup-words.test.ts` passes against the new markup.

## Risks T1 should look at

1. **The e2e fixtures click `#connect` and fill `#hub`, which now sit under a closed
   `<details>`.** Playwright requires visibility for `click`/`fill`, so those fixtures need the
   details opened (or must rely on auto-connect) — the ticket names moving them under More as
   the intended shape, and auto-connect means the popup is usually already connected by the time
   a fixture clicks, but a disabled Connect button (session ready) is also not clickable. T1
   should run the e2e with this in hand; nothing in this ticket may touch `tests/e2e/`.
2. **`plainSaveNotes` shows the duplicates sentence whenever the recording has no search**,
   including before a key column is chosen (the checkbox is disabled in that state anyway). If
   the owner reads that as noise, the fix is to gate it on a chosen key.
3. **The support notes carry the compiler's sentences verbatim** (that is their job), so the
   whole-body engine-word assertion in `popup-words.test.ts` is now scoped to what a person
   reads, not to `#make-warnings`. That is the one deliberate relaxation of PL-025's test, and it
   is the ticket's own requirement.
