No third run: the 75-minute box was nearly spent, and a third failure would still not have told us

## What was established about Twenty (evidence, not guesses)

- The workspace, seeding and REST API all work: 10 seeded people and 5 companies; a reset takes
  ~44 s; `twenty_list_people` reads them.
- **Clicking "+ Create" creates an empty person immediately.** The probe's URL after the click was
  `/objects/people?panel=/object/person/84a86c4a-…`, and the empty row appeared in the table
  before a single field was typed. Consequence for the brief's invariant: a row that parks after
  its Create click leaves an empty person behind. This is worth a product ticket of its own; it is
  not the failure this golden hit.
- The People table renders reliably only after roughly 20–25 s in a cold browser
  (`domcontentloaded` + a skeleton); the app's own metadata query is what fills it.
- The record panel's Fields widget carries `data-testid="record-fields-widget"`, with rows for
  Emails / Phones / Company / Job Title. In my probes, clicking the Emails row (by text, by the
  value cell, and by element box) never opened an editor — no input appeared. That is the
  harness gap at the heart of the demonstration: Twenty's field editors are not reachable with
  the locators I tried.
- Twenty's first/last name inputs expose zero-width non-joiners in their placeholders
  (`"F\u200c\u200cirst name"`), so a selector must match by substring, not equality.

## What the commit step would have been (the ticket's question)

Not observed, because no demonstration completed. From the code, the popup preselects **the last
recorded click** as the commit (`defaultCommitStepId` in `apps/extension/src/popup/make-recipe.ts`).
On Twenty a demonstration with no Save button would therefore mark whichever click ended the
person's work in the record panel — the Company option click, or the click that closed the panel —
and the compiler would then require an `assert_after` for it. Whether an autosaving app gives that
click any usable evidence is exactly what a working golden would have answered; this run did not
get far enough to read it.

## Smallest next steps for whoever picks this up

1. Record the demonstration manually once (popup's Recorder, not a script) on
   `http://localhost:3000/objects/people`, and export the recording. That answers two open
   questions at once: which click the session marks as the commit, and what evidence Twenty's
   autosave leaves on it.
2. Replace `_search_for` with whatever control the export shows the person used (the command menu
   is reachable via Ctrl+K, but its input has no stable placeholder in this build).
3. Make `twenty_page` land on `/objects/people` before `bind_extension_to` runs — the current
   fixture follows whatever route login/onboarding ended on. That is the run-2 failure and is a
   one-line fixture change (outside this ticket's file list, which is why it is named here rather
   than made).
4. Open a product ticket for the empty person created by "+ Create" when a demonstration parks
   before its first field: the brief's "never a second one for the same person" does not cover an
   abandoned draft.
