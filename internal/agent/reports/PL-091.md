## Summary

A text PDF of invoices now reads into columns and rows through the same path a Word document
takes: preview, notes, CSV download, batch, mapping and run. `read_pdf` uses pdfplumber's word
positions to find `Label: value` lines and column-aligned tables, and refuses a scan, a letter or
a non-PDF in one sentence. Both upload routes accept `.pdf`; a PDF batch is stored the way a
`.docx` batch is. The two file pickers accept `.pdf`.

The committed tests, fixtures and `fixtures/documents/make_pdf_fixtures.py` were not changed.

## PDF layout the reader cannot handle

These follow from the ticket's own rules; none is exercised by the fixtures.

- **A colon inside a data cell.** Any line containing a colon is a label line, so a table row like
  `12:30` or `Widget: Pro` ends the table and is read as a field instead.
- **A footer that lines up with the columns.** A line below a table that starts at or right of the
  first column's left edge, with no label line between, is read as one more table row. The
  fixture escapes this because `Total:` sits between the table and the footer.
- **A wrapped cell.** A product name that wraps onto a second visual line becomes a row of its
  own rather than joining the row above.
- **One visual line, two baselines.** Words whose tops differ by more than 2 pt (a superscript, a
  smaller unit beside a number) split into separate lines.
- **Text left of the first column.** A continuation line indented past the first column's left
  edge does not fall under the columns, so it ends the table.
- **Two tables with no label between them.** The second table's header line is read as a data row
  of the first.
- **Scans and text drawn as curves.** Refused with `NO_PDF_TEXT`; OCR is out of scope.
- **A password-protected PDF.** Refused with `NOT_A_PDF`'s sentence unless pdfplumber opens it
  without a password; no password is ever guessed or prompted for.
