# PL-007: Chrome Extension Recorder (Phase 2)

## Description
Build the browser recorder inside `apps/extension/` to capture user demonstrations as semantic fingerprints rather than raw coordinate clicks.

## Scope
1. Manifest V3 Chrome Extension structure under `apps/extension/`:
   - `manifest.json`: permissions (`activeTab`, `storage`, `debugger`, `webNavigation`), background service worker, content scripts, and side panel/popup UI.
2. Content Script semantic recorder:
   - Captures user interactions: `click`, `fill`/input, `change`/select, and form submits.
   - Computes semantic target bundle matching `packages/recipe/schema/recipe.schema.json`:
     - Rung 1: Role + accessible name + enclosing container (`within` form/dialog/section).
     - Rung 2: `data-testid` / `data-test` attributes.
     - Rung 3: Label association (`<label for="...">` or wrapping `<label>`).
     - Rung 4: Stable CSS selector (excluding dynamic class hashes).
     - Rung 5: Fuzzy text.
   - Security rule: Password fields (`input[type="password"]`) MUST be masked/ignored and never captured.
3. Extension background service worker & messaging:
   - Streams captured actions as typed JSON events over WebSocket or stores them in local session history.
   - Start / Stop / Clear recording state controls.

## Acceptance Criteria
- Extension builds and loads cleanly as an unpacked extension in Chrome.
- User typing, clicking, and selecting in standard web forms generates ordered semantic event objects matching recipe step schemas.
- Password inputs are strictly omitted from payloads.
- Report written to `internal/agent/reports/PL-007.md`.
