# PL-116: wait while a button is busy; no add-twice line on sign-in tasks

Owner: T2 (DeepSeek) · Branch `pl-116` (from `main` at cfed3c4) · Reviewer: T1

## Why

Owner's Goodlabs sign-in run on 2026-10-27 parked in about a second: `Couldn't click "Continue":
the button was busy.` After the email is typed, Goodlabs checks it and shows a spinner on Continue
for a moment, with the button disabled / `pointer-events: none`. A person never sees this because the
spinner is gone before they click. The runner gives up at the first look.

Cause: `resolveStepTarget` in `apps/extension/src/executor/step-runner.ts` (~line 441) retries a
failed `measureTarget` only when the message says "no longer in the document". The busy refusal from
`ladder.ts` (`the target is busy (disabled | busy | not taking clicks)`) returns at once. The same
failure read "covered" before PL-113 S3.

## Change

1. **Busy is waited on, inside the existing ready wait.** In `resolveStepTarget`, a `measureTarget`
   refusal that starts with `the target is busy` is retried every `READY_WAIT_POLL_MS` until
   `prepareDeadline`, exactly like the "no longer in the document" case. Only when the deadline
   passes does the step fail with the same busy message as today. No new timeout and no new
   constant. Nothing is pressed while waiting.
2. **The movedOn probe still applies.** If the step carries an assertion and it already holds while
   the button is busy, keep today's PL-107 item 11 / PL-113 B1 behaviour. Do not change the runner's
   commit path.
3. **Sign-in tasks show no key line.** In `apps/web/src/panel/PanelTeach.tsx` (~lines 500 and 515),
   the "We'll use <key> so nothing gets added twice" line, its **Change** button and the "We use it
   so nothing gets added twice" note are not shown when the recording is a sign-in
   (`status.signIn === true`). Nothing else on that screen changes, and what is sent on save does
   not change.

## Tests (write first, failing, then fix)

- Extension: a click target that reports busy (disabled, then enabled after ~300 ms) prepares OK and
  is clicked once. A target that stays busy past the ready wait fails with the busy message, and no
  click was sent. Use fake timers or a stub CDP like the existing step-runner tests.
- Web: a sign-in recording's save screen has no "added twice" text. A non-sign-in recording still
  has it.

## Stay out of

`services/`, `packages/`, the schema, and the runner. `ladder.ts` only if a test proves it's needed.
