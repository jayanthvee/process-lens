# PL-120: Remove a task from the list

Owner: T2 (DeepSeek) · Branch `pl-120` (from `main` at 04e6ddc) · Reviewer: T1
Read `internal/docs/WORKING-RULES.md` first. The owner asked for this ticket directly, so the scope
freeze doesn't apply to it.

## Why

The owner has 34 saved tasks: test runs, smoke tests and retries. The Tasks list in the panel and in
the web app is too long to find the one task that matters. The app has no way to remove a task: the
API has no delete or hide, and every task is linked to its runs.

## Change

1. **Removed, not deleted.**
   - Migration `0013_task_removed.sql` adds `workflows.removed_at timestamptz NULL`.
   - Removing a task sets it. Nothing else is deleted or changed: its recipe versions, runs, records, `committed_keys` and step events stay.
   - Don't touch `guard_record_transition()`.
2. **API.**
   - `POST /api/v1/tasks/{workflow_id}/remove` sets `removed_at` and returns 200.
   - The same call on a removed task is a no-op 200. An unknown id is 404.
   - A task with a run that is `queued`, `running` or `paused` is refused with 409, and the detail says "Stop its run first."
   - `POST /api/v1/tasks/{workflow_id}/restore` clears `removed_at`, so nothing is lost by mistake.
   - Every task list skips removed tasks: `list_tasks`, Home, the panel and the web Tasks page.
   - Runs and their details still show past runs of a removed task, under its name.
3. **Panel Tasks tab and web Tasks page.**
   - Each task card gets **Remove**.
   - Pressing it asks on the same card: "Remove "<name>" from the list? Its past runs stay." with **Remove** and **Keep it**.
   - After removal, the card goes away and the panel shows "Removed "<name>". Undo" for about 10 seconds. Undo calls restore.
   - A 409 shows its sentence on the card.

## Tests (write first, failing, then fix)

- API: remove hides a task from `GET` lists and from Home. Its runs still list. Restore brings it back. Removing a task with a paused run gets 409 with the sentence. An unknown id gets 404. A second remove is a no-op.
- Migration: applies on the current schema, and existing tasks have `removed_at` null.
- Web and panel: Remove asks first, and Keep it does nothing. Remove then calls the endpoint and the card goes away. Undo restores it. The 409 sentence shows on the card.
