# PL-099: Invoices from a real spreadsheet

Owner: T1 · Branch `pl-099` (from `main`)

## Why

The pilot's messy invoice file on Render (2026-10-24), and a local rerun of it, showed:

- **"$109.00" never saved.** Odoo's invoice-line price refuses a currency sign, so the save did nothing and the row parked. (Product prices happen to accept "$92".)
- **A product picked by name alone never matched.** Odoo lists products as `[CODE] Name`; a spreadsheet holds the name. The option rung (`{{row.product_2}}`) only matched exactly, and the fuzzy rung needs 60% of the text. Before PL-096 the recorded css rung clicked the first option, which only worked by luck.
- **A row stuck in "filling" for 10 minutes on Render, and "the extension disconnected" locally.** A test-harness fault, not the product: when a save fails Odoo asks "leave this page?", the abandon guard accepts it, Playwright dismisses it too, and the losing call crashes Playwright's driver and the whole test browser with it. A person's Chrome has no Playwright.
- **"Two extra empty lines" on each invoice** are Odoo's own payment-term and tax lines. Not a bug.
- "isn't in the Product 2 list" named the recorder's internal column.

## Change

- `packages/documents/kinds.py`: the field kinds from PL-095 move here, plus `plain_number` and `as_typed`. A column taught with a number types the number as a number field takes it: `$1,299.00` is `1299.00`. A value that is not a number ("free", "€79,50") is left exactly as written; the check flags it.
- `services/api/batches.py`: the check shows, and judges, the typed values.
- `services/runner/creation.py`: a run's values are the typed values, written to `clean` for the runner with or without a saved mapping.
- `apps/extension/src/executor/ladder.ts`: an option rung also matches an option named `[CODE] <name>`. The whole name must match: "Desk Lamp" never picks "Desk Lamp Pro".
- `services/runner/step_words.py`: a numbered recorder column is named as its field ("the Product list").
- `tests/e2e/conftest.py`: every test browser answers dialogs itself and tolerates one the extension answered first.

## Proof

- Unit and API tests for each change.
- The messy invoice file locally, with product names only: 7 invoices saved with the right product, quantity and price (109.0, 1299.0, 0.0, quantity 2.5); Acme, "Desk Lamp" and the empty price stop with plain reasons; no hang and no browser crash.
