# PL-097: A row that stops on a step says why in plain words

Owner: T2 (DeepSeek) · Branch `pl-097` (from `main`) · Reviewer: T1

## Why

The pilot's messy lead file on Render (2026-10-24) stopped rows with the extension's own diagnosis as the reason the person reads on the run page:

- a salesperson the list does not have: `the click target could not be resolved: the target is not clickable: the box center is covered by <div>`
- a row with no salesperson: `the fill step fill-6 resolved to an empty value; an empty fill is refused rather than submitted`
- a name with a line break: `the fill did not stick: the recipe typed "Kai Line\r\nBreak" but the field holds "Kai Line\nBreak"`

The tester (non-technical, on GoHighLevel) cannot act on these. `services/runner/check_words.py` (PL-047) already does this for a save's failed check; this is the same for a step that did not finish.

## Change

1. New module `services/runner/step_words.py`, in `check_words.py`'s style (pure, no database, no browser):

   `describe_step_failure(step, row, variables, error: str | None) -> str`

   | Situation | Sentence |
   |---|---|
   | a click on an option (`role: option` rung) templated from a row column, failed to resolve or not clickable | `“Priya Ramen” isn't in the Salesperson list` |
   | a fill whose value rendered empty | `No salesperson in this row` |
   | a fill that did not stick | `The page changed the name as it was typed; check the row's name` |
   | any other click that was covered / not clickable | `Couldn't click “Save manually”: something was in front of it` |
   | any other target not found (`no rung matched`, `could not be resolved`) | `Couldn't find “Save manually” on the page` |
   | anything else | `Step “Click Save manually” didn't finish: <error>`, at most 160 characters |
   | no error | `Step “Click Save manually” didn't finish` |

   - **Field name for an option:** the step that typed into that list is the nearest earlier fill of the same column; that is not available here, so use the column's label: `salesperson` → `Salesperson` (as `batches._label`).
   - **Column for a fill:** `step["value"]["column"]`, label lower-cased in the middle of a sentence.
   - **Element name:** the first `role` rung's `name`, else the step's `name` without its leading `Click `/`Fill `.
   - Render templates with `services.runner.templates.render`; a template that does not render stays literal (as `check_words._text`).

2. Wire it in `services/runner/run_loop.py`:
   - `_simple_step`: the record's **reason** becomes `describe_step_failure(...)`. The step event keeps the raw `error=result.error` unchanged.
   - `_commit_step`, when `prepared.status != "ok"` (the target could not be resolved before the save): same.
   - Do not touch the refused (`status == "refused"`) path; guard refusals already have their own words.

## Tests

`tests/runner/test_step_words.py` (written by T1; fails now on the missing module). Do not change these tests.

Add a run-loop test with `services/runner/testing.py`'s fake executor: a step that fails with the covered-option error leaves the record parked or failed with the plain sentence as `reason`, and the step event still carries the raw error.
