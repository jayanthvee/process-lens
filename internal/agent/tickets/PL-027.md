# PL-027: Teach once, replay for real, on Odoo and Twenty

Owner: T2 (second instance) · Reviewer: T1 · Depends on: PL-022 (the test apps) · Priority: **first**

## Why
This is the product. Today record → compile → replay is proven only on pages we wrote. It must work on real apps.

## Requirements
1. **Golden e2e: Odoo, use case 1.**
   - Record "new CRM lead" in Odoo 18 through the real extension: Name, Email, Phone, Company, Salesperson (a
     many2one autocomplete), Tags, then Save.
   - Compile through the popup.
   - Replay 5 rows: 3 new, 1 already in Odoo (skipped as a duplicate), and 1 with no email (parked).
   - Verify through XML-RPC that each new lead exists exactly once, with every field right.
2. **Golden e2e: Twenty, a new Person.** Name, email, company (a relation picker), job title. Replay 5 rows, and
   verify through Twenty's API.
3. **Fix what breaks** in the recorder, compiler and runner, each with a unit test that reproduces it.
4. **Reset before each test** with `infra/test-apps/reset.py`, so the tests can be re-run.

## Acceptance
- [ ] Both goldens pass three times in a row.
- [ ] Every fix has a unit test, and all gates are green.

## T2 rules for this ticket
- **This ticket's e2e is the deliverable,** so T2 may run *only* the two new goldens
  (`tests/e2e/test_odoo_lead_golden.py` and `tests/e2e/test_twenty_person_golden.py`), one at a time. T1 re-runs
  the full e2e suite in review.
- **Stay off PL-024's files:** `apps/web`, `services/api/batches*` and the batch code in `packages/ledger`. They
  are being built in parallel.
- Scope: `apps/extension`, `packages/compiler`, `services/runner`, `tests/e2e`, and unit tests for each fix.
