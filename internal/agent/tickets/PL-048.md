# PL-048: Find unlabeled fields in a table row by their column header

Owner: T2 (GLM Flash) · Reviewer: T1 · Size: **medium, 3 parts** · Branch `pl-048` (already holds PL-046's
golden) · Worktree `C:\Users\vasup\process-lens\.worktrees\glm` · **Extension only.**

## Why
PL-046 found that an Odoo quotation records and compiles, then parks every row at `click-5` ("Click Search a
product"). The order-line fields sit in an editable table row and have no label. They have only a placeholder (the
product) or nothing (the quantity). So:
- rung 1 (role `combobox`, name "Search a product") matched **0** elements on replay;
- rung 4 (`input.o-autocomplete--input.o_input`) matched **2** (the customer field too);
- the quantity's only rung is `input.o_input`, which matches many.

Quotations, invoices and purchase orders all use these rows, so this blocks three of the brief's use cases. Read
`internal/agent/reports/PL-046.md` first.

## The fix
1. **Explain the 0 first.** Find why the recorded role rung matched nothing on replay. The likely cause is that the
   recorder's `semanticRole` (`src/shared/fingerprint.ts`) and the resolver's `roleOf` (`src/executor/ladder.ts`)
   disagree on Odoo's autocomplete input: it is recorded as `combobox` but read as `textbox` or another role on
   replay. Make the two sides agree, with one test that runs the same element through both. If the cause is
   something else, write down what it was in your report and fix that.
2. **A column-header name.** When a control sits in a table cell (`td`, `role=cell` or `role=gridcell`) and has no
   `aria-labelledby`, `aria-label` or `<label>`, its name is the text of its column header:
   - the `th` (or `role=columnheader`) at the same column position, counting `colspan`, or the matching
     `aria-colindex`;
   - header text trimmed, with sort arrows or icon glyphs left out.

   **Recorder** (`accessibleName` in `fingerprint.ts`): the header name comes before the placeholder, so the product
   field records as role `combobox` (or whatever part 1 settled on), name "Product", and the quantity as name
   "Quantity".

   **Resolver** (`accessibleNameOf` in `ladder.ts`): a role rung's name matches if it equals the element's
   accessible name **or** its column-header name. Recipes already pinned with placeholder names keep resolving.

   Both sides must compute the header the same way. Put the rule in one place if the resolver's self-contained
   (serialized) function allows it; if not, mirror it and add a test that compares the two.
3. **Ties stay a refusal.** Two visible rows that both have an editable "Product" field must still fail as "more than
   one match". Don't pick the first. Odoo renders inputs only in the row being edited, so one match is the normal
   case.
