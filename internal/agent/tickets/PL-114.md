# PL-114: Fields you click, not type, are set to the row's value

Owner: T2 (DeepSeek) · Branch `pl-114` (from `pl-113`; merge `origin/pl-113` first once PL-113 is
done) · Reviewer: T1

## Why

Teaching records most non-typed fields as a fixed click, so every row repeats exactly what was
clicked while teaching and ignores the spreadsheet. On 2026-10-26/27 the owner saw it in Odoo:
Product Type radios (Goods/Service/Combo), "Limit registrations" checkbox, the event date range,
star ratings. Worse, a checkbox click *flips* the box: a row whose box is already ticked gets
unticked.

Rule for the whole ticket: **record the value the field ends with, not the click; replay sets the
field to the row's value.** Every fix is general; nothing may match Odoo's names, classes or URLs.

## Change

For each kind below: the recorder emits one step that names the field and its final value (so it
can be bound to a column like any fill), and the executor sets that value idempotently (setting a
field to the value it already holds does nothing and passes). If a column is not bound, the taught
value is used for every row (today's behaviour, minus the flip).

1. **Checkbox / switch** (`input[type=checkbox]`, `role=checkbox|switch`): step `check` with
   `checked: true|false`. A column binds with yes/no, true/false, 1/0, x/blank, ✓ (case-insensitive);
   anything else parks the row: "‘<value>’ isn't a yes or no for <field>."
2. **Radio group** (`input[type=radio]`, `role=radio`, `role=radiogroup`): step `select` on the group,
   value = the chosen option's label. Replay clicks the option whose label matches the row's value
   (same matching as `<select>`: exact, then case/space-insensitive); no match parks with the options
   listed.
3. **Click-only date / time pickers** (a calendar grid: `role=grid` of day cells, or a popup opened
   from a read-only input): record a `fill` of the date the field shows afterwards, not the day
   click. Replay: if the input accepts typing, type it in the field's own format (read the format
   from the value it showed while teaching); otherwise open the picker, move month/year with its
   next/previous controls to the target, click the day; then read the field back and check it.
   Date ranges are two such fills. Dates in the file are read as ISO, `M/D/YYYY`, `D Mon YYYY`;
   ambiguous ones (`03/04/2026` when the field's format differs) park, never guess.
4. **Tags / chips / many-to-many** (a pick box that keeps several values as chips): a cell like
   "VIP, Partner" is split on commas/semicolons and each value picked (PL-110 pick per value).
   Chips already there that are not in the cell are left alone (no removals in this ticket).
5. **Star rating / +− steppers / sliders** (`role=slider`, `input[type=range]`, a row of 3–10 same
   buttons/stars, a number with +/− buttons): record the final number. Replay sets it (click the
   Nth star; press +/− until the number shows the value; set the range value with input/change).
   Check the field shows it after.
6. **Status bar / stage buttons** (`role=radiogroup` or a row of `aria-checked`/`aria-current`
   buttons, like Odoo's New → Booked): treat as a radio group (item 2).
7. **File upload**: confirm whether teaching records an upload today (`recorder.ts` skips
   `type=file`). If not, record `upload_file` with the file's column (the row names a file from the
   run's attached documents), never the file's contents or local path. Report what you found.

Not handled (say so in the panel instead of recording a wrong step): drag and drop, colour pickers,
signature pads. Teaching shows "ProcessLens can't repeat dragging yet; do this step by hand." on the
step line, and the step is not saved.

## Panel wording

Lines read in plain words with the value: "Ticked Limit registrations", "Chose Goods for Product
type", "Set the date to 5 Nov 2026", "Picked tags VIP, Partner", "Set the rating to 3 stars".

## Tests (write first, failing, then fix)

Per kind, a recorder test (the final value is recorded, one step, no flip/day click) and an executor
test with a real DOM (sets the row's value; already-set is a no-op that passes; a bad value parks with
the sentence). Use two different markups per kind, so a fix can't match one site. Include: a
checkbox already ticked + row "yes" stays ticked; a calendar two months ahead; a 12/31 vs 31/12 park.
