# PL-101: A record key picked from a list is warned about before it skips real work

Owner: T2 (DeepSeek) · Branch `pl-101` (from `main`) · Reviewer: T1

## Why

ProcessLens does each record key once, for good (`committed_keys`, permanent per destination). A key the person picks from a list (a customer, a salesperson) is shared by many rows by its nature. Keyed on the customer, every customer's second invoice is "already done", in this run and every later one, and the row is skipped without anyone noticing. The pilot checklist had to warn about this by hand.

The compiler already knows which columns feed a list: a column templated into a `role: option` rung, and the column typed into the field right before that option was clicked (the search text).

## Change

1. **Compiler** (`packages/compiler/compiler.py`):
   - `CompileResult.key_warning: str | None`, default `None`.
   - Set it when the record key's column (`CompileOptions.record_key_column`, or the first `{{row.<column>}}` in `record_key`) is one that feeds a list, as above.
   - Sentence, using the column's label with a trailing `_<number>` removed (`salesperson_2` → `Salesperson`):
     `Salesperson is picked from a list, so many rows can share it. ProcessLens does each key once, ever: a later row with the same salesperson would be skipped. Pick a column that is different on every row, like an email or a reference.`
   - Also append the same sentence to `warnings`.
2. **API** (`services/api/compile.py`): return `key_warning` in the compile response, `null` when there is none. Add an API test.
3. **Popup** (Make recipe form): when the compile result has a `key_warning`, show it above the result in the popup's warning style, with a **Change the key** button right there that takes the person back to the key picker. Saving anyway stays possible. Add a popup test.

## Tests

- The batch check (it already flags repeats inside one file).
