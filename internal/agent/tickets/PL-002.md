# PL-002: Scaffold, migrations, database tests, CI, secret scanning

Owner: T2 DeepSeek · Critical: no · Depends on: none · Phase: 0

## Goal
A fresh clone runs `make up && make migrate && make test` successfully, and CI runs the same safely on a
public repository.

## Read first
- internal/AGENTS.md (repository map, public repository rules)
- internal/docs/sql-patterns.md
- db/migrations/0001_init.sql, db/tests/ledger_guard_test.sql

## Scope
- Root: Makefile, docker-compose.yml, pyproject.toml, .pre-commit-config.yaml, .gitleaks.toml
- README.md: only the "Getting started" section
- .gitignore: append lines only, never remove existing ones
- Folder skeleton from the internal/AGENTS.md repository map (empty folders get a `.gitkeep`)
- db/ (new files only; existing migration content must not change)
- services/api/
- tests/db/
- .github/workflows/
- internal/agent/reports/PL-002.md

## Out of scope
- Everything in internal/ except your report. AGENTS.md and CLAUDE.md pointer files. apps/ contents. Any business logic.

## Requirements
1. docker-compose.yml: Postgres 16 with a healthcheck, MinIO, named volumes, ports and credentials from `.env`.
2. Makefile targets: `up`, `down`, `migrate`, `test`, `lint`, `fmt`.
3. Migration runner (Python, psycopg 3): applies `db/migrations/*.sql` in filename order, each in its own
   transaction; records filename and sha256 in `schema_migrations`; re-running is a no-op; refuses to run,
   with a clear error, if an already-applied file's hash has changed.
4. Convert `db/tests/ledger_guard_test.sql` to pytest in `tests/db/` against a fresh database per session:
   every legal operation succeeds; every illegal one raises with the expected message; attempts cap at 3;
   `ON CONFLICT DO NOTHING` inserts 0 rows; `run_summary` counts are correct.
5. Race test: two connections run the claim query from `internal/docs/sql-patterns.md` concurrently over 50 pending
   records; assert every record is claimed exactly once.
6. `services/api`: FastAPI app with `GET /health` returning `{"status": "ok", "db": true|false}`.
7. CI workflow: triggers on `push` and `pull_request` only (never `pull_request_target`);
   top-level `permissions: contents: read`; Postgres 16 service container; runs lint and tests; uses no secrets.
8. gitleaks in pre-commit and as a CI job.
9. README "Getting started": prerequisites and the exact commands to run everything locally. Professional tone;
   no mention of internal docs, tickets, or AI tools.
10. Git: branch `pl-002`, push it, open a draft pull request titled
    "Project scaffold: local services, migrations, database tests, CI". Commit the report with `git -C internal`.

## Acceptance criteria
- [ ] From a clean clone: `cp .env.example .env && make up && make migrate && make test` passes. Paste output.
- [ ] Second `make migrate` reports nothing to apply.
- [ ] Changing one character in 0001_init.sql after applying makes `make migrate` fail with a clear message
      (then revert it).
- [ ] Race test passes 10 times in a row.
- [ ] CI is green on the pushed branch.
- [ ] gitleaks passes.
- [ ] No file outside Scope changed (`git diff --stat main...pl-002` in the report).
- [ ] `git ls-files` lists nothing from internal/, private/, AGENTS.md, CLAUDE.md, or .env.
- [ ] Draft pull request is open; its title and body read professionally.
