# PL-050: The demo refuses to start a second copy

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Size: **small, 1 part** · Branch `pl-050` · Worktree
`C:\Users\vasup\process-lens\.worktrees\deepseek` (after PL-049 is pushed) · **`scripts/demo.py` only.**

## Why
On 2026-10-19 two copies of `scripts/demo.py` ran at once. Both had supervisors watching the same database, so the
second one fought the first, and "Try one row" hung at Queued. Nothing told the owner that a copy was already
running.

## The fix
Before migrations, before anything else, `main()` checks two things and exits with code 1 and one plain line if
either fails:
1. **The port is taken.** Try to bind `127.0.0.1:API_PORT` (8000) with a plain socket and close it at once. If the
   bind fails, print: `ProcessLens is already running on http://127.0.0.1:8000 (or something else is using port
   8000). Close the other copy first: find its terminal and press Ctrl+C.`
2. **Another demo is alive.** Keep a lock file `DATA_DIR / "demo.pid"` holding this process's pid.
   - At start, if the file exists and its pid is alive (`os.kill(pid, 0)` on POSIX; on Windows use
     `psutil` if it's already a dependency, otherwise `ctypes` `OpenProcess`), print the same message with the pid.
   - A file whose pid is dead is stale: overwrite it.
   - Remove the file in the existing `finally` / Ctrl+C cleanup, only if it still holds our pid.

Put both checks in small functions, `port_in_use(port) -> bool` and `other_demo_pid(path) -> int | None`, so they can
be tested without starting anything.

## Tests first (pytest, in `tests/demo/test_demo.py`, red before the fix)
- **The port check:** `port_in_use` is true while a test socket holds a free port, and false after it closes.
- **The pid file:** `other_demo_pid` returns the pid for a file holding the test's own pid (alive), and `None` for a
  missing file, a dead pid, or a file with garbage in it.
- **The refusal:** `main([])` with `port_in_use` patched to true returns 1, prints the message, and never calls
  `apply_migrations` (patch it and assert it wasn't called).
- **Cleanup:** the pid file is removed on exit only when it holds our pid.
