# PL-028: Remember each column's example from teaching, so the spreadsheet check can match by value

Owner: T2 (Kimi) · Reviewer: T1 · Size: small

## Why
The PL-024 check can match a spreadsheet column to a task column by value. "Row 1 holds the same email the task
was taught with" is the strongest clue there is. But the web app never has the taught values, so today matching is
by name only.

## Do exactly this
1. **`packages/recipe/schema/recipe.schema.json`, `$defs.input_field`:** add an optional `"example"`: a string,
   `maxLength` 200, described as "The value this column held when the task was taught; used only to match
   spreadsheet columns." Nothing else in the schema changes.
2. **`packages/compiler/compiler.py`:** where `input_schema` fields are built from `options.sample_row`, set
   `example` to the column's sample value, as a string cut to 200 characters. Leave it out when the value is
   empty or `None`.
3. **`services/api/batches.py`, the `/check` route:** when no `sample_row` is passed, build one from the recipe's
   `meta.input_schema.fields[*].example`. The existing value match then works unchanged.

## Tests (write them first; done means they pass)
- **Compiler:** a recording whose `sample_row` has `{"email": "a@b.test", "note": ""}` gives `example` on
  `email` and none on `note`. A value over 200 characters is cut to 200.
- **Schema:** a recipe with `example` validates; one with `example: 5` (a number) does not.
- **API:** a recipe whose `email` field has `example: "ana@x.test"`, and an upload whose `Contact` column has
  `ana@x.test` in row 1, maps `email → Contact` with confidence `exact` and no `sample_row` passed.

## Files you may touch
The three files above, plus `packages/compiler/tests/` and `tests/api/test_batches_api.py`. Nothing else.

## Gates
`python -m pytest -q --ignore=tests/e2e`, `ruff check .` and `ruff format --check .`.
