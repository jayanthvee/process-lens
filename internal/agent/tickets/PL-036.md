## Part 1: the API (`GET /api/v1/spreadsheets`)
- **A new read, `list_spreadsheets(conn, *, tenant_id)`,** in `packages/ledger/reads.py`. It returns one row per
  `input_batches` row whose `kind` is `csv`, `xlsx` or `manual` (never `documents`), newest first, with:
  - `id`;
  - `file_name` (`files.original_name`, or "Pasted rows" when there's no file);
  - `task_id` and `task_name` (the workflow; use the same naming as `_LIST_TASKS`);
  - `row_count`;
  - `uploaded_at` (`input_batches.created_at`);
  - `uploaded_by` (`users.name`, or null);
  - `runs`: the number of runs whose `input_batch_id` is this batch;
  - `last_run_id`: the newest of those runs, or null.
- **A new route file, `services/api/spreadsheets.py`,** mounted in `main.py`, with the same `tenant_id` query
  parameter as `/apps`. The response keys are exactly the ones above. **No row contents**: never `raw`, and never
  anything from `input_records`.
- **Tests first,** in `tests/api/test_spreadsheets_api.py`, copying `test_apps_api.py`'s fixtures:
  - newest first;
  - another tenant's batches never appear;
  - "Pasted rows" when there's no file;
  - the run count and the newest run are right;
  - the response keys are asserted exactly.
- **Commit and push.**
