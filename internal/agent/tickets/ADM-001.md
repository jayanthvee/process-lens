## Who it is for, and what it is for
One or two people run ProcessLens for the company: an ops lead, IT, or the owner. They are more technical than
the people teaching tasks, but not developers. The admin panel answers three questions:

1. **Is anything wrong right now?**
   - Stuck runs.
   - A pile of rows that need help.
   - A task that keeps failing.
   - People on an old Chrome extension.

   And they can stop everything with one button.
2. **Who can do what?** People, their roles, turning someone's access off, and which extension version each
   person runs.
3. **What is it costing, and what is it saving?** AI spend, rows done, and time saved across the company.

The admin panel **never shows row contents**: no spreadsheet values, no document text, no screenshots. It shows
counts, task names, people and reasons only.

## Modular by design (D-025)
Every admin feature is a **module**, so a later feature that needs a migration slots in without touching the
others.

- **A module is two folders and one manifest:**
  - `api/modules/<id>/`: a FastAPI router, its queries, and `manifest.py`;
  - `web/src/modules/<id>/`: its pages, and `manifest.ts`.
- **The manifest declares:**
  - `id`, its title and its sidebar entries (label, icon, path, order);
  - `requires`: the `admin_modules` row it needs (for example `core`), or nothing;
  - `writes`: the tables and columns it writes, documentation checked by a test against the role's grants.
- **A registry** (`api/registry.py`, `web/src/registry.ts`) loads every manifest.
  - At API start-up it reads `admin_modules` from the database.
  - A module whose required row is missing is **not mounted**. Its sidebar entry shows "Needs a ProcessLens
    update" and its page explains that in one sentence. The panel never crashes on an older schema.
  - `GET /api/modules` tells the web app which modules are on.
- **The shell knows nothing about any module.** The sidebar, routes and Overview "needs a look" items all come
  from the registry. Each module may contribute Overview items through a `needs_a_look()` hook.
- **A new module that needs schema** is always a pair of tickets (`ADMIN-MODULES.md`):
  - a PL ticket: the migration in `process-lens`, its `admin_modules` row, and its grants;
  - an ADM ticket: the module here.
- `scripts/new_module.py <id>` scaffolds both folders and the manifests.

**The modules in this ticket:** `overview`, `people`, `runs`, `tasks`, `ai_spend` and `activity`.
- `people`, `runs`, `overview` (its freeze switch) and `activity` require `core`.
- `tasks` and `ai_spend` require nothing; they only read existing tables.

## The look: the same design language, in dark fog
Follow `DESIGN.md` §1–§3 and §5–§7 exactly: Public Sans, the vocabulary table, panels, rows and motion. The one
difference is that the admin panel is **dark only**, so an admin always knows which app they are in.

- **The approved mock** is `internal/docs/design/admin-mock.html` in `process-lens`. Port its tokens and
  structure. Ignore its AI budget bar: budgets were cut.
- **Tokens:** the same names as the main app's `tokens.css`, with the dark values from the mock:
  - fog `#121614` / `#191d1b` / `#232825`;
  - glass is white at 4–8%;
  - ink `#e7eae7`;
  - gold stays the one accent;
  - state colors `--ok`, `--help` and `--live`, plus **`--stop`**, used for "Pause everything" only.
- **"Pause everything"** is the only red thing on any screen. It is an outlined button, and always asks for
  confirmation in the page.

## Requirements
1. **The repository.**
   - Layout:
     - `web/`: React 18, React Router, TypeScript and Vite. Plain CSS, `@fontsource/public-sans`. No Tailwind,
       no component library.
     - `api/`: Python 3.12, FastAPI, psycopg 3.
     - `scripts/`.
     - `AGENTS.md`: the `process-lens` constitution, adapted. Same git rules and attribution ban; D-017 does not
       apply; the database and module rules here are added.
     - `README.md`, `.env.example` and `.gitignore`.
   - Pin every dependency to an exact version.
   - The gates are `npm --prefix web run check` (typecheck, test, build), `python -m pytest -q`, and
     `ruff check .` plus `ruff format --check .`.
2. **The database rules** (mandatory: D-023 and PL-026).
   - Connect with `ADMIN_DATABASE_URL`, a login in the `processlens_admin` role. **Never run migrations**, and
     there is no `db/` folder in this repo.
   - SQL writes go only to:
     - `admin_audit`;
     - `users.role` and `users.deactivated_at`.
   - **Everything that affects runs, or the minimum extension version, goes through the ProcessLens API**
     (`PROCESSLENS_API_URL`, with the `PROCESSLENS_ADMIN_TOKEN` header): pause, cancel, freeze, unfreeze, and
     setting the minimum version.
   - Every admin action writes one `admin_audit` row, with its `module`. A direct SQL write and its audit row go
     in one transaction.
   - Every query filters by the signed-in admin's `tenant_id` (SaaS-ready, D-024). Follow
     `../process-lens/internal/docs/sql-patterns.md`.
3. **Sign-in, behind one interface** (`api/auth.py`: `current_admin() -> Admin`).
   - Now: a local dev provider. It reads `ADMIN_DEV_EMAIL`, looks the user up, and refuses anyone whose role is
     not `owner` or who is deactivated.
   - The API binds to `127.0.0.1` only.
   - SSO replaces the provider in the Railway ticket, with no module changes.
4. **The shell.**
   - The sidebar, 216 px, frosted dark, built from the registry. At the bottom: Settings ("Coming soon") and
     "Back to ProcessLens".
   - The header: page title, then the company name and the avatar.
   - **When runs are frozen**, a full-width bar shows on every page: "All runs are paused. Paused by Jay at
     14:02." with **Let runs start again**.
5. **`overview`** (`/`), as in the mock.
   - **Headline:** "All quiet." / "2 runs going. Nothing needs you." / "2 runs going. 1 thing needs a look."
   - **Pause everything,** with the confirmation from the mock.
   - **Three figures** in one strip:
     - rows done this week;
     - **time saved this week** (the gold figure, the same formula as PL-023: finished runs only);
     - AI spend this month (a plain dollar figure, no budget).
   - **Needs a look:** the items every mounted module contributes, each with one action.
     - `runs`: a run whose heartbeat is more than 2 minutes old ("Stopped responding"); a run with 10 or more rows
       needing help.
     - `tasks`: a task whose last 3 runs ended with more rows not working than done ("Keeps failing").
     - `people`: people below the minimum extension version ("3 people need to update the Chrome extension"); a
       deactivated person with an open run.
   - **Running now:** person, task, live progress (poll every 5 s), and **Pause**.
6. **`people`** (`/people`).
   - The table:
     - name and email;
     - role;
     - **Chrome extension version**, with "Out of date" in `--help` when it is below the minimum, and "Not seen
       yet" when there is no report;
     - last active;
     - one action.
   - Change a role with a select that has one plain line per role:
     - Owner: everything, including this panel;
     - Builder: teaches and runs tasks;
     - Reviewer: fixes rows that need help, and approves;
     - Viewer: can look, can't change anything.
   - **Turn off access** / **Turn access back on**, with a confirmation. An owner can't demote or turn off
     themselves, or the last owner.
   - **"Minimum extension version"**, a small form above the table. It shows how many people it would block
     before saving.
   - Show "People join by signing in with your company account" instead of an invite button.
7. **`runs`** (`/runs`): every run across the company.
   - The columns: task, person, started, status, "11 of 20 done", and **Pause** or **Cancel** where allowed.
   - Two filters: person and status.
   - Clicking a run opens the main app's run page in a new tab.
8. **`tasks`** (`/tasks`), read-only.
   - The columns: task, who taught it, the apps it uses, runs in the last 30 days, and the share of rows done.
9. **`ai_spend`** (`/ai`).
   - The month's total.
   - A per-day bar chart in `--gold`, drawn to scale, with an axis.
   - "Where it went": a table by feature, in plain names, with calls, spend and share:
     - `normalize_fields` → **Cleaning spreadsheet values**;
     - `extract_document` → **Reading documents**;
     - `propose_repair` → **Fixing broken steps**;
     - anything else → **Other**.
   - The model name shows only in a hover title. The source is `ai_calls`.
10. **`activity`** (`/activity`).
    - One list, newest first, paged by 50, merging:
      - `admin_audit`;
      - `approvals`;
      - runs started and finished;
      - re-queues.
    - Each line is a plain sentence, a person and a time.
    - Filter by person.
    - **Export CSV** (filtered rows; no row contents).
11. **No engine words** on screen: the same forbidden-word vitest as PL-023 requirement 7, over every module's
    pages.
12. **Motion and accessibility** as in DESIGN.md §7: visible focus on dark, usable at 400 px wide.
