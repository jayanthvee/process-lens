# PL-087: A run goes to the Chrome of the person who started it

Owner: T1 · Branch `pl-087` (from `main`)

## Why

The hosted supervisor ran one worker for the newest attached Chrome, and that worker claimed any
queued run. With two testers connected, one person's run could drive the other person's Chrome,
and every run waited behind the single worker.

## Scope

1. **Browser id.** Each extension install keeps a random id in `chrome.storage.local` and sends it
   with `POST /executor/sessions`. The hub keeps it per session.
2. **The dashboard learns it.**
   - The content script answers `processlens:which-browser` from the page, only in the top frame
     and only on the ProcessLens address the extension last connected to.
   - The dashboard sends the id as `browser_id` when it creates a run, and asks
     `GET /executor/session?browser=` so "Chrome connected" means its own Chrome.
3. **The run keeps it.** `runs.browser_id` (migration 0011, with a shape check).
   - A worker started with `--browser` claims or takes over only that browser's runs and unbound
     ones.
   - A worker without `--browser` claims as before.
4. **One worker per Chrome.**
   - `GET /executor/sessions/attached` lists every attached session with its browser.
   - The supervisor keeps one worker per attached session (`sessions_to_start`), and stops a
     worker whose session left.

The id is a routing label, not a credential.
