# PL-077: a search that finds the record to change is not a duplicate check

Owner: T2 (DeepSeek) · Reviewer: T1 · Branch `pl-077` (built on `pl-063`)
Time box: 90 minutes

## Why

PL-017 proposes a "skip if the search finds it" branch whenever a recording searches for the
record key before saving. That's right for **creating** records: a lead that already exists is
skipped. It's wrong for **updating** them. In PL-063's price golden, the person searches for the
product's SKU, opens the one it finds, changes the price and saves. With the branch on, every row
would end `skipped`, because the product the search finds is exactly the one to change. The golden
only works today because it unticks the popup's checkbox.

For an update, the opposite rule holds. If the search finds **nothing**, the row has nothing to
change: it must be parked with a plain reason, not carry on and type into whatever page it's on.

## Scope

1. **Tell the two shapes apart** (`packages/compiler/compiler.py`, near the `search` detection
   and `_duplicate_branch`).
   - **Find-then-update:** after the search step, the recording opens a found result (a click on
     a result row or link that navigates to a record page), and the commit happens on that page.
   - **Create:** anything else, which keeps today's behaviour.

   Decide from the recorded steps and their URLs only, never from app names. Write down the
   exact rule in the code's docstring.
2. **Find-then-update gets a not-found branch, not a skip branch.** Right after the search's
   results settle and before the click that opens a result, add the branch: if no result
   matches the row's key, end the record `parked` with the reason "No record matched {{row.<key
   column>}}, so there was nothing to change." Reuse `_duplicate_branch`'s machinery and the same
   `if` and condition shapes the schema already has. Don't add new schema keys. A recipe's
   `end_record` can't set `failed` (D-017); `parked` is right.
3. **The popup** (`apps/extension/src/popup/make-recipe.ts`, the PL-017 option). For a
   find-then-update recording, the checkbox reads "Park a row when the search finds nothing" and
   is ticked by default. For a create, it stays as it is. The compiler tells the popup which
   shape it is, through whatever the popup already reads from the compile preview. Add one field
   if needed and document it.
4. **The price golden** (`tests/e2e/test_odoo_product_price_golden.py`): stop unticking the
   checkbox, and assert the popup offers the park wording. The golden stays `xfail` because
   PL-075 is fixing its commit evidence separately. Don't remove the marker. T1 will run it once
   PL-075 is merged.

## Out of scope

- Commit evidence for update-in-place saves (PL-075).
- Any change to how a create recording's duplicate branch works.
