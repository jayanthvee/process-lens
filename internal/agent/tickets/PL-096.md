# PL-096: A suggestion chosen by the row's value never falls back to a fixed position

Owner: T2 (DeepSeek) · Branch `pl-096` (from `main`) · Reviewer: T1

## Why

The pilot's lead task, compiled on Render (2026-10-24), picks the salesperson suggestion with:

```
role option "{{row.salesperson}}"  ->  css "#user_id_0_0_0"  ->  text_fuzzy "{{row.salesperson}}"
```

`#user_id_0_0_0` is the **first** option in the list, whoever it is. A row with a salesperson the list does not have ("Priya Ramen", or someone who does not exist) misses the role rung, so the css rung clicks the first suggestion. The lead would be saved with **someone else** as its salesperson, and verified.

In the pilot the click only failed because the option was covered by a `<div>`. On another CRM, or with a different layout, it would have gone through. This is a wrong-data bug, not a cosmetic one.

## Change

`packages/compiler/parameterize.py`, `parameterize_candidate`:

- When the candidate is a **click whose ladder names an option** (any rung with `role: option`, as `compiler._is_option_click`) and at least one rung was templated from the row (`{{row.` now in its text), drop every rung whose text carries no `{{row.` template: `css`, `testid`, and any other rung that still names the recorded option.
- Add one warning per dropped rung that names it, e.g. `dropped rung css "#user_id_0_0_0": it points at the recorded option, not the row's`.
- An option click with nothing templated ("Search More...") keeps its whole ladder.
- Clicks on anything else (buttons, cells) are unchanged; their fixed rungs still find the right element.

Recipes are immutable, so existing tasks keep their ladder. The tester records fresh, so this covers the pilot.
