# PL-110: Typing into a box that searches as you type

Owner: T2 (DeepSeek) · Branch `pl-110` (from `pl-109`) · Reviewer: T1

## Why

On 2026-10-27 the owner ran an Odoo pipeline (board view) lead task on 7 rows. Two rows saved; five
parked with "The page changed the contact as it was typed; check the row's contact." Odoo's Contact
box is a search-as-you-type picker: while the run types, it searches, re-renders and completes the
text, so the box no longer holds what was typed. The run refused rather than save a wrong contact,
which was right, but the row is lost.

Every CRM has these boxes (contact, company, owner, product). This is not an Odoo fix: nothing may
match Odoo's classes, names or URLs.

## Change

### 1. Know the box is a picker

A field is a picker when it has `role="combobox"`, `aria-autocomplete`, `aria-controls`/`aria-owns`
pointing at a listbox, or when typing into it opened a listbox while teaching (the recording shows a
fill followed by a click on an `option`). Record it as a pick, not a plain fill.

### 2. Replay a pick the way a person does

1. Clear the box, type the row's value at a person's pace (or the whole value, then wait).
2. Wait until the listbox shows options for this value (it settles: same options for ~300 ms), up to
   the step's timeout.
3. Choose, in order: an option whose name equals the value (an existing record); else the
   `Create "<value>"`-style option the recording used (already templated, PL-107 item 16); else
   park with "No match for “<value>” in <field>, and no way to create it."
4. Do not compare the box's text to the typed value after a pick: the picker is allowed to change
   it. Check instead that the chosen option's name is what the box now shows.

### 3. A plain fill keeps today's check

A box that is not a picker keeps the "the page changed it as it was typed" refusal.

## Done when

- Your tests, failing first: a picker whose listbox re-renders mid-typing; one with an existing exact
  match; one with only Create; one with neither (parks with the sentence); a plain field that the
  page rewrites still refuses. Markup not tied to any one product.
- Gates: `python -m pytest -q`, `ruff check .`, `ruff format --check .`,
  `npm --prefix apps/web run check`, `npm --prefix apps/extension run check`. No e2e.
- Report `internal/agent/reports/PL-110.md`.
- Acceptance is the owner's: the same 7-row Odoo board-view run ends with every row Done or Already
  there.
