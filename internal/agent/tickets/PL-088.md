# PL-088: A messy spreadsheet still uploads right

Owner: T2 (DeepSeek) · Reviewer: T1 · Branch `pl-088` (this ticket is on it)
Time box: 90 minutes · No e2e, no browser: this is parsing and its tests.

## Why

Pilot testers bring their own spreadsheets. The upload in `services/api/batches.py` matches
columns well, but it breaks on ordinary files:

- **Excel's default "CSV (Comma delimited)" on Windows** is Windows-1252, not UTF-8, so it is
  refused: "this .csv file is not UTF-8 text" (`_read_csv`, about line 165).
- **A semicolon-separated CSV** (European Excel) becomes one wide column: `csv.reader` uses commas
  only.
- **A title row above the headers** ("Q4 customers" in A1) becomes the header.
- **Two columns with the same name:** `dict(zip(headers, values))` in `_row_from` keeps only the
  last one, while the upload still lists the name twice.
- **Excel cells come through `str()`:** a date gives `2023-11-01 00:00:00`, a whole number gives
  `1.0`.
- **A line of only commas** (`,,,`) is kept as a row of blanks, and counts toward the 2,000 rows.
- **Values are never trimmed,** so `" Acme "` is what the run types.
- **`.xls` and `.tsv` are refused** with a message that doesn't say what to do.

## Scope

All in `services/api/batches.py`, except item 8. `raw` keeps the cells as read. Only the decoding
and the values in `clean` change.

1. **Encoding** (CSV and TSV):
   - try `utf-8-sig`;
   - a UTF-16 BOM (`FF FE` / `FE FF`, which is Excel's "Unicode Text") decodes as UTF-16;
   - otherwise fall back to `cp1252`, then `latin-1`.
   - A file is never refused for its encoding.
2. **Delimiter:**
   - `.tsv` is tab-separated;
   - for `.csv`, sniff the first 4 KB with `csv.Sniffer().sniff(sample, delimiters=",;\t|")`;
   - fall back to comma when sniffing fails or finds nothing.
3. **Blank rows:** drop a CSV or TSV row whose cells are all empty or whitespace, the same rule
   `_read_xlsx` already uses. It does not count toward the row limit.
4. **Title rows:** the header is the first row with at least two non-blank cells. Rows above it with
   at most one non-blank cell are skipped. A sheet whose rows all have one cell keeps today's rule
   (first non-blank row).
5. **Unique headers:**
   - a repeated name gets " 2", " 3", and so on, matching `packages/documents/clean.py`;
   - a generated "Column N" never collides with a real header;
   - every column's value survives;
   - the response's `columns` and the stored rows agree.
6. **Excel values** (`_read_xlsx` only):
   - a `datetime` at midnight gives `YYYY-MM-DD`, and any other time gives `YYYY-MM-DD HH:MM`;
   - a `date` gives `YYYY-MM-DD`; a `time` gives `HH:MM`;
   - a float that is a whole number gives the integer (`1.0` becomes `1`);
   - a bool gives `TRUE` / `FALSE`;
   - everything else gives `str()` as now.
   - Leading zeros Excel already dropped are out of scope.
7. **Trim:** strip leading and trailing whitespace from every value in `clean`.
8. **Formats:**
   - accept `.tsv` (`SUPPORTED_SUFFIXES`, and the web file picker's `accept` and its hint in
     `apps/web/src/pages/TaskRun.tsx`, about lines 342 and 362);
   - refuse `.xls` with: "This is an old Excel file (.xls). In Excel, choose File > Save As > Excel
     Workbook (.xlsx), then add that file."

Out of scope:
- matching (`_rank` and the synonyms);
- the DOCX path;
- the run page's layout.

## Gates

- **Tests first,** in `tests/api/test_batches_api.py`, one per item. Build each file in the test
  itself:
  - a cp1252 CSV with `é` and `£` uploads and keeps them;
  - a UTF-16 tab file;
  - a semicolon CSV gives three columns;
  - a `.tsv` file;
  - `,,,` lines are dropped;
  - a title row is skipped;
  - "Name, Name" gives "Name" and "Name 2", each with its own value;
  - an xlsx with a midnight date, a datetime, `1.0` and `True`;
  - `" Acme "` gives `Acme` in `clean` and stays `" Acme "` in `raw`;
  - `.xls` is refused with the new message.
- Then the full `python -m pytest -q`, `ruff check .`, `ruff format --check .`, and
  `npm --prefix apps/web run check`.
