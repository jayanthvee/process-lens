# ADM-003: Health fixes from review, and a link straight to a stuck run

Repository: **`process-lens-admin`** · Owner: T2 (admin DeepSeek) · Reviewer: T1 · Size: **small, 3 parts** ·
Branch `adm-003`, cut from `origin/adm-002` · No migrations, no writes.

## Why
T1's review of ADM-002 found two gaps in the Health page. ADM-002's own report flagged a third: a red line can only
link to the whole Runs page.

## The fix
1. **"Reachable" means it answered.** `processlens_line` treats any response as reachable. A 5xx (or any
   non-2xx) from `GET /health` is red: "ProcessLens is answering with an error at <url> (status 503)".
2. **A run that never reported is stuck too.** `workers_line` skips runs whose `heartbeat_at` is `NULL`. A `running`
   run with no heartbeat whose `started_at` (check the real column name in
   `../process-lens/db/migrations/0001_init.sql` and later) is older than the same 60 seconds counts as stuck.
3. **Per-run links.** The Runs page gives each row an anchor (`id="run-<id>"`, or a `?run=<id>` that scrolls to and
   highlights the row: pick whichever fits the existing page). The Workers line's links point at that run. Use the
   run's id only, never row contents.

## Tests first (red before the fix)
- **Reachable:** a `MockTransport` answering 503 gives red with the status, and 200 stays green.
- **Stuck without a heartbeat:** a running run with `heartbeat_at NULL` started 2 minutes ago is counted; one started
  10 seconds ago isn't.
- **Links:** the Workers link carries the run id, and the Runs page vitest highlights the linked row.
- **No regression:** the existing 132 API and 64 web tests pass.
