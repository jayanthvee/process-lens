# PL-014b: Harden the real-extension path

Owner: T2 · Reviewer: T1 · Depends on: PL-014 (merged) · Phase: C

## Description
These are the follow-ups from the PL-014 reviews (`internal/agent/reports/PL-014-review.md`). Each one fails safe
today: a record parks or a run pauses, and nothing is duplicated. Together they decide whether a real run on a real
CRM finishes without a person stepping in for every record.

There is no plan step; the items are small and specified here. **There is no new e2e harness work**: the e2e budget
for the whole ticket is one full-suite run at the end.

## Scope
- `services/api/hub.py`, `tests/runner/test_hub.py`
- `services/runner/run_loop.py`, `services/runner/browser_executor.py`, `tests/runner/`
- `apps/extension/src/` (background, executor, shared) and `apps/extension/tests/`
- `tests/e2e/test_disconnect_mid_save.py` (item 9 only)

## Requirements

1. **Hub slot release.** A slot reserved before `accept` is released in a `finally` if `accept` or the first frames
   fail. The previous resume token stays valid until the extension has re-attached with the new one.
2. **Hub session lifetime.**
   - The 10-minute expiry applies only to an unclaimed session.
   - A claimed session expires 10 minutes after both peers have gone, not 10 minutes after creation.
   - Expired sessions are removed.
   - `peer_gone` is announced before the hub awaits the close.
   - `_refuse` selects the offered subprotocol, so Chrome receives the close code.
   - The extension gets `peer_ready` only when both peers are attached.
3. **Hub tests that fail when their check is removed:**
   - a non-loopback client (`TestClient(client=("203.0.113.10", 1))`);
   - the close endpoint without the secret;
   - a wrong secret;
   - an unset `PROCESSLENS_EXTENSION_ID`;
   - Host rebinding on the runner socket and on close;
   - the close codes 4400, 4403 and 4408;
   - an expired session.
4. **Transient evaluate errors.**
   - During a condition poll, "Execution context was destroyed" and "Cannot find context" are retried within the
     poll window.
   - Only persistent errors (detach, a malformed condition, a missing tab) refuse the check.
   - Test: a page that navigates during the `assert_after` poll still verifies.
5. **Navigate guards.**
   - The pre-command origin and challenge/login guards do not refuse a `navigate`, whose target URL is already
     checked against `allowed_origins`.
   - The guards run on the page the navigate lands on.
   - Test: after an off-origin park, the next record's opening navigate works.
6. **Debugger detach.** On `chrome.debugger.onDetach` for the bound tab: drop the cached transport, send
   `event detached`, and abort the in-flight command.
7. **Event draining.**
   - Drain after the fresh-confirmation probe.
   - `_drain_events` processes the whole batch, and a run-level event takes precedence over `off_origin`.
   - Events from an aborted command are sent only while it is `current()`.
8. **Challenge markers.** Only a *visible* challenge iframe (non-zero box), or the "Just a moment" title, counts.
   An invisible reCAPTCHA badge does not pause a run.
9. **E2E reconnect test.** Start the worker with a budget that covers the whole test, or start a fresh worker after
   the resume.
10. **Prepare-phase test.** `runCommandStep` in the prepare phase makes zero `Input.*` calls, through the real step
    runner with a fake CDP.
