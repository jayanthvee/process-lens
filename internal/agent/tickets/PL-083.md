# PL-083: the web app's first run, menu and dead ends

Owner: T2 (DeepSeek) · Reviewer: T1 · Branch `pl-083` (from `main`)
Time box: 90 minutes

## Why

T1 walked `main` as a new employee would. Here's what got in the way:

- **Nothing says how to start.** "Chrome not connected" is a small grey line in the sidebar
  corner. Home and the Teach page both assume the extension is installed and connected.
- **Dead menu items.** Documents, Saved answers, Settings and Help all open "Coming soon". A new
  person clicks them and learns the app is half-built. (PL-080 is building Settings in parallel.)
- **Confusing empty-state copy:** Home says "Nothing has run yet. Nothing was entered twice."
- **Pages draw with no loading state.** On a slow machine a page sits blank for 1–2 seconds
  after a click, and it looks broken.

## Scope (`apps/web/` only)

1. **A "Get set up" panel**, shown on Home and the Teach page while Chrome isn't connected
   (the sidebar already knows). It has three numbered lines:
   - "Add the ProcessLens extension to Chrome", linking to the existing extension download or
     install instructions. Find what PL-052 shipped and use it; don't invent a URL.
   - "Open it and press Connect."
   - "Come back here. This panel goes away by itself."

   When the connection appears, the panel disappears without a reload. Nothing else on Home
   moves.
2. **The menu shows only what works.** Hide Documents, Saved answers and Help from the sidebar.
   Leave their routes alone, so old links still land on "Coming soon". Leave Settings to PL-080:
   don't touch it.
3. **Plain empty states.** Home with no runs says "Nothing has run yet. Teach a task to get
   started." with the existing button. Remove "Nothing was entered twice." from the empty state.
   It's only meaningful once there are runs, so keep it there if it means something then. Check
   every page for the same problem (Tasks, Runs, Needs help, Spreadsheets) and fix any line that
   only makes sense with data.
4. **A loading state.** While a page's first data request is in flight, show the page title and
   one quiet "Loading…" line, and no blank panel. Use the existing `useJson` hook's loading
   state; don't add a spinner library. Check that the blur-in animation doesn't hide content
   when it starts while the tab is hidden.

## Gates

- Tests first in `apps/web/tests/`:
  - the setup panel appears when disconnected and disappears on connect;
  - the hidden menu items are gone, and their routes still render;
  - each empty state's words;
  - the loading line shows before the data arrives.
- `npm --prefix apps/web run check`, and full `python -m pytest -q` (it serves `apps/web/dist`).
- No e2e.
