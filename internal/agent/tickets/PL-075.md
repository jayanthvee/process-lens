# PL-075: proof for a save that updates a record in place

Owner: T2 (DeepSeek) · Reviewer: T1 · Branch `pl-075` (built on `pl-063`, with `pl-073` merged)
Time box: 120 minutes

## Why

Updating existing records is one of the most common jobs we automate: a price change, a status
change, a new owner. PL-063 found that ProcessLens can't compile one today. On Odoo's product
form the Save click neither navigates (the URL stays `/odoo/products/<id>`) nor shows a toast. So
the recorder's observation window ends with nothing, and the compiler refuses:

> commit step click-2 has no assert_after: the recording observed no confirmation and no
> navigation, and none was supplied for it

What the page does show is that **the save control goes away**. Odoo hides its Save button once
the record is clean, and many apps disable theirs. That, on the same record page, is the proof.

While doing this you will also fix a fail-open in the executor. `conditionExpression` in
`apps/extension/src/executor/assertions.ts` evaluates **only the first** predicate key of a
condition. Any other keys in the same condition are silently ignored.

## Scope

1. **Executor: every key counts** (`apps/extension/src/executor/assertions.ts`). A condition with
   several predicate keys passes only when **all** of them pass. Write a test first: a condition
   with `text_visible` (true) plus `url_matches` (false) must fail today and pass after the fix.
   `timeout_ms` is not a predicate.
2. **Recorder: a third kind of evidence** (`apps/extension/src/content/recorder.ts`,
   `finishObservation` and `beginObservation`).
   - When a click's window ends with no confirmation and no navigation, check whether the
     **clicked control** is now gone, hidden, or disabled (`disabled`, `aria-disabled="true"`).
     If it is, emit one observation:
     `{ element_absent: { targets: <the clicked control's ladder> }, url_matches: <this page's pattern> }`.
     Use the same `navigationPattern` the URL evidence uses, so it pins the record page.
   - The window must remember the clicked element when it opens.
   - A disabled control is not "absent", so the executor needs a matching meaning. Either
     (a) treat `element_absent` as "no *enabled, visible* element resolves", or (b) add nothing
     new and only emit this evidence when the control is really gone or hidden. **Pick (b)**
     unless Odoo's button is only disabled. Check that first on the real page, and write in the
     report which one it is, with evidence.
   - Only for a click that the compiler would treat as a commit (the same steps that get
     `assert_after` today). Nothing changes for a click that already has a toast or a navigation.
3. **Compiler** (`packages/compiler/`). Accept that observation as `assert_after` like any
   other. Check `packages/compiler/assertions.py`'s allowed keys and the commit-evidence path in
   `compiler.py` near "observed no confirmation". The compiler warns when a `url_matches` assertion is
   also true on the page the step ran on. In this condition the URL only pins the record page, and
   `element_absent` is the proof, so that warning must not fire when the condition also carries
   `element_absent`. Add a test for it. **Do not** loosen the refusal for a click that
   produced no evidence at all: that refusal stays.
4. **The price golden** (`tests/e2e/test_odoo_product_price_golden.py`). Remove its
   `xfail(strict=True)` once it passes. It must then show three rows `verified`, Odoo's
   `list_price` matching the sheet, and a second run skipping all three. If it fails further on,
   keep the marker with the new reason, as before.

## Gates

- Tests first: (1) the executor test above; (2) recorder tests with a fixture page whose Save
  button is removed after the click, one whose button is hidden, one where nothing changes (no
  observation), and one with a toast (unchanged: `text_visible`); (3) a compiler test that the
  new observation becomes `assert_after` and a no-evidence click is still refused.
- `npm --prefix apps/extension run check` (typecheck, tests, build, validate), full
  `python -m pytest -q`, `ruff check .` and `ruff format --check .`.
- The price golden at most twice: run `python infra/test-apps/reset.py odoo` and rebuild
  `apps/extension/dist` before each. Also run the quotation golden and the invoice golden once
  each (they share the recorder) and say whether they pass.
