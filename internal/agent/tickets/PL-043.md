# PL-043: The popup gets simpler — the old run buttons go, and a stray step can be deleted

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Size: **small, 2 parts** · Branch `pl-043` · Worktree
`C:\Users\vasup\process-lens\.worktrees\pl-043` · **Extension only.**

The owner tested the popup on 2026-10-17. Two things confused them:
- the old **Try one row / Pause / Resume / Stop** buttons under "More", which run a recipe from inside the popup. The dashboard's "3. Try one row" replaced them, so now there are two different "Try one row" buttons;
- a stray click recorded by mistake can't be removed, so the only fix is to record everything again.

## Part 1: remove the old run buttons from the popup
- **Remove from `apps/extension/src/popup/popup.html`:**
  - `#run-start`, `#run-pause`, `#run-resume` and `#run-abort`;
  - their `#run-state` line;
  - the `make-commit` select **only if** nothing else uses it. Check `make-recipe.ts`: if the save form uses it, keep it.
- **Remove their wiring in `popup.ts`.** Remove their words from `popup/words.ts` if nothing else uses them.
- **Keep the service worker's `executor:*` handlers.** Other code and tests may still use them: don't touch `background/` in this part.
- **Update `tests/popup-steps.test.ts` and `tests/popup-words.test.ts`.** They list these ids: assert instead that **none** of the four buttons exists.
- **Commit and push.**

## Part 2: delete a stray step before saving
1. **Each step line gets a remove button.** In the popup's live list of recorded steps (`renderSteps` / `renderStepList` in `popup/flow.ts`), each step line gets a small quiet **×** button with `aria-label="Remove this step"`.
   - **While recording is on:** the button is hidden.
   - **After Stop:** it is shown.
2. **Clicking it** sends `{ type: "record:remove", seq }` to the service worker.
   - Add the message type to `shared/messages.ts`.
   - In `background/service-worker.ts`, handle it by removing the event with that `seq` from the recorder session, then `broadcast()`. Add a `remove(seq)` method to `RecorderSession` in `background/recorder-session.ts`.
   - Refuse silently while recording.
   - The popup re-renders from the status it gets back, so the step count and the save form's columns update too.
3. **An observation that belongs to the removed step** (`kind: "observation"`, recorded right after it for the same step) is removed with it. Look at how `pendingObservationTarget` links them, and keep that link intact.
- **Tests first (vitest):**
  - the × shows only when recording is off;
  - clicking it sends `record:remove` with the step's `seq`;
  - `RecorderSession.remove(seq)` drops that event and its observation, and nothing else;
  - remove is refused while recording;
  - the step list and count re-render without the removed step.
- **Commit and push.**
