# PL-092: One live connection per Chrome; a failed read stops no worker

Owner: T1 · Branch `pl-092` (from `main`)

## Why

The hosted smoke test on Render failed twice in a row on 2026-10-24, after PL-090 was deployed.

1. **First failure:** Ben's run was claimed, its first command got 60 s of silence (grace included), and the run paused `executor_disconnected`.
2. **Second failure:** Anna's next run stayed `queued` for 5 minutes. Only one run per destination may be active (`runs_one_active_per_destination`), and Ben's paused run held Odoo.

Cause: the popup connects by itself when it opens. When a person (or the test) then also presses Connect, `CommandSession.connect` paired a new session and opened a new socket **without closing the old one**. The sequence:

- The old socket stayed attached at the hub, so the supervisor started a worker for each session.
- The old socket's message listener was still live: a command on the old session ran in the tab.
- Its answer went out on `this.socket`, the new one, to a runner that never sent it (R3 dropped it there).
- The old session's worker heard nothing and paused the run.
- Which worker claimed first decided pass or fail, so it was intermittent.

A second, smaller fault: `attached_sessions` answered `[]` when it could not read the API, and the supervisor took that for "nobody is connected" and stopped every worker mid-run.

## Change

1. **Extension** (`command-session.ts`):
   - `connect` cancels a pending reconnect and drops the current socket before pairing. Dropping closes the socket, aborts a running command and marks it unwinding; the close is not treated as a drop.
   - A message is handled only when it arrives on the current socket.
2. **Hub** (`hub.py`): when an extension socket finishes attaching, every other session with the same non-empty `browser_id` is superseded. Its runner is told `peer_gone`, its extension socket is closed with `DETACHED_CODE`, and it can never be attached again. Extensions from before PL-087 (no browser id) are unaffected.
3. **Supervisor** (`deploy.py`): `attached_sessions` answers `None` when the API cannot be read. The supervisor then keeps every worker and starts none until the next good read.

## Tests

- `apps/extension/tests/command-state.test.ts`, "Connect pressed while a session is already open": 6 tests, 4 of which fail without the change.
- `tests/runner/test_hub.py`, the PL-092 section: the old session is retired, another Chrome is untouched, and an extension with no browser id never retires anything.
- `tests/deploy/test_deploy.py`: a failed read is `None`, and a failed read stops no worker.

## Not changed

`runs_one_active_per_destination`: one active (running or paused) run per destination across the team stays. It is safe, but a paused run blocks the team until someone resumes or cancels it. That is an owner decision.
