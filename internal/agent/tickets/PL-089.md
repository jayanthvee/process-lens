# PL-089: A cancelled run whose Chrome is gone still finishes; the hosted smoke test

Owner: T1 · Branch `pl-089` (from `main`)

## Why

Found while running the first hosted end-to-end test on 2026-10-23. A cancel is a request that a
worker finishes. Since PL-087 a run belongs to one Chrome, so a run cancelled after its Chrome went
away is never finished. It stays `running` or `queued`, and an open run blocks every other run on
its destination, for every tester.

## Scope

1. **`finalise_unheld_cancels`** (`services/runner/cancel.py`). The ledger reads and takes live in
   `packages/ledger/runs.py`, and the pattern is in `sql-patterns.md`. For each run with a cancel
   request that no live worker holds:
   - take its lease;
   - recover;
   - park the commit window for a person (never re-queued);
   - skip the pending records;
   - mark the run `cancelled`, all in one transaction.
2. The hosted supervisor and the local demo call it on every tick.
3. **`tests/e2e/test_hosted_smoke.py`**, opt-in with `PROCESSLENS_E2E_HOSTED_URL` and
   `PROCESSLENS_E2E_HOSTED_CODE`. Two Chromes run through the deployed API against real Odoo:
   - the task saves on Render;
   - Ben's run waits while his Chrome is away;
   - Anna's run goes to her Chrome;
   - Ben's run goes to his once he connects.
