# PL-017b: A click lands only on the element the guards approved

Owner: T2 · Reviewer: T1 · Depends on: PL-017 (merged) · Phase: C

## Description
`dispatchClick` (`apps/extension/src/executor/dispatch.ts`) works in two parts:
1. `measureTarget` checks that the target is hit-testable at measure time.
2. It then sends `mouseMoved`, `mousePressed` and `mouseReleased` to those coordinates.

Nothing confirms the element is still at that point when the press lands. If the page reflows in between (an
autocomplete list opening, a banner, a late image), the press goes to whatever moved there. PL-017's diagnosis
showed exactly this on the messy fixture, and the fixture was changed to stop reflowing. Real sites do reflow,
Gmail's recipient suggestions among them.

**This is a correctness and safety defect.** The executor's guarantee is that the element the guards approved is
the element acted on. A misplaced press on a real CRM could hit a different control, including a commit control.

This ticket closes the gap in the executor and restores a reflowing fixture to prove it.

## Scope
- `apps/extension/src/executor/` (`dispatch.ts`, `ladder.ts` measure helpers, `step-runner.ts` if needed) and

The runner and the protocol are out of scope. The extension already reports `lost` for an error after the first
gated input (F2), and the runner already reconciles `lost`. If a change there seems needed, stop and ask T1.

## Requirements

1. **Wait for the target to stop moving.**
   - Before the first `Input.*` event of a click, measure the target's box on two consecutive animation frames. Use
     a page-side `requestAnimationFrame` pair inside one `Runtime.evaluate`, with `awaitPromise`.
   - The box is stable when x, y, width and height each differ by 1 px or less. If it isn't stable, measure again
     until it is, within the step's own deadline.
   - If it never settles, the step **parks**, with reason "the target kept moving", and no input is sent.
   - **Tests (vitest, fake CDP):**
     - a box that moves once, then settles, is clicked at the settled point;
     - a box that never settles parks with zero `Input.*` calls.

2. **Hit-test the point again immediately before the press.**
   - After the stability check and right before `mouseMoved`, run `elementFromPoint` at the click point. It must
     return the target or a descendant of it.
   - If it doesn't, re-measure, which counts toward the deadline. A target still covered at the deadline **parks**,
     with reason "the target is covered by another element", and no input is sent.
   - **Test:** a hit test that returns an overlay parks with zero `Input.*` calls.

3. **Check where the press actually landed.**
   - Before the press, install a one-shot capture-phase `mousedown` listener on the document. It records whether the
     event's target is the approved element or a descendant, and is removed after one event or on timeout.
   - After `mouseReleased`, read the result:
     - **On the target:** success, as today.
     - **Elsewhere, on a non-commit step:** throw a park error, with reason "the click landed on a different
       element".
     - **Elsewhere, on a commit step:** input was sent, so this is an unknown outcome. The step reports `lost`
       through the existing F2 path, and the runner reconciles. It must never be `rejected` or `not_dispatched`.
     - **No result** (the page navigated and the listener's document is gone): treat it as landed only if the
       navigation was caused by this click, which the existing navigate watcher already detects. Otherwise use the
       "elsewhere" rules above.
   - **Tests:**
     - a press that lands on the target succeeds;
     - one that lands elsewhere on a fill-phase click parks;
     - one that lands elsewhere on a commit dispatch reports `lost`, not `rejected`.

4. **Prove it on a reflowing page.**
   - `messy-crm` gains a `listbox_in_flow` switch (default off) that restores the in-flow listbox PL-017 replaced. It
     reflows the page and pushes the Add button down when suggestions open.
   - The messy golden test runs with `listbox_in_flow` on and passes. Its replay clicks Add at the settled position.
   - Add a second e2e case on the same file: with the switch on, nothing is ever added for a recipient other than the
     row's, and no record is created twice.
   - Update the fixture selftest for the switch.

5. **Keep the existing behaviour.**
   - These checks add at most about two animation frames, plus one evaluate, to a click on a still page.
   - Record the measured overhead per click in the report: the median of the lead-crm golden test's clicks.
   - The 5 s ack budget for a commit dispatch must still be met. If the overhead threatens it, stop and report it.
