# PL-094: A row with no key is flagged at the check, not a refusal of the whole run

Owner: T1 · Branch `pl-094` (from `main`)

## Why

Found running the pilot kit's `products-messy.csv` against Render on 2026-10-24. One row had an empty SKU, and the SKU is the record key.

- The check passed every row except a duplicate.
- `POST /api/v1/runs` then refused the whole run: `input record …: a rendered key is empty`.
- One bad row stopped all of them, with a message a person cannot act on.

A key column with a "park if empty" rule (email on the lead task) was already flagged. A key column without one (SKU, a customer, a reference) was not.

## Change

`_duplicate_reason` (`services/api/batches.py`) flags a row whose rendered key is empty, blank, or cannot be rendered, with `No <column>`, the same words a missing-field rule uses. The row goes to `needs_review` and stays out of the run, so the run starts with the rest. When a precheck rule already said the same words, they are not repeated.

## Tests

`tests/api/test_batches_api.py::test_a_row_with_no_key_is_flagged_and_does_not_block_the_run`: an empty and a blank SKU are flagged `No sku`, and the run is created with the other two rows. It fails without the change.
