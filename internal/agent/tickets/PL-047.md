# PL-047: A row parked after its save says what ProcessLens looked for

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Size: **small, 1 part** · Branch `pl-047` · Worktree
`C:\Users\vasup\process-lens\.worktrees\pl-047` · **Runner only:** `services/runner/`

## Why
When a save's check doesn't pass, the row parks with `could not verify the save automatically; check the destination` (`PARKING_REASON` in `services/runner/reconcile.py`). The owner sees that on the dashboard and has to guess what "verify" meant. The runner knows exactly what it looked for: the commit step's `assert_after`, for example `text_visible: "Lead created"` or `text_count_increases: "{{row.contact}}"`, and how long it waited. That knowledge is dropped at `run_loop.py` ("the assertion did not pass" → `_reconcile`), and `_reconcile` parks with the reconciler's generic error.

## The fix
1. **A pure function `describe_check(condition, row, variables) -> str`** in a new `services/runner/check_words.py`. It turns an `assert_after` into one plain sentence, rendering templates with the same renderer the runner already uses for the check. One sentence per condition kind the schema allows (read `packages/recipe/schema/recipe.schema.json`):
   - `text_visible: "Lead created"` → `the page never showed "Lead created" within 8 seconds`;
   - `text_count_increases: "Ana Ruiz"` → `"Ana Ruiz" did not appear one more time within 8 seconds`;
   - an unknown kind → `the save's check did not pass`.

   Never more than 160 characters: truncate a long value with `…`.
2. **When the commit's check fails** (the `submitted_unverified → reconciling` transition after `verdict.passed` is false in `run_loop.py`), pass that sentence to `_reconcile`.
3. **If the record then parks,** its reason becomes `<sentence>; check Odoo: if the row is there, Dismiss it, otherwise Try again`. Use the destination's name if the run knows it; otherwise say `the destination` instead of `Odoo`.
   - Every other parking path (no dispatch proof, several matches, a search error with no failed check) keeps today's reason exactly.
   - Keep `PARKING_REASON` exported and unchanged: tests and the web app match on it.

## Tests first (pytest, red before the fix)
- **`describe_check`:** one test per condition kind, a rendered template, the 160-character cap, and an unknown kind.
- **The run loop:** with the existing fake executor and fake reconciler, a commit whose check fails parks with the new sentence. A reconcile with no failed check still parks with `PARKING_REASON`. Find the existing tests that drive `_reconcile` and copy their setup.
- **Existing runner tests** pass unchanged, except any that assert the exact old reason on the failed-check path. Update only those, and list them in your report.
