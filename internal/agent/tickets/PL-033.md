# PL-033: A popup and dashboard a non-technical person can walk through

Owner: T2 (GLM-5.3-Flash) · Reviewer: Kimi (reads the diff), then T1 · Size: medium · Depends on: PL-030 (merged)

## Why
The owner ran the real demo. Every point below is something they hit. The design stays the same: DESIGN.md tokens
and Public Sans, light fog with gold.

## Requirements
1. **The popup becomes three steps.** In `apps/extension/src/popup/`, one card per step, in order, with only the
   current step's button in gold:
   1. **Teach**: *Start teaching* / *Stop*, plus the step count ("15 steps recorded").
   2. **Save**: the task name, the "Which column identifies each row?" select, the "Stop and ask me if this is
      empty" ticks, and *Save as task*.
   3. **Open in ProcessLens**: shown after a save, with one button, *Open in ProcessLens*.
   - Everything else goes inside a closed `<details>` named **More**: Try one row, Pause, Resume, Stop,
     *Save a copy of the steps*, the streaming field, the ProcessLens address, Connect and Disconnect.
   - **Remove the popup's own Try one row**. The dashboard's Try one row is the only one. Keep the
     `#make-*`, `#start`, `#stop`, `#clear`, `#hub`, `#connect` and `#session-state` ids and their behaviour
     (frozen e2e contract, listed in `internal/agent/reports/PL-025.md`). Moving them into cards or `<details>` is
     fine. Deleting or renaming one is not.
   - **"Which click finishes the row?"** pre-selects the **last** click and moves under More, since most people
     never need it.
2. **The link works.** *Open in ProcessLens* calls `chrome.tabs.create({ url })`. A plain `<a href>` in an extension
   popup does nothing. Do the same for any other link in the popup.
3. **Plain words only.**
   - Under the save result, show at most **2** sentences. Show nothing about values the page set itself, or about
     columns.
   - Sentences that matter: "I couldn't check for duplicates because you didn't search first." and "Stops and asks
     when Email is empty."
   - Everything else is hidden; it stays reachable under More → "Notes for support".
   - Extend `words.ts` with the PL-031 compiler warnings: `skipped the fill`, `bound a literal`, `templated`,
     `derived the input schema`, `dropped container click`, `folded the retried fill`, `assertion for`, `this save
     is checked`. The test that measures the word list fails on any engine word.
4. **Connecting is automatic and visible.**
   - The address defaults to `http://127.0.0.1:8000`.
   - The popup connects by itself when it opens, if not connected, and shows "Connected to ProcessLens" or
     "ProcessLens isn't running".
   - In the dashboard (`apps/web`), a run that is `queued` while `GET /api/v1/executor/session` shows no
     session says **"Waiting for Chrome: open the ProcessLens extension and it will connect"**, not "Queued". This
     applies on the task-run page's Try one row and on the run page.
5. **Readable step names on the dashboard's task page.**
   - "Type the fill Contact" becomes **"Type the contact"**, "Click Add" stays.
   - A `press` step becomes **"Press Tab in Phone"**, using its target's label.
   - A step whose name is longer than 40 characters shows its action and its first label only.
   - Fix this where the web app builds step sentences (`grep -rn "Type the" apps/web/src`).

## Tests (write them first)
- **vitest (extension):**
  - only the current step's button is gold;
  - More is closed by default and holds the listed controls;
  - the popup Try one row is gone;
  - *Open in ProcessLens* calls `chrome.tabs.create` with the task URL;
  - the result area shows 2 sentences or fewer for the PL-031 warning list;
  - auto-connect runs once on open;
  - the frozen-id test still passes.
- **vitest (web):** the "Waiting for Chrome" wording when there is no session; step names for fill, press and long
  names.
