# PL-090: A busy Chrome is not a lost Chrome

Owner: T2 (DeepSeek) · Reviewer: T1 · Branch `pl-090` (the ticket and failing tests are on it)
Time box: 60 minutes · No e2e: T1 reruns the hosted smoke test after review.

## Why

In the hosted test on 2026-10-24, Odoo had just restarted. Its first page load rebuilt its assets
and kept Chrome busy. The step's reply came back after the runner's budget (the step's
`timeout_ms` plus `ack_budget_seconds`). `BrowserExecutor._lost` treats a timeout with the socket
still up as a lost extension (`self._detach(...)`), so the whole run paused as
`executor_disconnected`. A rerun with Odoo warm passed 4 of 4. A slow page should cost a wait, not
the run.

## Scope

Only `services/runner/browser_executor.py`.

1. Add a constructor argument `late_reply_grace_seconds: float = DEFAULT_LATE_REPLY_GRACE_SECONDS`,
   with the constant set to 45.0.
2. When a read for an awaited command times out while the socket is still up (not
   `self.disconnected`, `self._socket` not None), keep reading for that same `command_id` once
   more, until the original deadline plus the grace.
   - A reply that arrives in that window is used as if it had come in time.
   - Silence past the grace goes to `_lost` exactly as today, so it still detaches.
   - Apply this to all three waits:
     - `_step_result`;
     - the ack loop in `dispatch`;
     - the reply wait in `check_condition`.
3. Leave the wire `expires_at` alone. The extension still refuses a dispatch that expired before
   any input was sent, and that is the safety we keep.
4. Update the `_lost` docstring (R4) to say the grace comes first.

## Gates

- The tests already on the branch in `tests/runner/test_browser_executor.py` (PL-090 section) must
  pass:
  - a late step reply;
  - a late dispatch ack;
  - a late condition answer;
  - silence past the grace is still lost;
  - the second wait runs to the deadline plus the grace on the executor's clock: `waits == [15.0, 45.0]`.
- Don't change those tests.
