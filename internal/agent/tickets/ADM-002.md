# ADM-002: A Health page, and the panel moves off port 8000

Repository: **`process-lens-admin`** · Owner: T2 (admin DeepSeek) · Reviewer: T1 · Size: **small, 2 parts** ·
Branch `adm-002`, cut from `origin/adm-001e` · No migrations, no writes.

## Why
ADM-001 answers "is anything wrong right now?" with run counts, but not with whether the **machinery** is up. Before
the 2026-10-31 demo and the Railway deploy, the admin needs one page that says whether workers are alive, whether
work is piling up, and whether the database is the version the panel expects. ADM-001 already listed "a health
page" under Later.

Also, the panel's API binds `127.0.0.1:8000`, the same port as ProcessLens's own demo API (`scripts/demo.py`), so the
two can't run side by side.

## Part 1: the `health` module
Scaffold it with `scripts/new_module.py health`. It is read-only, its manifest declares `writes: []`, and it needs
`requires: core`. One route, `GET /api/health`, is tenant-filtered like every other query and returns counts and
times only, never row contents. The page shows each line as a plain sentence with a green / amber / red dot:

1. **Workers.** Count runs in `running` whose `runs.heartbeat_at` is older than 60 seconds: "No stuck runs" (green), or
   "2 runs have stopped reporting for over a minute" (red), each linking to that run on the Runs page.
2. **Waiting work.** Count `jobs` not yet finished and the age of the oldest: "Nothing waiting" (green), "5 jobs
   waiting, oldest 3 minutes" (amber if the oldest is over 5 minutes, red over 30). Check `jobs`'s real columns in
   `../process-lens/db/migrations/` first and use them; don't guess.
3. **Rows that need help.** Count `run_records` in `parked` across this company's runs: green at 0, amber otherwise,
   linking to Runs.
4. **Chrome extensions.** From `extension_reports`, how many people reported in the last 24 hours, and how many of them
   are below `tenants.min_extension_version`: green when none are below it, amber otherwise.
5. **Database.** Whether the `admin_modules` rows the panel needs (`core`) are present: green "Up to date", or red
   "Needs a ProcessLens update". Reuse the registry's existing check; don't write a second one.
6. **ProcessLens API.** One `GET` through the existing ProcessLens client (`api/processlens.py`) with a 2-second
   timeout: green "Reachable", or red "Can't reach ProcessLens at <url>". This is the only line allowed to show a URL.

Put the thresholds in one constant block at the top of the router. Sidebar entry: "Health", placed after Overview.
Don't use engine words on the page (the forbidden-word vitest covers it), and follow the dark theme and §7 of
`DESIGN.md`. Usable at 400 px.

## Part 2: the port
The panel API defaults to `127.0.0.1:8100`. Update the README's Run command, `.env.example`, the web dev proxy (or
whatever points the web app at the API), and any test that hard-codes 8000. ProcessLens's own port, 8000, is not this
repo's to change.
