## Description
The brief needs a real web app. `apps/web` is still the bare operator page from PL-015. This ticket rebuilds
`apps/web` in **React + TypeScript + Vite**, the stack the brief names, in the approved look, and delivers the
screens that use data we already have.

**Read these first, and follow them exactly:**
- `internal/docs/DESIGN.md`: the words, type, color tokens, layout, sidebar and motion;
- `internal/docs/design/home-mock.html`: the approved Home screen. Open it in a browser. Port its CSS tokens and
  structure; don't reinvent them.

**The user is not technical.** The UI vocabulary table in DESIGN.md Â§2 is mandatory. No engine word (recipe,
record key, parked, ledger, version) may appear on any screen. A unit test enforces this (requirement 7).

## Requirements
1. **The stack.**
   - React 18, React Router and TypeScript in `apps/web`, built by Vite into `apps/web/dist`, which
     `services/api/main.py` already serves.
   - Plain CSS with the DESIGN.md tokens (one `tokens.css` plus CSS modules or co-located CSS). **No Tailwind,
     no component library.**
   - Public Sans through `@fontsource/public-sans`.
   - Pin every new dependency to an exact version.
   - Keep `npm --prefix apps/web run check` (typecheck, test, build) as the gate.
2. **The app shell.**
   - The sidebar exactly as in DESIGN.md Â§6. Every item routes to a page.
   - The header: page title, search (Ctrl K opens a simple search over task names; a stub list is fine), the
     page's primary action, and the avatar.
   - The "Chrome connected" status comes from the hub's session state (whether a session is attached); show
     "Chrome not connected" otherwise.
   - Pages not built in this ticket (Spreadsheets, Documents, Saved answers, Apps, Settings, Help) show a
     designed empty state: one sentence plus "Coming soon". No blank pages.
3. **Home** matches the mock, backed by real data:
   - the headline "N rows done this week. M need you." (with no rows: "Nothing has run yet." and the Teach
     button);
   - **time saved this week** (rows done × 3 minutes, minus run time), shown in the gold figure exactly as in the mock;
   - Needs your help (top 3);
   - Running now, with a live progress bar (poll every 2 s while a run is active);
   - My tasks (latest 5).
4. **Tasks** (`/tasks`):
   - A table of the saved recipes, shown as tasks: name, the app (from the recipe's first allowed origin),
     last run, result, and one button ("Run again" or "Try one row"). Empty state: "Teach your first task" â†’
     a link to `/teach`, a "Coming next" page.
   - Clicking a task opens `/tasks/:id`, a read-only page for now: its steps in plain words (a navigate step
     becomes "Open Odoo CRM", a fill becomes "Type the email", and so on) and its runs. The editor comes in
     PL-024.
5. **Runs** (`/runs` and `/runs/:id`):
   - **The list:** task, started, status, and "11 of 20 done".
   - **A run page** with:
     - live progress;
     - pause, resume and cancel;
     - a results table: each row's name or key, its outcome in plain words and the reason;
     - **Export CSV**, using the existing `results.csv`.
   - Time saved for a finished run: rows done Ã— 3 minutes, minus the run's duration. Show it as "About 52
     minutes saved".
6. **Needs help** (`/needs-help`):
   - Every row across runs that needs a person, with the plain reason and one action:
     - **Try again**: re-queue.
     - **Dismiss**.
   - **Safety (unchanged from PL-015, mandatory):** a row that may already have been saved (any commit was
     attempted) can only be re-queued after the person ticks "I checked Odoo and it isn't there". The API
     enforces this already. The UI must show the checkbox and explain why.
   - The Home and sidebar counts come from the same source.
7. **No engine words on screen.**
   - Add a vitest that renders every page with sample data and fails if the visible text contains any of:
     `recipe`, `ledger`, `parked`, `record key`, `verified`, `rung`, `idempotency`, `v1`, `v2`, `step_`,
     `fill-`, `click-`.
   - Each forbidden word maps to the plain wording in DESIGN.md Â§2.
8. **The API, only what the pages need.**
   - Add `GET /api/v1/home`, which returns the week's counts (done, already there, needs help), the minutes
     saved, the needs-help top 3, the running runs with their progress, and the latest tasks. Use one module in
     `services/api`, following `internal/docs/sql-patterns.md`, with pytest tests.
   - Reuse the existing `/runs`, `/recipes`, `/records/*` and `/approvals` routes for everything else.
   - **No change** to the ledger, runner, hub protocol, or the re-queue safety check.
9. **Motion and accessibility.**
   - The blur-in entrance runs on first render only. Live updates ease. Everything is off under reduced motion.
   - All buttons are real `<button>` or `<a>` elements with visible focus. The pages are usable at 400 px wide.
