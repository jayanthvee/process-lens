# PL-045: When the ProcessLens window won't come forward, the event says why

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Size: **small, 1 part** · Branch `pl-045` · Worktree
`C:\Users\vasup\process-lens\.worktrees\pl-045` · **Extension only.**

## Why
PL-040 brings a hidden work window to the front before each step (`ensureVisible` in `apps/extension/src/executor/visibility.ts`). If the page is still hidden after 2 seconds, it sends the `window_hidden` event and pauses the run. In the owner's testing this **missed once, and nobody can tell why**: we don't know whether `chrome.tabs.update` or `chrome.windows.update` threw, what state the window was in (minimized, normal or maximized), or whether it was focused.

## The fix
1. **`ensureVisible` returns a report** instead of a bare boolean, for example `{ visible: boolean; tried: boolean; error?: string; before?: WindowFacts; after?: WindowFacts; waitedMs: number }`, where `WindowFacts = { state, focused, tabActive }`.
   - `VisibilityDeps` gets one optional `windowFacts?: () => Promise<WindowFacts | undefined>`.
   - Call it once before `bringForward` and once at the end.
   - Record the `bringForward` error's message instead of discarding it.
2. **`workTabVisibility` in `background/service-worker.ts`** implements `windowFacts` with `chrome.tabs.get(tabId)` and `chrome.windows.get(windowId)`. Return `undefined` on any error.
3. **When the page stays hidden,** the `window_hidden` event's `detail` gets one short line built from the report, after `WINDOW_HIDDEN_MESSAGE`, for example: `(window minimized→minimized, focused no, tab active yes, raise error: none, waited 2000ms)`.
   - Also `console.warn` the full report from the service worker.
   - Never put a URL or page text in it.
4. **Update every caller:** the `ensureVisible?` option in `executor/command-step.ts`, and where the service worker converts an error to `window_hidden`. The visible case behaves exactly as today.

## Tests first (vitest, red before the fix)
- **A visible page:** the report is `{ visible: true, tried: false }`, and `bringForward` is never called.
- **Hidden, then visible after a raise:** `visible: true, tried: true`, with `waitedMs` filled in.
- **Hidden, and the raise throws:** `visible: false`, with `error` holding the message.
- **`windowFacts` is called before and after,** and a throwing or `undefined` `windowFacts` doesn't break anything.
- **The `window_hidden` detail line** contains the before/after window state and no URL.
- **The existing PL-040 tests** pass. Update their assertions only where the return type changed.
