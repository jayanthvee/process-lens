# PL-124: the price task loses the typed price, and four faults behind it

Use case #4, Odoo Sales price update. The owner's first run after PL-121/122/123 (2026-10-29) failed.
The saved task and the run's rows are in `internal/agent/tickets/PL-124-evidence/`.

## What the owner did

Sales → Products → searched "Oak Standing Desk" → opened the card → changed Sales Price from 400 to
3200 → left by the back arrow without Save → Stop → saved as `salestask` → loaded `prices-test.csv`
→ Try one row → Run all.

## What happened

- After Stop, the list showed Odoo's own values as "Typed the …" (product name, the "on" boxes,
  goods, track inventory, cost, category, reference, sales price **400.00**). The owner's **3200**
  was gone. "Hidden: 4".
- The saved recipe (`salestask-recipe.json`) has **no price step**: navigate, search, Enter,
  branch, click "On hand: 18.00", back, park "couldn't confirm the change was saved".
- Try one row previewed "Sales price — you typed 3200 → 799" for a step that doesn't exist.
- Oak and Mesh: `skipped`, "already committed in an earlier run", before any step ran.
- Drafting Stool: the work window was black; "Fill Search..." parked as not found with
  "0 input(s), 498 element(s)" on `/odoo/products`.

## Causes (T1, from the code on main 7d858fd)

1. **The cleaning model can't tell a typed value from one the page set.**
   `services/api/compile.py:_recorded_steps` passes only id, action, name, targets and value, and
   `redact_clean_payload` removes the value. `page_set` and `keystrokes` never reach the model. It saw
   two identical "sales price" fills, kept the first (Odoo's 400) and dropped the owner's. No code
   stops a model from hiding a value a person typed.
2. **The panel doesn't hide page-set fills by their flag.** `PanelTeach.tsx` hides only the model's
   `keep:false` ids. PL-123's report said page-set steps were hidden by the flag; they aren't.
3. **The open-click is compiled from the clicked sub-element's literal text** ("On hand: 18.00").
   That only matches Oak, and its intent "click On hand: 18.00" points find_target at the wrong
   thing on every other row.
4. **An update task with no changed value still compiles.** With no update column, the
   idempotency key is `{{row.search | lower}}` alone, so any product an earlier price task touched
   is skipped as "already committed" forever. The preview then shows a change the recipe never
   makes (it's built from the columns, not from the recipe's steps).
5. **A blank work window was reported as "not found".** PL-123 promised it never would be.
   `ensureDrawing` ran before the step and passed (it counts frames once). Odoo renders through
   `requestAnimationFrame`, so a window that stops drawing *after* that check leaves a page with no
   inputs, and the ladder then reports not found. Unproven: there's no screenshot of that moment.

## Scope

1. **Facts to the model, and a code gate around it.**
   - Send each step's origin to `clean_recording` as `"by": "person"` (typed, `keystrokes > 0`,
     or `page_set` not true) or `"by": "page"`, with no values. Update the prompt: a step `by: page`
     is dropped; a step `by: person` is kept.
   - **The panel decides, not the model:** a page-set fill/select is always hidden; a fill or
     select the person typed is **never** hidden, whatever the model answered. The model may hide
     only clicks and presses.
   - When the same field is filled by the page and then by the person, only the person's last value
     is a step and a column.
2. **The open-click targets the row.** A click right after the search (and its found/not-found
   branch) is "open the result for `{{row.<search column>}}`". Its targets are the result element
   containing the row's value (`text_fuzzy {{row.<col>}}` with `exclude_search_box`, and the card or
   row that holds it). They're never the literal text of the sub-element clicked. Same for the
   table view.
3. **No update without a change.**
   - When the task saves (Save click or leave/self-save) but no step writes a column, Save in the
     panel refuses with: "This task doesn't change anything. Change the value you want each row to
     set, then Stop again."
   - The compiler refuses the same case with a CompileError, so no key-only update is ever pinned.
4. **The preview comes from the recipe.** "About to add/change" lists only fills the recipe
   actually makes, with the row's value.
5. **Not found on a page with no inputs re-checks drawing.** When a fill or click target isn't found
   and the page has 0 inputs (or the frame count is below `DRAWING_FRAMES`):
   - run `ensureDrawing` again;
   - if it still isn't drawing, park with `NOT_DRAWING_MESSAGE`, not "not found";
   - attach a `Page.captureScreenshot` of the work window to the step's evidence, so the next
     failure shows what the window looked like.

## Tests (write first, see each fail)

- API: `_recorded_steps` passes `by` per step and no value. The prompt mentions `by`.
- Web (`PanelTeach`): a recording shaped like the owner's has page-set fills (sales price 400,
  cost, reference, the "on" boxes) and the typed sales price 3200. Use a model answer that drops the
  3200 and keeps the 400. The visible list then has the 3200 fill and none of the page-set ones,
  and the request sent to compile carries a `sales_price` column with value 3200.
- Compiler: the owner's shape compiles to search → branch → open-click targeting `{{row.search}}`
  → fill Sales Price `{{row.sales_price}}` → leave → read-back. The idempotency key includes
  `{{row.sales_price}}`. A recording with the leave but no column-writing fill raises CompileError.
- Extension: a fill whose target isn't found on a page with 0 inputs and 0 frames answers the
  drawing sentence and carries a screenshot.

## Done means

The owner teaches the price task fresh (cards view, then table view, by clicking), runs
`prices-test.csv`, and sees 799 / 349 / 199 in Odoo, with each row Done and read back.

## Don't

- No Odoo words in the compiler or panel.
- No e2e, no browsers, no `git stash`. Run only the new test files to see them fail. Full gates once
  at the end.
