## Where it stands

PL-073 fixed the recorder, and T1 fixed the golden's own bugs:
- it signs in as the seeded employee;
- the reset deletes saved rows;
- the project box is cleared before typing;
- the day cells are pinned before typing.

Run as a demonstration, it now records and compiles, and the compiled save check is
`text_visible: "Successfully Saved"`, which OrangeHRM really shows. On replay, though, the canary
row parks:

> CRM Cleanup:Development = parked (the page never showed "Successfully Saved" within 8 seconds)

## Scope

1. **Find the cause, with evidence, before changing anything.** In the golden only, add a
   temporary capture: screenshots, plus the grid's input values and any `.oxd-input-group__message`
   text, right before and right after the replay's Save. Also dump each replayed step's
   `step_events` (target resolved, value) to `.cache/pl078/`. Remove all of it before you commit.
   Check whether the compiled day-cell targets depend on `oxd-input--active`. That class goes away
   when a cell has focus. If they do, say so.
2. **Fix the cause where it lives.** The recorder or compiler if a target or value is wrong;
   the executor if the toast is missed; the golden if it's the test. Product changes need tests
   first. Don't lengthen the 8-second assertion timeout to get past this unless the evidence shows
   the toast really comes after 8 seconds.
3. When the golden passes, remove its `xfail` marker. If it fails further on, update the marker's
   reason to the new failure.
