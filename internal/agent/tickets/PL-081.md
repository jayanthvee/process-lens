# PL-081: each timesheet row lands on its own line, and the proof says which line

Owner: T2 (DeepSeek) · Reviewer: T1 · Branch `pl-081` (built on `pl-078`)
Time box: 120 minutes

## Where it stands

After PL-078 the OrangeHRM replay saves, and all three records end `verified`. OrangeHRM's own
API, though, shows the week holding **one** line, not three:

    ('CRM Cleanup', 'Development', {'mon': 0.5, 'tue': 3.0, 'wed': 3.0, 'thu': 2.5, 'fri': 0.5})

Each record opened the week's grid and re-filled **its first line**. The project stayed the
first one, and the hours are some later row's. Every save showed "Successfully Saved", so every
record verified. That's two problems:

1. **The wrong line.** The demonstration filled the grid's only (empty) line. On replay, row 2
   finds row 1's saved line in that position and overwrites it. A person entering a second
   project would click **Add Row** and fill the new, last line.
2. **A false verified.** A toast that appears on any save can't tell "my line was saved" from
   "some line was saved". A grid save needs proof that names the record, such as the row's
   project and activity, visible together on the saved page.

## Scope

1. **Find out what really happened, with evidence.** Capture the grid's lines right before each
   record's Save on replay, and the project fill's resolved target. Why did the project stay
   "CRM Cleanup" when row 2 says "Quarterly Reporting"? Did the project fill resolve to the
   first line's box, or did its option choice fail? Remove the capture before committing.
2. **The demonstration** (`tests/e2e/test_orangehrm_timesheet_golden.py`): teach it the way a
   person adds a project: Edit → **Add Row** → fill the **new** line → Save. Then make the
   recording target the line it added, not "line 1". Decide where that belongs from the
   evidence: a recorder or compiler rule for "the line a click just added" (preferred, since every
   grid app has this), or the ladder resolving the last of several identical lines. Write the
   rule down. Don't touch raw coordinates or positional CSS (`nth-child`).
3. **The proof** (`packages/compiler/`): when a commit's only evidence is a confirmation toast and
   the record filled values into a grid line, add a `text_visible` for the record key's value to
   the same condition. PL-075 made conditions require every key, so the record's own value must
   be on the page after the save. Tests first, and a create on a plain form is unchanged.
4. When the golden passes (three lines in the week, each with its sheet hours, read from
   OrangeHRM's API), remove its `xfail` marker. Otherwise update the marker's reason.
