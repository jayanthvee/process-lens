# PL-071: Accounting on QuickBooks Online (sandbox company): customers, invoices and bills from a sheet

Owner: T2 (GLM Flash) · Reviewer: T1 · Size: **medium, 3 parts** · Branch `pl-071` · Worktree
`C:\Users\vasup\process-lens\.worktrees\glm` · e2e tests against Intuit's **sandbox** company only.

## Why
Consulting firms do their billing and supplier bills in QuickBooks. We've proved invoices on Odoo, but QuickBooks
Online is what the PM will recognise. Intuit gives every developer account free **sandbox companies**: real QuickBooks
Online with fake data, made for testing, and nothing in them is a real company's books. That's a sandbox, so it fits
our live-safety rule (AGENTS §3).

## Before the agent starts (the owner, once)
1. Create a free Intuit Developer account at developer.intuit.com, then **Dashboard → Sandbox → Add a sandbox
   company** (US, QuickBooks Online Plus).
2. In the test Chrome profile the e2e harness uses, sign in to the sandbox company once. The agent never types a
   password; see "Signing in" below.
3. Put the sandbox's company URL in `infra/test-apps/.env` as `QBO_SANDBOX_URL` (not committed), and note it
   is a sandbox. **No password goes anywhere in the repo.**

## Signing in
ProcessLens never enters passwords. The tests run with a Chrome profile that is already signed in:
- `PROCESSLENS_E2E_PROFILE` points the harness at a persistent profile directory under `.cache/qbo-profile/`
  (gitignored), instead of a throwaway one. Add that switch to `tests/e2e/conftest.py`'s `context` fixture; default
  off, so every other test is unchanged.
- `tests/e2e/qbo_signin.py` opens that profile headed so the owner can sign in by hand once, and closes it.
- **If the session has expired,** the tests skip with "Sign in to the QuickBooks sandbox again: run
  `python tests/e2e/qbo_signin.py`". They never fail and never try to sign in.

## The tests (`tests/e2e/test_qbo_*.py`, marked `e2e` and `live_sandbox`; CI never runs them)
1. **`test_qbo_customer_golden.py`:** demonstrate **+ New → Customer** → display name, email, company → Save. A
   four-row sheet, where one email already exists in the sandbox's demo data. Every row is `verified` or `skipped`,
   with no duplicate customer, and a second run creates nothing.
2. **`test_qbo_invoice_golden.py`:** **+ New → Invoice** → customer → product/service line → qty → rate → **Save**
   (not "Save and send": nothing is emailed). Three rows. Each customer gets exactly one new invoice with that line.
   Read it back through the QuickBooks UI's invoice list, or through the Accounting API if the sandbox has an OAuth app
   (optional, and say which you used).
3. **`test_qbo_bill_golden.py`:** **+ New → Bill** → vendor → category line → amount → Save. Three rows, one bill each.

**Cleanup:** each test deletes nothing in the UI. Instead, every value it creates carries a run-unique suffix
(`PL071-<date>-<n>`), so reruns never collide, and the report lists what was created. Sandbox data can be reset from
Intuit's dashboard.

## When something fails
At most **3 runs** per test. A product bug (recorder, compiler or runner) is a finding: mark that test
`xfail(strict=True)` with the parked reason and failing step, and write the smallest product change that would fix it.
QuickBooks uses heavy custom widgets (grid lines, typeahead pickers, React portals), so expect findings like the Odoo
order lines. Write each one up precisely.

## Limits (non-negotiable)
- **Only the sandbox company.** If `QBO_SANDBOX_URL` doesn't contain `sandbox`, or the page header doesn't show
  Intuit's sandbox marker, the tests refuse to run.
- **Never** type a password, never press "Save and send", and never touch bank feeds, payments or payroll.
- **Files:** the three tests, `tests/e2e/qbo_signin.py`, `tests/e2e/conftest.py` (the profile switch only),
  `tests/e2e/real_apps.py` (QBO helpers), `fixtures/demo/qbo-*.csv`, `.gitignore` (`.cache/qbo-profile/` if `.cache/`
  isn't already ignored), `infra/test-apps/.env.example` (the `QBO_SANDBOX_URL` name only, no value), your report.
  No product code.
- **Before each run:** a fresh `npm --prefix apps/extension run build`.
- **Gates:** the full `.venv\Scripts\python -m pytest -q -p no:cacheprovider` (the new tests are deselected without
  `PROCESSLENS_E2E=1`), `ruff check .`, `ruff format --check .`.
- **Stop rules:** no sub-agents · time box 90 minutes · every command 10-minute timeout or less · stop after 2
  identical failures. If the owner hasn't done the setup above, stop at once and say so.
- **Windows:** never use `2>&1` or the PowerShell `&` call operator. Scratch files go only in `.cache/`.
- **Git:** conventional commits, no AI attribution, never push to `main`.
- **When done:** write `internal/agent/reports/PL-071.md`, push, and stop.
