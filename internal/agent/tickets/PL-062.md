# PL-062: The workflow editor (rename, remove, change where a value comes from, change the save's check)

Owner: T2 (DeepSeek, second tab) · Reviewer: T1 · Size: **large, 4 parts** · Branch `pl-062` · Worktree
`C:\Users\vasup\process-lens\.worktrees\deepseek2` · Web and one API route.

## Why
The brief's third screen is a workflow editor. Today `apps/web/src/pages/TaskDetail.tsx` shows a task's steps read
only (its own comment says "the editor arrives in a later ticket"). Without an editor, the only fix for a wrong step
is to teach the whole task again, which is the "mental gymnastics" the owner doesn't want.

Recipes are immutable once pinned by a run (`internal/AGENTS.md` §4). So **an edit never changes a stored
version.** Saving writes the edited document as the workflow's next version through the existing
`POST /api/v1/recipes` (`services/api/recipes.py`), which validates against the schema and refuses a commit step
without `assert_after`. Runs already started keep their pinned version.

## The fix
1. **The edit model** (`apps/web/src/lib/editRecipe.ts`, new, pure functions, no React). Each returns a new document
   or a refusal sentence:
   - `renameStep(doc, stepId, name)`: 1–120 characters.
   - `removeStep(doc, stepId)`: refused for a commit step ("This is the step that saves; it can't be removed"), and
     for a step another step refers to (a branch or `goto` naming its id; read `packages/recipe/schema` and
     `internal/docs/RECIPE_SPEC.md` for every field that names a step id). Removing the last step is refused too.
   - `setValueSource(doc, stepId, source)`: for a `fill` or `select`, switch between a spreadsheet column (one of
     `meta.input_schema`'s columns) and fixed text. Never AI.
   - `setSaveCheck(doc, stepId, check)`: for a commit step, set `assert_after` to one of "the page shows this text"
     (`text_visible`), "the address becomes" (`url_matches`, given as a path the person types and escaped into a
     pattern), or keep what was recorded. The timeout stays.
   - `diffSummary(before, after)`: plain sentences for the change reason, for example "Renamed step 3; the save is
     now checked by the address".
2. **The page.** `TaskDetail.tsx` gets an **Edit steps** button (secondary; the primary action stays Run).
   - **Edit mode:** each step row gets Rename (inline input), Remove (with the refusal sentence shown on the row
     when it is refused), and for a fill or select a "Comes from" control (column dropdown or fixed text). The save
     step gets "How we know it saved".
   - **Save** and **Cancel** sit on the same screen as the steps (the owner's rule: the action is where the problem
     is). Save posts to `/api/v1/recipes?workflow_id=…&change_reason=<diffSummary>`; a 422 shows the server's
     problems in plain words on the page, and nothing changes.
   - **After a save,** the page shows the new version number and "Runs already started keep the old steps."
   - Light theme, gold accent, `DESIGN.md` §7 motion and focus, usable at 400 px. No engine words: "step", "saves",
     "column" are fine; "recipe", "assert", "selector" and "rung" never appear (the forbidden-word test covers it).
3. **The task points at the newest version.** Check what `GET /api/v1/tasks` returns as `recipe_version_id` after a
   new version is stored. If it already returns the latest, change nothing and say so in the report. If not, fix the
   read in `packages/ledger/reads.py` (`list_tasks`) so a task runs its latest version, with a test.
4. **The editor never touches targets.** Rename, remove, the value source and the save check are the whole scope.
   Element targets (`targets`), reordering and adding steps are out: say so in a one-line note under the editor
   ("To change what a step clicks, teach that part again").

## Tests first (red before the fix)
- **vitest, `editRecipe`:** each operation's happy path; every refusal (the commit step, a referenced step, the last
  step, an unknown column, an empty name); the edited document still has an `assert_after` on every commit step;
  `diffSummary` sentences.
- **vitest, page:** Edit, rename, Save posts the right body and the change reason; a 422's problems appear on the
  page; Cancel restores the steps; the forbidden-word test covers edit mode.
- **pytest, API** (`tests/api`): posting an edited document stores version N+1 with the change reason; version N is
  unchanged; and, per part 3, the task's `recipe_version_id` is the new one.
