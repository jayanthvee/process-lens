# PL-052: An extension coworkers can install, with a fixed id, pointed at the hosted ProcessLens

Owner: T2 (DeepSeek) · Reviewer: T1 · Size: **medium, 3 parts** · Branch `pl-052` · Worktree
`C:\Users\vasup\process-lens\.worktrees\deepseek2` · **Extension build and docs only.**

## Why
Coworkers will use ProcessLens hosted on Railway (PL-051). Today the extension has three problems for that:
- Its **id changes with the folder it is loaded from**. The API pins `PROCESSLENS_EXTENSION_ID` and refuses any other
  origin, so every coworker's copy would be refused.
- Its default address is `http://127.0.0.1:8000` (`DEFAULT_HUB_URL` in `apps/extension/src/popup/popup.ts`), so each
  person would have to type the hosted URL.
- There is no file to hand someone.

## The fix
1. **A fixed id.** A Chrome extension's id comes from the manifest's `key` (the public key).
   - Add `scripts/make-key.mjs`: it generates an RSA 2048 key pair with Node's `crypto` and writes the **private** key
     to `private/extension-key.pem`. `private/` is gitignored; check with `git check-ignore`, and refuse to write if
     it isn't ignored.
   - It prints the base64 public key (DER, SPKI) and the extension id it gives: the first 32 hex characters of the
     SHA-256 of the DER, with `0-9a-f` mapped to `a-p`.
   - The build reads the public key from `apps/extension/extension-key.pub` (committed; it's public) and puts it in
     `dist/manifest.json` as `key`. With no key file, the build stays as today, so the e2e harness keeps its own id.
   - `npm run extension-id` prints the id from the committed public key.
   - **Never** commit the `.pem`; add `*.pem` to `.gitignore` as well.
   - The owner runs `make-key` once; you run it in your worktree only to test, and don't commit the generated
     `extension-key.pub`. The owner commits theirs.
2. **The hosted address as the default.** The build takes `PROCESSLENS_HUB_URL` from the environment (for example
   `https://processlens.up.railway.app`) and bakes it in as the default hub address, falling back to
   `http://127.0.0.1:8000`. The popup's address field still lets a person change it. Validate at build time: it must be
   `http(s)://host[:port]` with no path; refuse anything else with one plain line.
3. **A package to hand out.** `npm --prefix apps/extension run package` builds, validates, and writes
   `apps/extension/release/processlens-<version>.zip` (gitignored). The zip holds `dist`'s contents, so Chrome's
   "Load unpacked" works after unzipping. Write `internal/docs/INSTALL-EXTENSION.md`, a one-page guide for a
   coworker: unzip, `chrome://extensions`, Developer mode, Load unpacked, pin it, open it (the address is already
   filled in), Connect. Plus a short section for the owner: run make-key once, set `PROCESSLENS_EXTENSION_ID` on
   Railway to the printed id, and bump `version` in `manifest.json` for each release.

## Tests first (vitest or node test, red before the fix)
- **The id:** the id helper turns a known public key into its known id. Use a fixed test key in the test file;
  generate it once and paste it into the test as a constant, public key only.
- **The key in the build:** with a key file, `dist/manifest.json` has `key`; without one, it has none.
- **The address:** `PROCESSLENS_HUB_URL=https://x.example` gives a popup default of `https://x.example`;
  `https://x.example/path` is refused; unset gives `127.0.0.1:8000`.
- **The package:** `package` produces a zip containing `manifest.json` at its root.
- **No regression:** `npm --prefix apps/extension run check` passes, and the e2e harness's build (no key, no env)
  is byte-identical in `manifest.json` to today's, apart from nothing.
