# PL-018c: The save checks read text inside open shadow roots

Owner: T2 (GLM) · Reviewer: T1 · Size: **small, 1 part** · Branch `pl-018c` · Worktree
`C:\Users\vasup\process-lens\.worktrees\pl-018c`

This is the text half of PL-018b. T1 does the frame half, which is CDP work.

## The bug
`apps/extension/src/executor/assertions.ts` builds three text checks that read only
`document.body.innerText`: `text_visible`, `text_absent` and `text_count_increases`. Text inside an open
shadow root is never part of that string. So:
- **A confirmation inside a web component is never seen.** The save goes to "could not verify".
- **The safety bug:** an error message inside a shadow root reads as absent, so `text_absent` can **pass on a
  page that is showing the error.**

## The change
1. **One shared snippet, `PAGE_TEXT_SOURCE`,** exported from `assertions.ts`. It is a JS expression string that
   evaluates to the page's visible text, with whitespace collapsed exactly as now. It is:
   - the light DOM: `document.body.innerText || document.body.textContent || ""`, as now;
   - **plus every open shadow root**, found with the same walk as `markerExpression` in `executor/page.ts`.
     Nested roots count too. For each root, take the `innerText` (falling back to `textContent`) of each element
     child of the root, skipping `STYLE`, `SCRIPT` and `TEMPLATE`.
   - The parts are joined with a single space.
2. **All three checks use `PAGE_TEXT_SOURCE`.** Nothing else in them changes:
   - the fail-closed empty-string rules stay;
   - the `window.__processLensCounts` baseline logic stays;
   - the normalization stays.
3. **Frames are out of scope.** Don't read iframes.

## Tests first (`apps/extension/tests/executor-assertions.test.ts`; jsdom supports `attachShadow`)
Evaluate the built expression against a jsdom document, as the existing tests do.
- `text_visible` finds text inside an open shadow root, and inside a nested one.
- `text_absent` **fails** when the text is only inside a shadow root. This is the safety test.
- `text_count_increases` counts an occurrence that is added inside a shadow root after the baseline.
- Text in a `<style>` or `<template>` inside a shadow root is not counted.
- All the existing tests still pass, unchanged.
