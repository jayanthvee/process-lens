## Part 1: pausing a run never answers 500 (`services/api/runs.py`)
**The bug.** `POST /api/v1/runs/{id}/pause` on a **queued** run, while another run on the same destination is already `paused`, raises `psycopg.errors.UniqueViolation` on `runs_one_active_per_destination`. That index covers `running` and `paused` (`db/migrations/0002_ledger_hardening.sql:41`). The person sees a server error.

**The fix.**
- In `pause_run_endpoint`, catch `UniqueViolation` around `set_run_status`, roll back, and raise `HTTPException(409, …)`.
- The detail must read in plain words: "Another run of a task on this app is already paused. Finish or cancel that one first."
- Check whether `resume_run_endpoint` can hit the same index, and handle it the same way. Look at `resume_run` in `packages/ledger/runs.py`; a queued resume may not. Report what you found.
- **Do not change the index, the migration or `set_run_status`.**

**Tests first,** in `tests/db/test_runs_api.py`, using its fixtures:
- two runs on one destination, one paused: pausing the queued one answers **409** with that detail;
- the queued run's status is unchanged afterwards;
- the existing pause tests stay green.

- **Commit and push.**

## Part 2: the popup says "refresh this page" when recording can't reach the page
**The bug.** Reloading the extension orphans the content script in every open tab. Pressing **Start recording** on such a tab then records nothing, with no message. The owner lost time on this twice.

**The fix.**
1. **Answer pings.** In `apps/extension/src/content/recorder.ts`, the existing `onMessage` listener (around `incoming?.type === "record:state"`) also answers `{ type: "record:ping" }` with `{ ok: true }` through `sendResponse`.
2. **Ping before recording starts.** Where the service worker starts a recording on the active tab (`apps/extension/src/background/service-worker.ts`), it first sends `record:ping` to that tab with a 1-second timeout.
   - **No answer or an error:** don't start. Set a status warning that the popup shows in place of the steps:
     "**Refresh this page** (press F5), then start recording again. ProcessLens was updated and can't see this page yet."
   - **The page is `chrome://` or the Web Store:** "ProcessLens can't record on this page. Open your app's page first."
3. **The popup shows the warning** with the popup's existing warning style (`apps/extension/src/popup/`). It needs no new button: after refreshing, the person presses Start recording again.

**Tests first** (vitest, next to `recorder-session.test.ts` and the popup tests, with the existing chrome stubs):
- a tab that answers the ping starts recording;
- a tab that throws "Receiving end does not exist" doesn't start, and the status carries the refresh warning;
- a `chrome://` tab gets the "can't record on this page" line;
- the popup renders the warning text.

- **Commit and push.**
