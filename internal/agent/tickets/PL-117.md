# PL-117: a sign-in saves nothing; plain stop words; let go of the tab while a run waits

Owner: T2 (DeepSeek) · Branch `pl-117` (from `main` at a8cc554) · Reviewer: T1

## Why (owner's Goodlabs run 21400545, 2026-10-27)

With PL-116 the busy Continue button was waited on and clicked (2:30:24). The run then parked at
2:30:32: `the page never went to a URL matching "/home/" within 8 seconds`. The saved recipe was:

1. navigate /login
2. fill email
3. click Continue, **`commit: true`, `assert_after: {url_matches: "/home/", timeout_ms: 8000}`**
4. `sign-in-finished`: `wait_for` url `/home/dashboard…`, 90 s (PL-113 S2). The Gmail code is read
   and typed here.

Continue leads to the code page, not to /home/. Step 3's check could never pass in 8 s, so step 4,
where the code is typed, never ran. While teaching, the code was typed for the owner and the page
reached /home/, so the compiler took that landing as Continue's result.

A sign-in also adds nothing anywhere, yet it ran as a commit with the email as its
never-add-twice key. Once one run finished, every later sign-in with that email would be "already
done".

Also on the same screen:
- `I checked Odoo and it isn't there` (`apps/web/src/pages/needsHelpActions.ts:17`) is hard-coded
  to Odoo.
- The reason is the runner's raw sentence (`services/runner/check_words.py:60`).
- "if the row is there, Dismiss it" is spreadsheet wording on a sign-in.

Separately, after any run Chrome's bar `"ProcessLens Recorder" started debugging this browser`
stays on every window. The run was paused waiting for the owner, and the extension keeps the
debugger attached until the command session goes idle (`service-worker.ts` ~1018).

## Change

1. **A sign-in task saves nothing.** When the compile is a sign-in (`options.sign_in`), it is
   compiled as PL-112's "Nothing gets saved" (`commit_step_ids == []`): no step has `commit`, no
   step has an inferred `assert_after` landing check, and the record goes `filling -> verified`
   through the read-only path when `sign-in-finished` passes. `sign-in-finished` (90 s) is the only
   check that the sign-in finished. A sign-in recipe whose landing could not be seen keeps today's
   warning.
   - The ledger must not treat a finished sign-in as "already done" on the next run with the same
     email: prove in a runner test that two runs of the same sign-in row both run their steps.
     Don't change `guard_record_transition()` or the migrations. If this can't be done without
     them, stop and say so in the report.
   - Teaching screen: a sign-in does not show "The Continue click saves your work. Change".
2. **A sign-in that never finishes says so plainly.** When `sign-in-finished` times out, the row's
   sentence is "The sign-in didn't finish: the site never got past the code page." (or "…never
   reached <landing words>" when it isn't on a code page). There is no "if the row is there,
   Dismiss it" and no destination checkbox on a sign-in row: just **Try again**.
3. **The destination checkbox names the site.** `DESTINATION_CHECK_LABEL` uses the task's site name,
   as PL-115 shows it on cards (e.g. "I checked goodlabs.com and it isn't there"), never a fixed
   app name.
4. **No raw URL sentences on screen.** A stop whose reason is a `url_matches` check shows "The page
   didn't move on after <step name> within N seconds." No regex, slashes or the word URL.
5. **Let go of the tab while a run waits.** When a run pauses (parked row, approval, canary, code
   window, daily cap) or ends, the extension detaches the debugger, so Chrome's bar goes away.
   Resume / Try again / Go ahead attach it again before the next step. Pausing must not abort the
   run. The browser-side detach watcher must not take our own detach for a person pressing Cancel
   (see `releaseDebugger`'s ordering).

## Tests (write first, failing, then fix)

- Compiler: a sign-in compile (the owner's three steps + `sign_in_after_path`) has no `commit` and
  no `assert_after` on the Continue click, and ends with `sign-in-finished`. A non-sign-in compile
  is unchanged.
- Runner: a sign-in row whose `sign-in-finished` passes ends `verified` with no `committed_keys`
  row. A second run of the same row runs its steps again. A timeout parks with item 2's sentence.
- Web: the sign-in row shows no destination checkbox and no Dismiss advice. The checkbox label on
  a normal task names its site. No `URL matching` text appears on any run screen.
- Extension: a run that pauses detaches the debugger exactly once, and Resume attaches before the
  next step. Our own detach does not abort or mark the run as cancelled by the person.

## Stay out of

needed; say why in the report).
