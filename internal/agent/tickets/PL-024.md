# PL-024: Teach, spreadsheet upload, column matching, Try one row and Run, from the web app

Owner: T2 · Reviewer: T1 · Depends on: PL-023 (merged), PL-025 (merged) · Design: `internal/docs/DESIGN.md`,
`internal/docs/design/demo/CLAUDE-DESIGN-PROMPT.md` (steps 2–8 are the target flow)

## Why
Today a task is taught from the popup alone, and a run needs an input batch inserted by hand through SQL. A person
must be able to go from "I have a spreadsheet" to "the rows are in the app" without leaving the web app.

## Requirements
1. **The API.** Everything is tenant-filtered and follows `internal/docs/sql-patterns.md`.
   - **`POST /api/v1/batches`** (multipart: `workflow_id`, `file`).
     - Accepts `.csv` and `.xlsx` (`openpyxl`, pinned). At most 2,000 rows and 5 MB.
     - Creates `input_batches` plus its rows exactly as `tests/e2e/conftest.py` does today; move that insert into
       `packages/ledger`, so both use one function.
     - Returns `batch_id`, `row_count`, `columns`.
   - **`GET /api/v1/batches/{id}/check?recipe_version_id=`.** Matches the spreadsheet's columns to the recipe's
     `meta.input_schema` columns, then checks each row against the recipe's precheck rules without touching the
     browser. Returns:
     - `mapping`: for each recipe column, the chosen spreadsheet column, a `confidence` (`exact`, `close` or
       `none`), and the alternatives;
     - `rows_ok`, plus `rows_need_a_look`, each with a row number and one plain reason ("No email").
   - **How matching works** (deterministic, no LLM):
     - normalise names: lowercase, strip, collapse non-letters to `_`;
     - an exact match comes first;
     - then token overlap, plus a small synonym table (`email`/`e-mail`/`mail`, `phone`/`mobile`/`tel`,
       `company`/`organisation`/`organization`/`account`, `name`/`full_name`/`contact`);
     - then a **value match**: a spreadsheet column whose row-1 value equals the recipe's recorded sample value
       for that column is `exact`.
   - **`PUT /api/v1/batches/{id}/mapping`** saves the mapping a person confirmed. Run creation applies it, renaming
     row keys to the recipe's columns when the run's records are created. The mapping lives on the batch;
     **recipes are never mutated**.
   - **`POST /api/v1/runs`** stays as it is. "Try one row" is `mode: "preview"` with the batch limited to its
     first OK row. Check how `preview` behaves today, and if it doesn't run exactly one record, add
     `limit: 1` to the request.
   - **No migration unless needed.** If the mapping needs a column, add `db/migrations/0005_batch_mapping.sql`,
     with only `input_batches.column_mapping jsonb`.
2. **The web app (`apps/web`).** Same tokens and vocabulary as PL-023, and no engine words on screen.
   - **Task page → "Run this task"** opens a three-step flow on one page (`/tasks/:id/run`):
     1. **Add your spreadsheet:** drag and drop or browse. It shows "20 rows, 8 columns".
     2. **Check it:** a table with one row per task column, showing "Your column" (a select) and a status chip
        (Matched / Check this / Not found).
        - Below it: "18 rows ready · 2 need a look", listing the reasons.
        - **Continue** is enabled only when every required column is matched.
     3. **Try one row:** shows the first ready row as "About to add: …", from the row's values.
        - **Try it** starts a preview run, and the screen follows it live (poll every 2 s) until the row is done
          or needs help.
        - Then **Run the other 19**, which starts the batch and goes to that run's page.
   - **"Teach a new task"** on the Tasks page and on Home opens `/teach`. It tells the person, in 3 plain
     steps, to open the app in Chrome, press **Start teaching** in the ProcessLens extension, and do one row by
     hand.
     - The page polls `GET /api/v1/tasks`, and when a new task appears it says "Got it: <name>" and links to it.
     - (Teaching itself stays in the extension.)
3. **Tests.**
   - pytest: upload CSV and XLSX; the size and row limits; matching (exact, synonym, value match, none); the
     check's reasons; a mapped run whose records carry the recipe's column names; tenant isolation.
   - vitest: the three steps render; Continue is disabled when a column is unmatched; no engine words.

## Not in scope
Editing a recipe; inline fixing of spreadsheet cells; documents or OCR; admin.
