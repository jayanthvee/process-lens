# PL-095: The check flags values that cannot be right, and names columns the way the file does

Owner: T2 (DeepSeek) · Branch `pl-095` (from `main`) · Reviewer: T1

## Why

The pilot's messy files, run on Render (2026-10-24), saved bad values and reported them verified:

- a product price of `free` was saved as 0.00, and `-5.00` was saved as a negative price;
- a lead with the email `gus.hale.at.example` was created.

The check also confused the person twice:

- the product task's key column is called `search` (the recorded search box) and the file's column is `SKU`; the automatic match left it empty;
- a repeated SKU said "Same search as row 12".

A recorded task has no field types: every field is `{"type": "string", "example": ...}` (`packages/compiler/compiler.py`, `_derived_field`). The example value the person typed is the only type information there is, so the check reads the kind from it.

## Change

All in `services/api/batches.py`. No model, no network: the batch check stays deterministic (D-017).

1. **A field's kind comes from its example.**
   - *email*: the example has the shape `local@domain.tld`, with one `@` and no spaces.
   - *number*: the example is a plain number, optionally with a currency sign (`$ € £`), thousands commas and one decimal point. Examples with internal spaces, a leading `+`, or more than 6 digits and no decimal point are **not** numbers (they are phones and IDs).
   - Anything else, or no example: no check.
2. **A value that does not fit its kind needs a look** (a reason in `_row_reasons`, after the rule reasons and before the duplicate reason):
   - number column, a value that is not a number: `“free” isn't a number`
   - number column, a value below zero: `“-5.00” is below zero`
   - email column, a value that is not an email: `“gus.hale.at.example” isn't an email`
   - A blank value is never judged by this; blanks belong to the `missing` rule.
   - `$92`, `1,232.00` and `0` are numbers and fine.
3. **Match a column by the example's shape.** In `_rank`, after the exact value match: when row one's value has the same shape as the example (letters → `A`, digits → `9`, runs collapsed, separators kept, e.g. `PL-CHR-2001` and `PL-KEY-5002` are both `A-A-9`), rank it as close (2). Only a non-empty example takes part.
4. **Name a repeat after the file's own column.** `_duplicate_reason` says `Same SKU as row 1` using the spreadsheet column mapped to the key's task column. Fall back to the task column's label when it is not mapped.
