# PL-093: A Connect overtaken while it waits on the hub opens nothing

Owner: T1 · Branch `pl-093` (from `main`)

## Why

After PL-092 was deployed, the hosted smoke test still failed intermittently: a run claimed seconds after a Chrome connected heard 60 s of silence and paused `executor_disconnected`. Watching the hub's attached sessions and the extension's own state during the runs showed the cause.

- The popup starts an auto-connect as soon as it opens. Over the internet, pairing (`POST /executor/sessions`) takes about a second; locally it is instant, which is why only the hosted test failed.
- A Disconnect or a second Connect pressed while that pairing is in flight did not stop it. When the hub answered, the overtaken Connect stored its session and opened a socket anyway: a zombie.
- PL-092's `dropSocket` runs at the start of Connect, so it never sees a socket that is still on its way. Whichever socket attached last won at the hub (PL-092 retires the others), and when that was the zombie, the extension's current socket was retired and the worker talked to a session the extension no longer listened to.

## Change

`CommandSession` numbers every Connect and Disconnect (`pairingAttempt`).

- After every `await` in `connect`, an attempt that is no longer the newest returns quietly. It opens no socket, stores no session, and does not change the state the newer attempt owns, and that includes its own error paths.
- `disconnect` bumps the number, so a Connect still waiting on the hub opens nothing.
- Connect also drops any current socket right before it opens its own.

## Tests

`apps/extension/tests/command-state.test.ts`, "two Connects in flight at once": the hub's replies are held and released in a chosen order. All 4 fail without the change.

- the older reply arrives first: one socket, for the newer session;
- the older reply arrives last: the same;
- a Disconnect while pairing: nothing opens and the session stays idle;
- an overtaken Connect that then fails does not knock the newer one back to idle.

Proof on Render: `tests/e2e/test_hosted_smoke.py` builds its extension from the branch, so it was run against the deployed API before merge.
