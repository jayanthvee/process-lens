# PL-119: a run types the new emailed code, never one already used

Owner: T2 (DeepSeek) · Branch `pl-119` (from `main` at c971e2c) · Reviewer: T1
Read `internal/docs/WORKING-RULES.md` first.

## Why (owner's Goodlabs run fc15039b, 2026-10-28)

Timeline (UTC):
- About 01:17:2x: while teaching, Goodlabs emailed code A, and ProcessLens typed it. The task was saved at 01:17:53.
- 01:18:15: the run starts. Continue is clicked, and the code page shows about 01:18:20. Goodlabs sends code B.
- The run reads Gmail at once. B has not arrived yet. A is the only code inside the window, so A is typed. Goodlabs answers "Verification failed".
- The run then paused with `code_required` / `none`. The owner had opened B in Gmail, and the Gmail feed lists only unread mail.

Cause: `findCode` (`apps/extension/src/shared/email-code.ts:99`) accepts any message received after
`since - CLOCK_SLACK_MS`, and `CLOCK_SLACK_MS` is 60 s. `since` is when the code page appeared
(`codePageAt` in `command-session.ts`). When the session didn't see the code page, it is now minus
3 minutes (`CODE_PAGE_FALLBACK_MS`). A code emailed during teaching or a previous attempt less than
a minute earlier counts as fresh. It's also the newest code until the new email lands, so it is
typed at once.

## Change

1. **A code ProcessLens typed is never typed again.**
   - The service worker remembers each code it types, during teaching or a run, as a salted hash: a random salt made when the worker starts, kept in memory only. Entries expire after 15 minutes.
   - A later look skips any message whose code matches. The code itself is never stored, logged or sent anywhere.
2. **Only a code that arrived after the code page counts.**
   - `CLOCK_SLACK_MS` goes from 60 s to 10 s.
   - When the session never saw the code page, `since` is the time the enter-code command arrived, minus 10 s, not 3 minutes back.
   - The teaching watch (`CODE_EMAIL_SLACK_MS`, 30 s before the last action) is unchanged. It runs before the person acts on the page.
3. **A refused code gets one more look.**
   - If, after typing, the page still asks for a code (`cleared` is false), that code counts as used (item 1).
   - ProcessLens looks again, for the rest of the same look time, for a newer code, and types it once.
   - If that one is refused too, or none arrives, the run pauses exactly as today.
   - Never more than two codes per code page.
4. **The pause says why the code wasn't found.** The `none` sentence becomes:
   "No new code email arrived. If you already opened it in Gmail, ProcessLens can't see it — type the code here."
