# PL-065: Each row on the results page shows its steps, how long each took, and where it stopped

Owner: T2 (DeepSeek) · Reviewer: T1 · Size: **medium, 3 parts** · Branch `pl-065` · Worktree
`C:\Users\vasup\process-lens\.worktrees\deepseek2` · Ledger read, API and web.

## Why
The brief's execution monitor and results screens should show what happened inside a row. `SYSTEM_DESIGN.md` asks
for step timings. Today `apps/web/src/pages/RunDetail.tsx` shows each row's outcome and reason only. The data is
already there: `step_events` (`db/migrations/0001_init.sql`) holds one row per step attempt, with `step_id`,
`attempt`, `started_at`, `ended_at`, `outcome`, `locator_rung` and `error`. Screenshots are out of scope (none are
captured yet).

## The fix
1. **Read** (`packages/ledger/reads.py`, following `internal/docs/sql-patterns.md`, tenant-filtered):
   `record_steps(conn, record_id, tenant_id)` returns that row's step events in order: step id, attempt, started,
   ended, outcome, and a short error message. **Never `observed`**, which can hold the row's values, and never the
   full error JSON; only its `message` (or `reason`) string, cut to 200 characters. Append the function at the end of
   the file.
2. **API:** `GET /api/v1/runs/{run_id}/records/{record_id}/steps` (`services/api/runs.py`), returning
   `[{step_id, step_name, attempt, outcome, seconds, error}]`.
   - `step_name` comes from the run's pinned recipe (look the step id up in its `steps`, nested branches included),
     falling back to the id.
   - `seconds` is `ended - started`, rounded to 0.1, or null while the step is running.
   - A 404 if the record isn't in that run, or in the caller's tenant.
3. **Web** (`RunDetail.tsx`): each row gets a "Show steps" disclosure (closed by default) that loads that route and
   lists the steps, one line each.
   - **The line:** the step's name, a plain outcome word (done / skipped / stopped here), the time ("0.4 s"), and for
     the step that stopped the row, its error sentence. A retried step shows "tried 2 times".
   - **Polling:** while a run is open, an expanded row refreshes with the page's existing poll, which makes this the
     execution monitor's live view.
   - **Style:** light theme, gold accent, existing `.times`-style classes where they fit, usable at 400 px, no
     engine words (the forbidden-word test covers it: "rung", "selector" and "assert" must not appear).
