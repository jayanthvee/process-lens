# PL-059: A save from a "new" page is checked by the address it lands on

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Size: **small, 1 part** · Branch `pl-059` · Worktree
`C:\Users\vasup\process-lens\.worktrees\deepseek` · **Compiler only.**

## Why
The Odoo quotation golden now records, compiles and reaches Save on every row. It parks at the save check:

> "Ridgeline Outfitters" did not appear one more time within 8 seconds

The quotation's number isn't pinned any more (PL-049), so the compiler fell back to "the new record's name appears
one more time" (`_infer_assertion_from_fills`). On a quotation the customer's name is already on the page before
Save, so the count never goes up. The durable signal is the address: Odoo saves `/odoo/sales/new` and lands on
`/odoo/sales/42`. Twenty and most apps do the same with `/new`, giving `/<id>`.

## The fix
In `compile_recording`, for a commit step with no supplied assertion, the order becomes:
1. the recorded observation, as today (PL-049 already drops generated numbers);
2. the recorded navigation, as today (`after_url` gives `path_pattern`);
3. **new:** when the save's own page path ends in `/new` (with or without a trailing slash or a query string) and no
   `after_url` was recorded, use `url_matches` with the same path and `/new` replaced by `/[0-9]+` (also allow a UUID
   shape `/[0-9a-f-]{8,}` when the app uses UUIDs; one pattern that accepts both is fine). Build it with the
   existing `path_pattern` / `origin_of` helpers so its shape matches the other URL checks. Add the warning: "this
   save is checked by the page moving from /new to the saved record";
4. the fill-name fallback, as today, only when none of the above applies.

## Tests first (pytest, red before the fix, new `packages/compiler/tests/test_pl059.py`)
- **The quotation:** save on `http://127.0.0.1:8069/odoo/sales/new`, with no observation and no `after_url`, gives
  a `url_matches` that matches `/odoo/sales/42` and doesn't match `/odoo/sales/new`.
- **A UUID app:** `/objects/companies/new` matches `/objects/companies/6f1c2a9e-0b7d-4c1e-9a55-3c2d1e0f9a11`.
- **Recorded navigation wins:** a recorded `after_url` still wins.
- **Observations win:** a real (non-generated) `text_visible` observation still wins.
- **No `/new`:** a save on a page whose path has no `/new` still gets the fill-name fallback.
- **PL-049 unchanged:** an `S00001` observation on a `/new` page now gets the `/new` URL check, not the fill
  fallback.
- **No regression:** the existing PL-044 and PL-049 tests pass unchanged. If one has to change, say why in the
  report.
