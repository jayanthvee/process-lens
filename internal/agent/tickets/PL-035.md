The dashboard's **Apps** link (`/apps`) shows "Coming soon". DESIGN.md §6 says what it should show: "Odoo, Twenty
…; the sites each task may use; the Chrome extension's status". This ticket builds it as a **read-only** page. **No
browser tests**: the API tests and vitest cover it.

## Part 1: the API (`GET /api/v1/apps`)
- **A new read, `list_apps(conn, *, tenant_id)`,** in `packages/ledger/reads.py`.
  - Copy `_LIST_TASKS` / `list_tasks`: the same tenant filter, and archived workflows left out.
  - It returns **one row per origin** found in `workflows.allowed_origins`, with:
    - `origin`, e.g. `http://localhost:8069`;
    - `tasks`: each task's `id` and `name`, sorted by name;
    - `last_run_at` and `last_run_status`: the newest run of any of those tasks, or `null`.
- **A new route file, `services/api/apps.py`**, mounted in `services/api/main.py` like `home.py`. It takes the same
  `tenant_id` query parameter as `/tasks`.
  - It adds `name`, worked out in Python:
    - a host containing `odoo`, or port `8069` → "Odoo";
    - `twenty`, or port `3000` → "Twenty";
    - otherwise, the host without the port.
  - It adds `host`, which is the host and port: `localhost:8069`.
- **The response** is exactly `[{name, host, origin, tasks: [{id, name}], last_run_at, last_run_status}]`, sorted by
  `name`. No row contents.
- **Tests first,** in `tests/api/test_apps_api.py`, with the fixtures of `tests/api/test_home_api.py`:
  - two tasks on one origin give one app with both tasks;
  - an archived task is left out;
  - another tenant's tasks never appear;
  - no runs gives `last_run_at: null`;
  - the newest run wins;
  - the response keys are asserted exactly;
  - the name rules have their own unit test.
- **Commit and push.**
