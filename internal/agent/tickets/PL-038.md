# PL-038: Act where the problem shows — Approve in "Try one row", Try again on the run page

Owner: T2 (DeepSeek Flash) · Reviewer: T1 · Size: **small, 2 parts** · Branch `pl-038` · Worktree
`C:\Users\vasup\process-lens\.worktrees\pl-038` · **Web only:** `apps/web/` (no API, extension or runner changes).

**The rule from the owner, repeated several times:** every action sits on the same screen as the problem or decision it answers, so the person never has to know to go to another page.

In the owner's test on 2026-10-17:
- "Try one row" stopped for approval, but **Approve was only on the run page.**
- A failed row on the run page had **no Try again.** The owner had to know to go to Needs help.

## Part 1: Approve inside the "3. Try one row" card (`pages/TaskRun.tsx`)
1. **Move the approval block into a shared component.**
   - Move the block in `pages/RunDetail.tsx` (the `{/* PL-015's approval decision … */}` section, its `decide()` and the operator fetch) into a new **`components/ApprovalPanel.tsx`**.
   - Its props: `{ detail: RunDetailPayload; onDecided: () => void }`. It keeps the exact markup, class names and wording.
   - `RunDetail.tsx` then renders `<ApprovalPanel detail={…} onDecided={run.reload} />`, and its existing tests must stay green unchanged.
2. **Show it in the card.**
   - In the "3. Try one row" card, when `run.data?.open_approval` is set, render `<ApprovalPanel>` in place of the "Live" marker. The card already polls `run` while the run is open.
   - After the decision, `run.reload()`. The card then moves on as it does today: Live, then the outcome, then "Run the other N rows".
3. **Name the wait.** While the preview run is open and no approval is waiting, the card says "Adding this row in the ProcessLens window…" next to the Live marker.
4. **Tests first** (`apps/web/tests/taskRun.test.tsx`, stubbing like the existing tests):
   - a run with `open_approval` shows the values and an **Approve** button inside the card;
   - clicking it POSTs to the approvals path with `decision: "approved"` and reloads the run;
   - **Don't save** POSTs `rejected`;
   - the run page still shows the same panel (`runs.test.tsx` stays green);
   - `engineWordsIn` of the card's text is empty.
- **Commit and push.**

## Part 2: Try again on each row of the run page (`pages/RunDetail.tsx`)
1. **Add the actions to each row.** In "What happened to each row", a row whose state is `parked` or `failed` gets the same two actions as Needs help, **Try again** and **Dismiss**.
   - Reuse `actionGate`, `recordActionLabel` and the requeue/dismiss calls from `pages/needsHelpActions.ts` and `NeedsHelp.tsx`. Don't write a second copy.
   - Move any shared helper into `needsHelpActions.ts` if it currently lives in `NeedsHelp.tsx`.
   - `RecordRow` already carries `id`, `state` and `commit_attempted`.
2. **Keep the safety tick.** A row with `commit_attempted: true` shows the same "I checked Odoo and it isn't there" tick that Needs help shows before Try again is enabled. That is the commit-window safety rule, and it is not optional.
3. **After an action,** reload the records and the run.
   - A run that has finished and gets a row re-queued shows "Running again" while the API reports it open. The existing polling handles this; just make sure the poll restarts when the status becomes open again.
4. **Offer the batch action.** When the run is finished and 2 or more rows can be tried again, show one **Try all N again** button above the table that requeues each of them. Rows needing the tick are excluded and named: "Felix needs a check first."
5. **Tests first** (`apps/web/tests/runs.test.tsx`):
   - a failed row shows Try again, and clicking it calls the requeue endpoint for that record;
   - a `commit_attempted` row keeps the button disabled until the tick;
   - a verified row shows no actions;
   - Try all requeues exactly the eligible rows;
   - `engineWordsIn` is empty.
- **Commit and push.**
