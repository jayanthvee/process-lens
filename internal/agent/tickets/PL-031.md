# PL-031: Make a real person's Odoo recording replayable

Owner: T2 · Reviewer: T1 · Size: medium (6 fixes, each small) · Depends on: PL-027 (merged)

## Why
The owner taught "new lead" through Odoo's **quick-create card** on the CRM pipeline, the way a real person does:
they typed the contact, the dropdown misbehaved, they clicked around and typed it again. T1 replayed that exact
recording (sanitized) on real Odoo, and **all 3 rows parked; nothing was saved.**

The engine was safe, but the recorder kept the fumbling, and the compiler couldn't see when the save had worked.
The recording, with fake values, is `packages/compiler/tests/fixtures/odoo_quick_create_owner.json`. **Every fix
below is tested against that file, with no browser.**

## Fixes. For each one, write its test against the fixture first; it is done when the test passes.
1. **Drop Odoo's "?" help marker from labels.**
   - Odoo renders `<label>Contact<sup>?</sup></label>`, so the accessible name and the label text come out as
     `Contact?`.
   - In the recorder's name and label computation (`apps/extension/src/content/`), leave out `<sup>` and `<sub>`
     children whose trimmed text is `?`.
   - In the compiler, strip a trailing `?` from a recorded label or name when the text before it is a real word.
     That covers recordings already made.
   - Test: the fixture compiles to a column named `contact`, not `contact?`, and every rung reads `Contact`.
2. **A retried field keeps only its last attempt.**
   - When the same target (equal first rung) is filled again before the commit step, drop the earlier fill. Also
     drop every click between the two fills that only touched that field: the field itself, its options, or a
     container around it.
   - Test: fixture steps 2–7 fold away, leaving: New, fill Contact, Create option, Email, Phone, Expected Revenue,
     and Add.
3. **Drop container clicks.**
   - Drop a click whose only meaningful rung is `role: generic` (or css only), and whose name or text contains
     the labels of two or more inputs. That is a click on a group or card, not on a control.
   - Do the same for a click whose targets are **css only** with no role, label or test id (fixture seq 6,
     `div.o_cell…`). That one matched 4 elements on replay and parked every row.
   - The compiler adds a warning for each dropped click.
4. **Don't record what the page typed.**
   - A fill whose value equals the value of a different field filled just before it, and that arrived with no
     keystrokes on its own target, is `page_set`: drop it.
   - Fixture seq 11 is Opportunity = the contact name, which Odoo copies in itself.
   - If the recorder can't tell yet, add the keystroke count to the fill event (`apps/extension`) and use it.
5. **A "Create" option must also accept an existing record.**
   - An option click named `Create "<value>"`, where `<value>` is a fill value just typed, compiles to an option
     target templated from the column. The runner accepts the option whose name is exactly `{{row.col}}` first,
     else `Create "{{row.col}}"`.
   - Do this with two rungs in that order; no runner change is needed if the ladder already takes the first rung
     that matches exactly one element. Verify that in a unit test.
6. **A quick-create save must be checkable.**
   - On Odoo's card, Add changes no URL and shows no message. The only evidence is the new card.
   - When a commit click has no observation and no navigation, but one of the fills before it was templated
     from the record key or a required column, infer `assert_after: {"text_visible": "{{row.<that column>}}"}`,
     preferring the record key.
   - Add a warning: "this save is checked by the new record's name appearing".
   - Test: the fixture compiles with no 422.

## Acceptance
- [ ] The fixture compiles to: navigate (if any), click New, fill Contact, click the Create/exact option, fill
  Email, fill Phone, fill Expected Revenue, click Add (`assert_after` text_visible from the contact). That is
  no more than 8 steps, with no `?` in any name.
- [ ] Unit gates pass: `npm --prefix apps/extension run check`, `python -m pytest -q --ignore=tests/e2e` and
  ruff.
- [ ] **T1 replays the fixture on real Odoo**, with one new contact and one existing one, before approving.

## Rules
Tests first. Run only relevant tests while building, and the full gates once at the end. Every command has a timeout
of 10 minutes or less. After 2 identical failures, stop and report. No e2e: T1 runs it.
