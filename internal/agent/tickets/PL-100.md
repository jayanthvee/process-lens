# PL-100: Every tester zip says which build it is

Owner: T2 (DeepSeek) · Branch `pl-100` (from `main`) · Reviewer: T1

## Why

Every release so far was `processlens-0.1.0.zip`. The owner cannot tell an old zip from a new one, and a tester's notes cannot say which build they came from. The version in `manifest.json` has never moved.

## Change

All in `apps/extension/scripts/` and the popup.

1. **`packageExtension({ ..., stamp })`** (`release-lib.mjs`):
   - `stamp` is `{ date: "YYYYMMDD", commit: "<short sha>" }`. When it is not given: today's date (local time), and `git rev-parse --short HEAD` run in the extension's root. If git is not available, the commit is `nogit`.
   - The zip is `processlens-<version>-<date>-<commit>.zip`.
   - The **built** `dist/manifest.json` gets `"version_name": "<version> (<date> <commit>)"`. Chrome shows `version_name` on chrome://extensions. The source `manifest.json` is not changed by a build.
   - `packageExtension` must honour `options.dist` (the tests build into `.cache/`, never the real `dist/`).
2. **`bumpVersion({ root })`** (`release-lib.mjs`): adds one to the patch number of `version` in both `manifest.json` and `package.json`, and returns the new version. A version that is not `N.N.N` throws an error naming the version, and changes neither file.
3. **`npm run bump`** in `apps/extension/package.json`: runs `bumpVersion` on the real root and prints the new version.
4. **Popup:** show the build in small grey text at the bottom of the popup, e.g. `ProcessLens 0.1.1 (20261025 c8abcb3)`, read from `chrome.runtime.getManifest().version_name`, falling back to `version`. Add a popup test for it.
5. `scripts/package.mjs` prints the zip path as it does now. Nothing else about the access code or hub address changes.

## Tests

`apps/extension/tests/release-version.test.ts` (written by T1; all 5 fail now). Do not change these tests.

The existing test "is named for the manifest's version" in `tests/extension-release.test.ts` expects the old name. Update that one test to the new name and say so in the report.
