# PL-104: The work window can't be hidden by accident, and says what it is

Owner: T1 · Branch `pl-104` (from `main`)

## Why

On the pilot call Chrome refused the separate work window, so the run used a tab in the person's own
window. Every time they looked at the run page, that tab went to the background, stopped drawing,
and the run paused ("window hidden") or failed ("Couldn't find Contact"). The blank tab it opens
first has no words on it, so it looks broken.

## Change

1. **Always its own window.** `bindActiveTab` tries the normal window, then a minimized-safe size
   beside the person's window. If Chrome refuses every window, the run does not start in a tab: the
   run says "Chrome didn't let ProcessLens open its own window. Click Try again." with the button
   right there.
2. **Never behind the person.** The work window is not focused-stealing, but if it is minimized or
   fully covered, the run pauses with "The ProcessLens window is hidden. Click Show it." and Show it
   brings it forward and resumes. No silent failures from a hidden page.
3. **It says what it is.** The first page in the work window is a small extension page, not
   `about:blank`: "ProcessLens works in this window. Leave it open; you can keep using your other
   windows." The run then navigates from there.
4. **The side panel (PL-105) shows** "Working in the ProcessLens window" with a Show it button while a
   run is going.

## Tests

Written while building (T1): `bindActiveTab` refusing to fall back to a tab, the hidden pause and
Show it, the first page's address. Plus one e2e: the person clicks back to their own window during a
run and the run keeps going.
