# PL-061: Show the real manual-versus-automated time

Owner: T2 (DeepSeek) · Reviewer: T1 · Size: **medium, 3 parts** · Branch `pl-061`, built on `pl-060` · Worktree
`C:\Users\vasup\process-lens\.worktrees\deepseek` · API, ledger reads and web.

## Why
PL-060 makes each recipe remember `meta.manual_seconds_per_row`: how long the person took to do one row by hand while
teaching it. The screens still use a guess of 3 minutes per row (`services/api/home.py`,
`apps/web/src/pages/RunDetail.tsx`, `lib/words.ts`). The brief's time comparison is "by hand vs ProcessLens"; this
ticket makes it real and puts it on the two screens the PM will look at.

## The fix
1. **Ledger reads** (`packages/ledger/reads.py`, following `internal/docs/sql-patterns.md`):
   - per finished run: the done-row count, the run's wall clock, and the pinned recipe's
     `meta.manual_seconds_per_row` (read from `recipe_versions.recipe` with `->`). It may be absent.
   - per week (Home): the sum over the window of done rows × that recipe's manual seconds, using **180 seconds** when
     a recipe has none. Also return how many done rows used the fallback.
   Every query filters by `tenant_id` like its neighbours. `tests/runner/test_sql_separation.py` must stay green, so
   the SQL lives in `reads.py` only.
2. **API.**
   - `GET` home (`services/api/home.py`): replace the 3-minute formula with
     `{manual_seconds, automated_seconds, saved_seconds, estimated_rows}`. `saved` = manual − automated, clamped at 0.
   - The run detail (`services/api/runs.py`): add `manual_seconds_per_row`, `automated_seconds_per_row` (wall clock ÷
     done rows) and `saved_seconds`, all null for an open run or zero done rows.
   - Keep the old field names working, so the existing web tests keep passing until part 3 changes them.
3. **Web.**
   - **Results** (`RunDetail.tsx`): one comparison line under the outcome, for example "By hand: about 2 min 10 s a
     row · ProcessLens: 14 s a row · About 31 minutes saved". If the recipe has no measurement, say "By hand: about 3
     min a row (estimated)".
   - **Home** (`Home.tsx`): the time-saved figure uses the API's `saved_seconds`, with a small "estimated for N rows"
     note when `estimated_rows > 0`.
   - The words go in `lib/words.ts`, in the existing format helpers' style. No engine words (the forbidden-word test
     covers it). Light theme, gold accent, as the rest of the page.

## Tests first (red before the fix)
- **pytest, ledger** (`tests/db` style, real schema):
  - 3 done rows on a recipe with 120 manual seconds and a 60-second run give manual 360, automated 60, saved 300;
  - a recipe without the field uses 180 and is counted in `estimated_rows`;
  - another tenant's runs aren't counted.
- **pytest, API:** the new fields on home and run detail; nulls for an open run.
- **vitest:** RunDetail renders the measured line and the estimated line; Home shows the estimated note only when
  `estimated_rows > 0`; the forbidden-word test passes.
