## Requirements
1. **PRODUCT.md**: problem, users, the ten use cases, success measures from the brief. Written in your own
   words; never copy the brief. Public-safe.
2. **ARCHITECTURE.md**: every component in the repository map, what it owns, and an explicit allowed-dependency
   list (which of apps/, services/, packages/ may import which). Write that list as a fenced YAML block;
   PL-005 copies it into the public `tools/guards/boundaries.yaml` and turns it into CI checks. `services/ai` must be the only importer of model SDKs.
3. **LEDGER_SPEC.md**: states, the exact transition list from the migration (reference it, do not restate SQL),
   the write-ahead sequence around a commit, the recovery procedure, and each invariant mapped to the test
   that will prove it.
4. **AI_BOUNDARIES.md**: the six AI call types, the router and escalation cascade, the data-policy rules
   for personal data, and an explicit list of what AI may never do.
5. **TEST_STRATEGY.md**: test layers, drift injection on demo sites, kill tests, golden sets, and what CI runs.
6. **Design review** in P-001: contradictions, missing invariants, unsafe assumptions, and failure modes
   across SYSTEM_DESIGN, internal/AGENTS.md, and the migration. Each finding: severity, evidence, proposed amendment.
7. Where a fact already lives in a schema, migration, or other doc, link to it instead of repeating it.
8. Git: this ticket touches only the private repo. Commit with `git -C internal ...` and push. Do not run git
   commands in the root folder; T2 is working there.
