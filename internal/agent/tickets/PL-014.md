# PL-014: Connect the runner to the real extension

Owner: T2 · Reviewer: T1 (plan review, then code review and break-it tests before merge) · Depends on: PL-013 (merged) · Phase: C

## Description
Replace the fake browser with the person's real Chrome tab:
- The backend runner (PL-013) sends one command at a time over a WebSocket.
- The extension executes it with the PL-010 executor and reports back.
- The ledger records the outcome exactly as it does with the fake today.

This ticket also adds the safety behaviour a real website needs: challenge and login detection, an origin check on
every step, a clear error when an IT policy blocks the debugger, fresh confirmations, and the destructive-control
guard. It carries the PL-010 executor follow-ups that real pages will hit.

Constitution rules this ticket must hold:
- zero model calls (D-017);
- the backend owns workflow state, and the extension owns none (D-004);
- never bypass a bot check: a challenge pauses the run for a person (rule 19);
- waits are conditions with timeouts.

## Requirements

### 1. The hub (`services/api/hub.py`)
**Two WebSocket endpoints:**
- `/api/v1/executor/ws`, for the extension.
- `/api/v1/runner/ws`, for a runner worker.

**Pairing (attended, single user for now).**
- In the popup, the person presses **Connect**. The extension calls `POST /api/v1/executor/sessions` and receives a
  `session_id` plus a one-time `session_token`, and binds the session to the active tab.
- A worker started with `--executor browser --session <session_id>` is relayed to that session only.

**Security.** Any web page can try to open a WebSocket to localhost, and a page that reached the runner channel
could make the extension click things. So:
- the extension channel requires `Origin: chrome-extension://<extension id>` and the session token;
- the runner channel requires a secret from the server's environment (`PROCESSLENS_RUNNER_SECRET`);
- anything else is refused before a message is read;
- by default the hub listens on 127.0.0.1 only.

**Dumb relay.**
- The hub never interprets, reorders, buffers, or replays a command.
- If the other side is not connected, the hub answers `peer_unavailable` immediately; it does not queue.

### 2. Messages (version them: `protocol: 1`)
**Runner → extension** (`prepare`, `dispatch`, `check`). Each carries:
- `command_id` (unique), `run_id`, `run_record_id`, `lease_epoch`, `expires_at`;
- `step` (values already rendered), `commit`, and `allowed_origins`.

**Extension → runner:**
- `ack {command_id}`: sent the moment a commit's trusted input event has been dispatched, and before waiting for
  anything.
- `result {command_id, status, rung, observed, error}`, where `status` is one of `ok`, `locator_failed`,
  `not_dispatched`, `rejected`, `timeout`, `lost`, `refused`.
- `condition {command_id, passed}`.
- `event {kind, detail}`, where `kind` is one of `detached`, `tab_closed`, `login_required`, `challenge`,
  `policy_blocked`, `off_origin`.

**The extension keeps per-session state (in memory only):**
- the highest `lease_epoch` seen per run;
- the recent `command_id`s;
- the in-flight command.

**It refuses** (`result status=refused`) any command with a lower epoch, a repeated id, or a passed `expires_at`.
It never queues commands while disconnected. After a reconnect, it reports any command that was in flight as
`lost`, and never re-runs it.

**Keepalive.** Exchange a ping at least every 20 seconds while connected, so Chrome does not suspend the MV3
service worker in the middle of a run.

### 3. The extension in command mode
- **Reuse the PL-010 code.** Ladder resolution, hit-tested clicks and CDP input from PL-010, plus a new `check` that
  evaluates a condition with polling up to its timeout.
- **`prepare`** resolves and hit-tests the target with **no input sent**.
- **`dispatch`** performs the action; for a commit it sends `ack` immediately after `mouseReleased` or the last key.
- **Before every command, run these guards in order. Each produces a `result` or `event` and never acts:**
  1. **Origin.** The frame's current origin must be in `allowed_origins`, otherwise `event off_origin`, and the
     record parks.
  2. **Challenge or login page.** If the page shows a challenge, send `event challenge`. Detect these markers: a
     challenge iframe (`challenges.cloudflare.com`, reCAPTCHA, hCaptcha, Turnstile), or a title like "Just a moment".
     If a visible password field appears that is not part of the step, send `event login_required`. Never try to
     solve or bypass either.
  3. **Destructive control** (security model). Refuse a click on a control whose accessible name contains delete,
     cancel, refund, pay or transfer, unless the step sets `allow_destructive_control: true`. Send
     `result refused` with the reason.
- **Debugger attach errors.** If `chrome.debugger.attach()` fails with "Host access is restricted by policy" or
  "Screenshot capture is restricted by policy" (Chrome 155+, managed browsers), send `event policy_blocked` with a
  message a person can act on: "your administrator's Chrome policy blocks ProcessLens".
- **The standalone popup Run** (PL-010 mode) stays available for manual testing, clearly labelled "local test run",
  and never writes to the ledger.

### 4. The real executor and runner changes
**`BrowserExecutor`** implements the PL-013 `Executor` protocol over the runner channel:
- a missing `ack` within the dispatch budget → `lost`;
- `event`s are surfaced to the run loop.

**The run loop maps events:**
- `challenge` / `login_required` / `policy_blocked` → pause the run with that `pause_reason`. A record before its
  commit is released `filling → pending`; a record in the commit window goes through reconcile.
- `off_origin` → park the record.
- `detached` / `tab_closed` → treat in-flight commands as `lost`, then pause the run `executor_disconnected`.

**`ParkingReconciler`** is the default for real runs until P-003 is decided. Any record that needs a destination
check is parked with the reason "could not verify the save automatically; check the destination". It is never
returned to `pending`, because with no real check, "not found" proves nothing.

**Fresh confirmation** (PL-010 follow-up 9). Immediately before dispatching a commit, the runner checks
`assert_after`. If it already holds, the record parks with "the confirmation was already on the page before saving",
because the save could not be verified.

**PL-013 follow-up.** Hand the run back on the `internal_error` pause path.

### 5. Executor hardening carried from the PL-010 review
Each needs a unit test:
- **Ladder order.** Sort by rung rank, not array order, and report rungs as 1 to 5.
- **`within` containers** must match exactly one visible container.
- **Hit test.** Accept only the target or its descendants, not an ancestor.
- **Nested frames.** Refuse a click in a non-top frame (`result refused`) until the frame offset is added.
- **`fill`.**
  - Type text with `Input.insertText`, so `\n` and `\t` are characters, not Enter or Tab.
  - `clear_first: false` must not select the existing text.
  - Read the value back afterwards and fail on a mismatch.
- **`navigate`.** Fail on `errorText`, and wait for the frame's load event, with a timeout.
- **Combobox.** The option search is scoped to the controlled listbox, with `role=option` only.
- **Fuzzy matching.** The fuzzy rung ignores an input's current value.
- **Abort.** Abort detection reads `control.aborted` only, and the condition poll checks it.

### 7. Fixture site and end-to-end tests
**`fixtures/sites/lead-crm/`** is a small static lead CRM served on 127.0.0.1 by the test harness, with synthetic
data only. It has search, a results list, a new-lead form, and a "Lead created" toast after the server stores the
record. A duplicate email shows an inline error. Its test API reports how many leads exist per email.

**Switches:**
- slow save;
- a confirmation toast left over from a previous save (stale);
- a login page;
- a challenge marker page;
- a field moved into an iframe;
- a disconnect mid-save.

**`tests/e2e/`:**
- Playwright with its **bundled Chromium**, because Chrome and Edge no longer allow loading an unpacked extension
  from the command line.
- A persistent context that loads `apps/extension/dist`.
- The real API, hub, runner worker, and Postgres.
- Document the command that runs it. It stays out of pull-request CI, like the existing browser smoke test, and runs
  on demand or nightly.

## Acceptance criteria
- [ ] Step 0 plan committed and approved by T1 before any implementation commit.
- [ ] Hub security: the runner channel without the secret, and the extension channel with a wrong origin or token,
      are refused before any message is relayed.
- [ ] End to end, real extension: a 5-record batch on the fixture site (one already exists, one missing email, three
      new) ends 3 `verified`, 1 `skipped`, 1 `parked`. The fixture's test API shows each email exactly once.
- [ ] Extension disconnect mid-save: the record parks. There is no duplicate and the run pauses
      `executor_disconnected`. Reconnecting and resuming continues the run.
- [ ] Runner crash mid-save, then takeover: the record parks (`ParkingReconciler`), with no duplicate.
- [ ] Commands with a stale epoch, a repeated id, or a passed expiry are refused (unit). After a reconnect, an
      in-flight command is reported `lost` and is not re-run.
- [ ] Challenge marker page → run paused `challenge`, no record `failed`. Login page → paused `login_required`.
- [ ] Policy-blocked attach (fake debugger in unit tests) → paused `policy_blocked` with the readable message.
- [ ] Off-origin page → the record parks. A destructive control without the flag → refused, and the record parks.
- [ ] A stale "Lead created" toast left on the page → the record is not `verified`.
- [ ] The run survives an idle wait of over 30 seconds (keepalive): an e2e test, or a unit test with the timer seam.
- [ ] Every item in Requirement 5 has a test.
- [ ] The `internal_error` pause hands the run back: a resume queues it at once.
- [ ] Unused permissions are removed, and the final permission list is in the report.
- [ ] Gates: `python -m pytest -q`, `ruff check .`, `ruff format --check .`, `npm --prefix apps/extension run check`,
      `python -m db.migrate` twice, and the e2e command with its real output.
- [ ] Report written to `internal/agent/reports/PL-014.md`.
