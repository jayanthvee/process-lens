# PL-109: Decide and show — no question an employee can't answer

Owner: T2 (DeepSeek) · Branch `pl-109` (from `pl-107` once it is pushed) · Reviewer: T1

## Why

On 2026-10-26 the owner taught an Odoo lead from the pipeline (board) view and ran a 20-row file.
The owner could not tell what several screens were asking. If the owner can't, an employee can't.
Seen on the panel:

- "Which column identifies each row?" meant nothing, and defaulted to "Contact", a name two rows
  can share.
- Two task fields named "Contact" and "Contact 2". The quick-add card's boxes carry similar labels,
  and nothing says which box is which.
- "Check this" next to E-mail → Email, with nothing to check.
- "Expected revenue — Not in my file — Not found", with no word on what happens to that box.
- Both Contacts guessed as Full Name.

## The rule

ProcessLens decides, and shows its decision in one plain line the person can change. It asks only
when it really cannot tell, and then asks about the person's own data in their own words
("Which column has the email addresses?"), never about engine concepts (keys, commit steps,
matching confidence).

## Change

### 1. Show what was typed while teaching, everywhere a field is named

Every place a task field appears (Check it, the panel's step list, the run's row values), show the
value the person typed for it while teaching: `Contact — you typed “ben baller”`. The taught value
is already in the recording (`recordedValues(events)`); carry it in the compiled task's input
schema (as an example, never as a default value).

### 2. Field names a person recognises, and never two the same

- Name a field from, in order: its visible label, its column header, its `aria-label`, then a
  placeholder that is not an example ("e.g. …", "such as …" never become names; PL-107 item 13).
- Two fields that would get the same name are told apart by what was typed in them
  (`Contact (ben baller)`, `Contact (ben baller's opportunity)`), never by "2".

### 3. Match columns by their values, not only their headers

On Check it, a file column whose values look like the taught value (email-shaped, phone-shaped, a
person's name, money) is the suggestion even when the header differs. Two task fields never get
the same file column suggested unless the taught values were the same.

### 4. Matched or ask: no "Check this"

- A confident match shows **Matched**, with the first row's value beside it so the person can see
  it is right ("E-mail → riley.ivanova@…").
- An unsure match does not say "Check this". It asks one question in words about the data: "Which
  column has the email addresses?", with the file's columns as the choices.
- "Not in my file" says what happens: "Left empty for every row."

### 5. The key column is decided, not asked

Replace "Which column identifies each row?" with a line: `We'll use **Email** so nothing gets
added twice. Change`. Choose: an email-shaped value; else an id/number-like value; else ask
"Which value is different for every row?". (Supersedes PL-107 item 14's wording.)

### 6. The save click is decided, not asked

PL-107 item 6 adds "Which click saves your work?". Show it the same way: `The **Save** click saves
your work. Change`, where the default is the last click on the task's own site whose result shows
on the page. "Nothing gets saved" stays a choice under Change.

### 7. Every question passes the stranger test

List every question, label and status word in the panel (Teach, Tasks, Runs, Check it, Try one row,
run rows) in the report, with the words before and after. A word an employee would not use
(column, key, commit, matched, parked, queued, record) does not appear on screen.
