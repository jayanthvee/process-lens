# Widget corpus fixture

A stdlib-only synthetic site with one page per shape PL-018's recorder has to
survive. It follows `fixtures/sites/messy-crm`'s anatomy exactly: one JSON
handshake line on stdout, an in-memory store behind `/__test__/`, switches
injected as `window.__SWITCHES__`, a standalone `selftest.py`, and nothing but
`@example.test` addresses.

```powershell
python fixtures/sites/widget-corpus/selftest.py     # SELFTEST PASSED (N checks)
python fixtures/sites/widget-corpus/server.py --port 0
# {"url": "http://127.0.0.1:<port>", "port": <port>, "crm_url": ..., "crm_port": ...}
```

## Pages

| page | what it is | the value the fixture proves |
|---|---|---|
| `gmail-compose.html` | the golden: a combobox whose suggestion becomes a chip, a `contenteditable` body the **page** writes (no `input` event), Send, a 4-second `Sent — Undo` toast | `messages[].body`, `messages[].to` |
| `plain-editor.html` | a `contenteditable` that fires `input` normally | `values["plain-editor"].note` |
| `framework-editor.html` | a `contenteditable` mutated by script from `keydown` and on a timer, with no `input` event at all | `values["framework-editor"].draft` |
| `react-autocomplete.html` | an autocomplete accepted **only** by clicking the option; Enter and Tab do nothing | `values["react-autocomplete"].reviewer` |
| `shadow-form.html` | a labelled input, a native `<select>` and Save inside an **open** shadow root | `values["shadow-form"].name` / `.team` |
| `iframe-form.html` | a **same-origin** frame (`/iframe-child.html`), whose Save goes through the parent page's store helper | `values["iframe-form"].note` |
| `chip-removal.html` | chips with **no** remove control of their own (Delete key or page menu), plus a Ctrl+Enter compose that fires no `submit` | nothing: both recordings are refused at compile time (R2, R1) |
| `perf.html` | 1000 labelled inputs generated by script for the snapshot budget | nothing |

`/` and `/index.html` are the hub: every page is linked from it and every page
links back. The hub is rendered by `server.py` because it is the only page that
is not a widget.

## API

| route | what it does |
|---|---|
| `GET /directory.json?q=` | the synthetic directory, filtered on name or address (an empty query matches nothing) |
| `POST /send` | `{to: [addresses], body, source}` — refuses a non-`@example.test` address with 400 |
| `POST /save` | `{source, fields}` — one widget's persisted value |
| `GET /__test__/state` | `{messages, sends, saves, values, switches, directory_size, widget_count…}` plus request counters |
| `POST /__test__/reset` | empties the store and clears the switches |
| `POST /__test__/switches` | merges a patch into the switches |

Switches (all off by default):

| switch | effect |
|---|---|
| `slow_suggest_ms` | delays `/directory.json`, so a fast typist can race the suggestions |
| `slow_send_ms` | delays `/send` |
| `suggest_empty` | typing surfaces no suggestions at all |
| `no_toast` | the Send still stores its message and the toast **never** appears, so the commit has no observation |

## The deliberate traps

* **The suggestion popup and the chips container are structurally identical** —
  both are labelled `role="listbox"` full of `role="option"` children. The
  popup is named by the To field's `aria-controls`; the chips container is the
  one holding already-accepted tokens.
* **The accept is one synchronous tick** — `compose-app.js` adds the chip and
  clears the field with no `await` between the two lines, so a checkpoint that
  fires at `click` time sees only the chip.
* **The body editor never fires `input`** — its text is written by a direct
  `textContent` assignment inside the keydown handler; `compose-app.js` contains
  no `dispatchEvent` call at all. The snapshot is the only way to see it.
* **`chip-removal.html` has no ✕** — removal is a Delete-key handler or a page
  menu, neither of which a recording can replay, so the compile must refuse it
  (R2); its Ctrl+Enter compose fires no `submit`, so the compile must refuse
  that too (R1).

## The selftest

`selftest.py` starts the server in-process, checks the standalone handshake,
every route, the DOM and script promises above, the store and switch behaviour,
that every address served anywhere is `@example.test`, and — with the repo root
on `sys.path` — that `packages.compiler.compile_recording` refuses the two
hand-written recordings the corpus exists for (R1's key send, R2's chip
removal). A missing or broken compiler package is reported as one FAIL check
with its reason, never a crash.
